# C1 수정 지시 4회차

근거: C1 4회차 리뷰(OpenAI 높음 1·중간 2, Claude 낮음 2, UX 중간 1·낮음 2). UX 문구 경로("설정 > 운영 설정 > 예산", [요청 카드 다시 허용])와 최대 비용 안내 문구는 Claude가 strings.xml에서 이미 고쳤으니 되돌리지 않는다. 규칙은 [C1-fix-r3.md](C1-fix-r3.md)와 같다.

## 코드
1. **월말 차단 표식(높음)**
   - 차단 표식은 승인일이 아니라 초과를 일으킨 호출이 기록된 원장의 월에 남긴다.
   - 견적과 각 호출 예약 직전에는 현재 월 표식을 확인한다. 실행 중 월이 바뀌었으면 승인월 표식도 확인한다.
   - 테스트: 11-30 승인 → 12-01 초과 정산 → 12월 다음 요청이 막히는지 확인한다.
2. **웹 검색 지원 모델만 선택**
   - `ModelPrice`(카탈로그)에 `webSearch: Boolean` 항목을 둔다. 기본 카탈로그에는 Anthropic 모델 중 지원 모델만 true로 둔다.
   - 견적과 실행 모두 "분류 공급자 중 webSearch=true이면서 입력 단가가 가장 낮은 모델"을 쓴다. 공급자가 `WebSearchProvider`를 구현하지 않으면 지원하지 않는 것으로 본다.
   - 지원 모델이 없으면 새 사유 `RESEARCH_UNSUPPORTED`로 표시하고, 추가 조사 스위치를 끈 상태로 비활성화한다.
   - 새 문자열 `request_card_research_unsupported` = "지금 쓰는 AI 공급자는 웹 검색을 지원하지 않아 추가 조사를 할 수 없습니다. 분류 단계를 Claude로 바꾸면 쓸 수 있습니다."
   - 테스트를 넣는다.
3. **추가 조사만 초과한 경우**
   - 추가 조사를 켠 견적만 예산을 넘고 일반 견적은 들어가면, 스위치를 끌 수 있게 둔다. 화면의 `research` 상태와 스위치 표시를 일치시킨다.
   - 스위치를 끄면 일반 견적을 다시 받는다.
   - 하루 최대·월 예산·차단 표식처럼 일반 요청도 막히는 경우에만 스위치를 비활성화한다. 이때 `research`를 false로 맞춘다.

## UX
4. **차단 안내 위치:** 월 차단 상태이면 SC-11 예산 구역 맨 위에 경고 Notice를 둔다. 문구는 `request_card_settlement_block`이다. [요청 카드 다시 허용] 버튼도 그 Notice 바로 아래로 옮긴다.
5. **추가 조사 안내 순서:** `request_card_search_limit`(무엇을 하는지)를 먼저 보이고, 그 아래에 `request_card_research_max`(최대 비용)를 보인다.
6. **캡처:** 같은 테스트 상태로 다시 찍는다. 대상은 월 차단 견적과 그 상태의 SC-11 예산 구역이다. 하루 최대 금액이 설정값과 일치해야 한다.
