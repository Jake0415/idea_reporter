# P14 수정 지시 — 2회차 (OpenAI 높음 3·중간 4·낮음 1, Claude 중간 3·낮음 5)

규칙은 같다. 커밋·docs 수정·실제 실행·push 금지.

## 원칙 (Claude)
**돈이 드는 일과 메일은 "원격에 기록이 남은 뒤"에 한다.** 그 앞에서 기록이 끊기면 다시 하지 않고 "확인 필요"로 남긴다.

## 높음
1. **inbox 결과 충돌.** (OpenAI) 잘못된 파일의 거부 결과는 본문·파일명의 UUID를 쓰지 않는다. `invalid-<파일 내용+이름 sha256 앞 16자>` ID로 기록한다. 정상 requestId의 결과 슬롯을 절대 차지하지 않게 한다. 테스트: 같은 UUID를 담은 잘못된 파일이 먼저 처리돼도 정상 요청이 적용된다.
2. **공개 정제 보강.** (OpenAI)
   - JSON은 **키와 값 모두** 정제한다. 키에 주소·토큰이 있으면 그 항목을 뺀다.
   - 문자열은 **URL 디코딩(`%40` 등)한 형태로도 검사**한다. HTML 엔티티(`&#64;`)도 같다.
   - 공개 사본의 `classification.summary`는 300자로 자른다.
   - 테스트: 인코딩된 주소, 키에 든 주소, 긴 summary.
3. **메일은 2단계로 기록한다.**
   - 메일 단계 순서:
     1. `sending` 기록을 로컬에 쓴다.
     2. **메일 기록만 data 브랜치에 push한다.**
     3. 그 push가 성공했을 때만 SMTP로 보낸다.
     4. 결과를 기록하고 다시 push한다.
   - 첫 push가 실패하면 보내지 않는다(다음 실행 재시도).
   - 결과 push가 실패해도 원격에는 `sending`이 남는다. 다음 실행은 그것을 `unknown`으로 읽으므로 중복 발송하지 않는다(P11 규칙).
   - 결과 push 실패 시 올리는 아티팩트는 **정제한 메일 기록**만 담는다(`issue` 문자열 제거).
4. **분석도 같은 원칙을 따른다.** (둘 다 지적)
   - `analyze.yml` 순서:
     1. pull + inbox
     2. 추정
     3. `run`이면 **"분석 시작" 표시**(`out/inbox-results/<requestId>.json`의 `status=running`, `dispatchRunId`)를 push한다.
     4. 그 push가 성공했을 때만 유료 분석을 실행한다.
     5. 보고서·원장·결과를 push한다.
     6. 메일은 3번 방식으로 보낸다.
   - 같은 requestId가 `running`인데 결과가 없으면 다시 실행하지 않는다. "확인 필요 — 새 requestId로 다시 요청" 결과를 남긴다.
   - `Apply inbox` 단계에 `continue-on-error`를 단다.

## 중간
5. **동기화 실패 시 수집하지 않는다.** (둘 다 지적) checkout 또는 `data-pull`이 실패하면 수집·메일 단계를 **건너뛴다.** 상태가 없으면 비용 원장과 Batch 체크포인트가 없어 상한이 무력화되고 이중 제출이 생기기 때문이다. 동기화 실패 issue만 남긴다. 이미 열린 같은 제목의 issue가 있으면 새로 만들지 말고 댓글을 단다.
6. **공개 사본을 다음 실행 상태로 쓸 때 정보가 사라지지 않게 한다.** (Claude)
   - 구조 필드는 공개 허용 목록에 넣는다: `discussionUrl`, `alsoSeenIn`, `extra`(값은 정제), `commentCount`, `profileHint`.
   - `snippet`은 원문 앞 300자를 정제해 유지한다. 분류 요약으로 바꾸지 않는다.
   - 제거는 댓글 본문·작성자·원문 전체만 한다.
   - 정제 → 다시 읽기 왕복 테스트로 아래 기능이 유지되는지 확인한다: 과거 기록 검색, 추적 매칭, 트렌드, `--mail --resend`.
7. **rebase 충돌 해결기가 실패하면 처음부터 다시 만든다.** 파일·디렉터리 충돌 등으로 해결기가 실패하면 rebase를 중단(`--abort`)하고, 원격 최신(`origin/data`)으로 리셋한 뒤 이번 실행 출력으로 `--data-push`를 다시 만들어 commit·push한다. 메일 기록은 병합 규칙을 쓴다. 이 과정이 3회 재시도 안에 들어가야 한다.
8. **Batch 공개 메타데이터 보완.**
   - 생성 Batch의 `supplementRefs`는 공개 메타데이터에 포함한다. 웹 검색 결과의 공개 URL·제목이며, 정제를 적용한다.
   - 격리된 미정산 예약(`quarantine/*.unsettled.json`과 정산 재시도 정보)도 공개 메타데이터로 동기화한다. 새 러너에서 정산 재시도를 할 수 있어야 한다.

## 낮음
9. 경로 탈출 테스트는 **유효한 파일명**(`<ISO>-<UUID>.json`)에 악의적 본문을 넣어, 본문 식별자 검증까지 도달하게 한다.
10. `collector.data` KDoc에 앱 계약을 적는다.
    - inbox 파일명 형식(`<ISO시각>-<UUID>.json`)
    - `internal_error`나 `확인 필요`는 **새 requestId로 다시 요청**한다.
    - `analyze.yml` 입력은 `requestId` 하나다.
