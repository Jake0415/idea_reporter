# P13 수정 지시 — 1회차 (OpenAI 높음 3·중간 4, Claude 높음 3·중간 5)

규칙은 P13과 같다. 커밋·docs 수정·실제 LLM/Batch/검색 호출 금지.

**핵심 원칙: 한 번 제출해 과금된 Batch 결과는 반드시 회수해서 쓰거나, 적어도 비용을 정확히 정산한다. 결과가 불확실하면 다시 제출하지 않는다.**

## 높음
1. **재개 매칭을 요청 지문에서 항목 단위로 바꾼다.** (둘 다 지적)
   - 지금은 요청 전체 해시로 비교한다. 재수집하면 점수·댓글이 바뀌어 매칭에 실패하고, 결과를 버린 채 전부 동기로 다시 돈다.
   - 바꿀 방식: 체크포인트에 `custom_id → [itemKey…]`와 **제출한 요청 본문(또는 입력 항목 스냅샷)**을 저장한다.
   - 재개 시 처리:
     - 결과를 itemKey로 현재 항목에 매핑한다.
     - 현재 후보에 없는 항목은 버리되, 비용은 정산한다.
     - 결과가 없는 현재 항목만 동기로 분류한다.
   - 같은 날 재실행은 체크포인트에 저장한 입력 스냅샷으로 분류 결과를 재사용한다.
2. **분류 Batch가 아직 끝나지 않은 상태로 실행이 끝나면 select 이후 단계를 하지 않는다.** (Claude)
   - "아직 끝나지 않은 상태"란 취소 대기 초과, 결과 조회 실패 등으로 대기 상태로 남는 경우다.
   - 하지 않는 단계: 작성·보충 검색·추적.
   - 실행 결과는 "분류 Batch 대기 — 다음 실행에서 이어서"로 남기고, 메일은 보내지 않는다.
   - 다음 실행이 그 결과를 이어서 쓴다.
3. **제출이 불확실하거나 체크포인트 저장에 실패해도 다시 제출하지 않는다.** (둘 다 지적)
   - 제출 **전에** 의도 기록을 원자적으로 저장한다. 기록 내용: 제출 시각, 결정적 `custom_id` 목록, 요청 수, 예약 금액.
   - 저장에 실패하면 제출하지 않고 동기로 진행한다.
   - 제출 응답을 잃은 경우(시간 초과·연결 끊김·5xx 등 결과가 불확실한 오류):
     - 동기로 대체하지 않고 "Batch 제출 확인 필요" 상태로 둔다.
     - 이번 실행에서 그 묶음은 **분류하지 않는다**(원칙 2 적용).
   - 확정 거절(4xx 검증 오류)만 동기로 대체한다.
   - 다음 실행에서 의도 기록만 있고 batch id가 없으면:
     1. `batches.list`로 의도 시각 이후에 생성되고 요청 수가 같은 batch를 찾는다.
     2. 결과의 `custom_id`로 일치를 확인한 뒤 채택한다.
     3. 못 찾으면 의도 기록을 만료 처리한다(24시간 경과 후). 그 뒤 동기 실행을 허용한다.
4. **결과를 안전하게 저장한 뒤에 체크포인트를 지운다.** (OpenAI)
   - 결과를 회수하면 먼저 `out/batch/<batchId>.results.jsonl`에 원자적으로 저장하고, 비용을 정산한다.
   - 결과 파일은 호출자가 검증·실행 기록 저장을 마친 뒤에 지운다. 보관 7일 정리로 지워도 된다.
   - 재개 시 결과 파일이 있으면 API를 다시 부르지 않는다.
5. **결과 누락·중복 ID** (OpenAI)
   - `ENDED` 결과에서 예상 ID가 빠졌으면 1회 다시 조회한다.
   - 그래도 없으면 "결과 누락"으로 기록하고, 해당 요청 비용은 batch 가격 추정치로 보수적으로 정산한다. 그 묶음은 동기로 분류한다.
   - 중복 ID는 첫 성공 행을 쓰고 issue로 남긴다.

## 중간
6. **체크포인트를 날짜와 무관하게 처리한다.** (둘 다 지적) 모든 실행 시작 때 `out/batch/`의 미결 체크포인트를 전부 처리한다(날짜·설정·공급자 변경과 무관). 지난 날짜 것은 결과를 회수하고 비용을 정산한 뒤 결과 파일만 남긴다(보관). 예약도 반드시 정산한다.
7. **예약 누수를 막는다.** (둘 다 지적) 모든 예외 경로에서 예약을 정산한다. `LlmService`·`LlmAuth`가 아닌 예외(IO, `system().get()` 등)와 검색 시간 초과도 포함한다.
   - 결과가 불확실하면 예약액 그대로 정산한다(보수적).
   - 미확인 가격이면 `priceUnverified`를 전파한다.
   - `try/finally`로 예외 경로마다 정산되는지 테스트한다.
8. **동기 대체 묶음은 기존 동기 경로 전체를 탄다.** (Claude) 동기 경로란 분할 재시도, 미해결 항목 재시도, 대체 공급자, invalid 재시도다. Batch 전용으로 줄인 경로를 쓰지 않는다.
9. **보충 검색**
   - 재개 경로에서도 검증된 결과 블록 URL·제목을 저장·사용한다. 모델이 돌려준 URL·제목을 그대로 쓰지 않는다. 정규화는 비교에만 쓰고, 최종 링크는 결과 블록 원문 URL로 둔다.
   - 검색 예약에 검색 결과 입력 토큰을 포함한다(`maxUses` × 보수적 결과 토큰).
   - 카드 작성 예산을 먼저 확보한다. 작성 예약 가능액을 남기고도 여유가 있을 때만 검색한다.
10. **시간 한도.** 실행 전체 마감(`deadlineMinutes`, 기본 140)을 두고, 남은 시간으로 Batch 대기·결과 다운로드·동기 대체 시간을 제한한다. generate Batch를 켜도 마감을 넘지 않게 한다.
11. **Backfill:** 체크포인트가 있어도 월 상한 사전 검사를 건너뛰지 않는다. 다른 날짜로 진행할 때마다 검사한다. (Claude)
12. **로컬 설정:** `config/pipeline.local.json`은 일부 키만 있어도 기본값과 합쳐 읽는다(깊은 병합). 경로는 작업 위치 기준 상수로 두고, 테스트한다. (Claude)
