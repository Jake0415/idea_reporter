# P8 S2 수정 지시 — 2회차 (Claude 중간 1, OpenAI 높음 1·중간 3·낮음 1)

규칙 동일(커밋·docs·프롬프트 수정·키 출력 금지, 실제 수집·LLM 실행 금지).

## 높음
1. **GitHub 부분 결과가 성공으로 확정** (OpenAI) — 검색 응답의 `incomplete_results`를 읽어, `true`면 그 요청은 실패로 보고 기존 재시도(대기 포함)를 거친다. 재시도 후에도 부분이면 그 출처는 그날 **실패**(캐시하지 않음, 미완료). 일일 수집(GitHubAdapter 일일 경로)에서는 지금처럼 결과를 쓰되 실행 기록에 경고 한 줄. 수집 캐시 형식에 출처별 `complete` 표시를 추가하고, **이 표시가 없는 기존 캐시는 다시 수집**한다(지금 `out/backfill/collected/`의 캐시는 표시가 없으므로 자동 재수집됨). 테스트.

## 중간
2. **채운 항목이 실제 실행에서 다시 "새 항목"** (Claude) — 출처 맞춤 모드의 비교용 새 항목은 **4주 전체에서 itemKey별 가장 이른 관측만** 인정한다(이후 주의 같은 itemKey는 비교에서 제외). 표의 전체 건수는 그대로. 테스트: 앞 주 채운 날의 GitHub 항목이 이번 주 실제 실행에서 다시 새 분류 → 이번 주 비교 건수에 안 셈.
3. **새 항목 필터와 주간 중복 제거 순서** (OpenAI) — 비교용 집합은 **HN·GH 조건(`source` 또는 `alsoSeenIn`)을 먼저 적용한 뒤** itemKey 중복 제거(2번의 "가장 이른 관측")를 한다. 테스트(RSS 행 2개 중 앞 행에만 `alsoSeenIn=hn`).
4. **◆ 출처 수 계산 회귀** (OpenAI) — ◆의 출처 조건은 **표에 보이는 출처 수와 같은 집합**(이번 주 중복 제거 후 관측, 같은 항목의 `alsoSeenIn` 포함 여부도 표와 동일 규칙)으로 계산한다. backfill 없는 기간에도 표 출처 수 = ◆ 판정 출처 수. 테스트.
5. **`--force --dry-run` 뒤 체크포인트 섞임** (OpenAI) — 수집 캐시를 새로 쓰면 그날의 `interrupted/` 체크포인트를 삭제한다(또는 체크포인트에 수집 캐시 해시를 저장하고 다르면 버림). 테스트.
