## 코드 — 높음
1. **실행 중 메일 수신 끄기**
   - 메일을 보내는 세 시점에서 현재 수신 설정을 다시 읽는다: 발송 대기에 넣기 직전, 이전 실패 재시도 직전, 실제 발송 직전. 실행을 시작할 때 고정한 값은 쓰지 않는다.
   - 그 시점에 수신이 꺼져 있으면 보내지 않고, 대기열에도 넣지 않는다. 일일 실행과 분석 모두 같다.
   - core는 `mailEnabled: () -> Boolean` 같은 공급자를 받는다.
   - 테스트를 넣는다.

## 코드 — 중간
2. **SC-09 저장은 실제로 고친 칸만**
   - 카드 구성 숫자와 평가 기준 입력란 모두, 편집을 시작할 때의 값을 기준으로 실제로 바꾼 칸만 최신 설정(대기열 포함)에 합친다.
   - 평가 기준 입력란의 기준값과 초기값은 대기열의 `criteria` 변경을 `mergeCriteria`로 합친 값으로 만든다.
   - 저장이 접수되면 입력값과 기준값을 함께 갱신한다.
   - SC-09의 연속 저장과 대기열 반영이 겹치는 경우를 테스트한다.
3. **메일 테스트와 시험 실행이 끝난 뒤 반영**
   - 두 작업은 공통 실행 상태와 core 파일 락을 잡지만 `CollectorRunService.running`은 false로 둔다. 그래서 그 사이에 저장한 변경과 예약 갱신이 반영되지 않고 남는다.
   - 공통 실행 상태를 해제하는 함수 하나에서 `flushLocalChanges()`와 `schedule.finishScheduleUpdate()`를 호출한다. 일일·분석·메일 테스트·시험 실행이 모두 이 함수로 해제한다.
   - 화면의 "실행이 끝나면 반영" 안내는 공통 실행 상태를 기준으로 보여 준다.
4. **첫 실행 5단계 복원**
   - 첫 실행 대상 날짜를 저장한다.
   - 마법사에 들어올 때 그 날짜가 게시됐는지 확인한다. 게시됐으면 5단계 완료를 보여 준다.
   - 게시 전이면 `hasBatchToResume`을 함께 보고 묶음 처리 대기를 보여 준다. 정산은 됐지만 아직 게시되지 않은 경우도 여기에 포함한다.
   - 이 확인은 1단계로 가기 전에 한다. `first-run.finished`는 [완료]를 누를 때만 기록한다.
5. **분석 견적 실패를 고정하지 않음**
   - 실패 결과는 캐시하지 않는다.
   - `RunLockedException`은 "실행 중이라 잠시 뒤에 계산합니다"라는 일시 상태로 보여 준다. 공통 실행 상태가 풀리면 같은 선택으로 자동으로 다시 견적한다.
6. **분석 서비스 시작 거부:** `startAnalysis()`의 `check`를 없앤다. 시작 결과(거부, 실행 중)를 화면의 분석 오류 상태로 돌려주고, 앱이 죽지 않게 한다.

## 코드 — 낮음
7. **메일을 끈 상태의 실패 건수:** noMail일 때도 만료 처리는 하거나, 건수를 셀 때 3일 기간을 적용한다. "다른 날짜"는 실행 대상일이 아니라 현재 날짜 기준으로 센다.
8. **메일 테스트의 공통 실행 상태:** CAS는 `appScope.launch` 안에서 잡고 try/finally로 해제한다. 화면 scope가 취소돼도 상태가 남지 않게 한다. 시험 실행도 같은 방식인지 확인한다.
9. **SC-07 연결 확인 횟수:** RSS는 피드 수만큼 센다. 추가 요청이 있을 수 있는 어댑터는 "최대 n번"처럼 범위로 적는다.

## UX
10. **마법사의 [다음]이 꺼진 이유 문구**
    - 하단 바 안, 버튼 바로 위로 옮긴다. `padding(horizontal=16.dp, vertical=8.dp)`를 주고, bodySmall에 `onSurfaceVariant` 색을 쓴다.
    - 스크롤 영역에는 그만큼 아래 여백을 둔다.
    - 200%에서 입력란을 가리지 않는지 확인한다.
11. **SC-01 실행 중 띠(다크):** 차분한 옅은 파랑 컨테이너(예: #0B2A45 계열)를 쓴다. 진행 막대는 accent, 트랙은 보이는 회색, [취소]는 밝은 파랑으로 둔다. 막대와 트랙의 대비는 3:1 이상, 글자는 4.5:1 이상으로 맞춘다.
12. **SC-07 상세**
    - 화면 제목은 출처 이름(예: "해커 뉴스")으로 쓴다.
    - 분류 기준 칩은 마법사 3단계와 같은 ✓ 선택 칩으로 바꾼다.
    - "기본값으로 되돌리기"는 왼쪽 16dp에 맞춘다.
13. **SC-01 메일 실패**
    - "17:19 · 메일 실패 ›"처럼 가운뎃점 앞에 공백을 넣는다.
    - 줄 높이는 다른 줄과 같게 두고, 링크만 `minimumInteractiveComponentSize`로 둔다.
14. **SC-01 경고 시트:** "다른 날짜 메일 n건 실패 · 기록 보기 ›"로 바꾸고 SC-12로 이동하게 한다.
15. **SC-09 도움말:** 입력란마다 한 줄 도움말을 붙인다.
    - 같은 태그의 후보 최대 개수: "비슷한 주제 후보가 한쪽으로 몰리지 않게 합니다"
    - 같은 분류 카드 최대 개수: "하루 카드 중 같은 분류는 이 개수까지만"
    - 하루 카드 수: "매일 받는 카드 수(3~7)"
    - 피드백 반영 개수: "최근 ★·평가 중 다음 카드에 참고할 개수"
16. **텍스트 버튼 왼쪽 정렬:** "메일 받지 않기", "기본값으로 건너뛰기", "나중에 실행"이 본문 왼쪽과 맞도록 `contentPadding` 시작값을 0으로 한다.
17. **마법사 1단계:** [이전]을 숨기고 그 자리는 비워 둔다.
18. **SC-16**
    - 편집 영역에 테두리(outlined)를 둔다.
    - [저장]과 [시험 실행]을 화면 아래에 고정한다. 키보드 위로 올라와야 한다.
19. **권한 상태 표시:** 꺼진 권한은 ⚠를 warning 색으로, 켜진 권한은 ✓를 success 색으로 보여 준다. SC-11과 마법사 4단계 모두 고친다.
20. **분석 화면 빈 상태:** 고를 주제가 없으면 "아직 고를 주제가 없습니다. 일요일 트렌드 리포트 후 다시 확인하세요"를 보여 준다.
21. **strings 정리:** 쓰이지 않는 `token_help`(Actions 쓰기 권한)와 `actions_error`를 지운다. 다른 Actions·inbox·저장소 연결 문구도 남아 있으면 같이 정리한다.
22. **imePadding과 하단 탭 여백:** `Scaffold` 안쪽에서 imePadding과 하단 탭 여백이 겹쳐 빈 공간이 두 배가 되지 않는지 확인하고 고친다(`consumeWindowInsets` 등).
