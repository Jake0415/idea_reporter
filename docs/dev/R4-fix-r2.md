# R4 수정 지시 2회차

근거: R4 2회차 리뷰(OpenAI 코드, Claude 코드). UX 2회차 지적 3건은 Claude가 이미 직접 고쳤다(BackupSettings의 [가져오기] 글자색, `backup_alarm_pending`, `backup_too_large`). 규칙은 [R4-fix-r1.md](R4-fix-r1.md)와 같다.

## 높음
1. **RSS URL 자격 증명 제외**
   - 내보내기에서 `sources.local.json`의 피드 URL을 기존 `rssPrivateValues()` 규칙으로 판별한다. 쿼리 값이 6자 이상이거나 userinfo가 있는 경우다.
   - 자격 증명이 든 피드 항목은 내보내지 않는다.
   - 쿼리 이름이 privateField(token, key, secret 등)에 걸리는 경우도 제외한다.
   - 테스트를 넣는다.
2. **복구 실패 시 쓰기 차단**
   - 롤백이 실패해 저널이 남으면 "복구 대기" 상태를 디스크에 기록한다.
   - 복구 대기 중에는 실행·sync·가져오기·설정 저장을 모두 막는다. 실행은 실패로 기록하지 않고 건너뛴다.
   - 화면에는 "이전 가져오기를 되돌리지 못했습니다 · 다시 시도"를 보여 주고, 알림도 띄운다.
   - 복구에 성공하면 해제한다.
3. **앱 시작 복구 예외**
   - `attachBaseContext`(또는 시작) 복구를 try/catch로 감싼다. 예외가 나면 앱이 죽지 않고 2번의 복구 대기 상태로 들어간다.
   - 재시도는 IO 스레드에서 한다.
   - 앱 업데이트로 허용 경로가 바뀐 경우를 막기 위해, 저널에 기록된 경로는 저널 자체의 목록으로 복원한다. 경로는 canonical 검사로 앱 폴더 안인지 확인한다.
4. **예산 설정 보존**
   - 백업에 `budget.json`이 없으면 기존 예산 파일을 유지한다.
   - 백업의 예산이 현재보다 상한을 완화하면(값이 커지거나 null), 미리보기에 "예산 상한이 늘어납니다: 월 $A → $B"를 보여 준다. 사용자가 [바꾸기]를 눌러야만 반영한다.
   - 테스트를 넣는다.

## 중간
5. **원장 병합: 예약액과 정산액**
   - 현재 기록이 정산돼 있으면(`actualUsd != null`) 그대로 둔다.
   - 들어온 기록이 미정산(예약액만 있음)이면 현재의 정산값보다 크게 만들지 않는다.
   - 실행 결과에서 계산한 `prior-runs` 합계와 백업의 개별 원장이 같은 실행을 나타내면 한 번만 센다. 실행 id나 날짜로 겹침을 판정한다.
   - 테스트를 넣는다: 예약 $2를 백업 → $0.5로 정산 → 가져오기 → $0.5 유지. 같은 실행이 결과와 원장 양쪽에 있어도 두 번 세지 않는다.
6. **`requireComplete` 범위:** 가져오기가 쓴 대상 경로 집합 안에서만 PARTIAL을 판정한다. 기존에 깨져 있던 다른 파일 때문에 가져오기가 실패하지 않게 한다.
7. **시작 복구 후 Room**
   - 시작 복구가 실제로 파일을 되돌렸다면, 데이터 화면을 열기 전에 `sync.refresh()`를 마친다. 그동안 화면에는 로딩을 보여 준다.

## 낮음
8. **오늘 기록 보존:** 오늘 날짜와 Batch 대기 날짜의 `runs/`·`runs/failed/` 파일도 덮어쓰거나 지우지 않는다.
9. **오늘 daily 파일:** 이 폰에 오늘 파일이 없으면 백업의 오늘 파일을 쓴다. 있으면 현재 파일을 유지한다.
10. **임시 파일 정리:** 시작 복구 때 백업 트랜잭션이 만든 `.collector-*.tmp` 임시 파일도 정리한다. 식별할 수 있는 접두어를 쓴다.
