# P7 S1 수정 지시 — 2회차 (실제 출력 기반 재설계: 테마 = 분류 태그)

1회차 반영 후 실제 출력(`out/trend/2026-11-20.txt`): 연쇄 묶임은 해결됐지만 **테마 89개, 거의 전부 주제 1개짜리**. 원인: 주제 키가 제품 단위(`qwen3.8-27b`, `minimax-h3-image`)라 트렌드 축이 되지 못함. 반면 분류 태그(`classification.tags`)는 범주 단위(`small-llm`, `local-llm`, `quantized-model`, `image-generation`, `text-to-speech`, `workflow-automation`)라 주 단위로 비교하기 좋다.
규칙 동일(커밋·docs·프롬프트 수정·키 출력 금지, LLM·네트워크 금지).

## 1. 테마 = 정규화한 분류 태그 (두 단계: 테마 → 주제)
- **테마**는 `classification.tags`(LLM 분류 태그)를 정규화한 값이다. 항목 하나가 태그 여러 개면 **각 테마에 모두 센다**(테마끼리 겹치는 것이 정상 — 1회차 5번 "한 항목 한 테마" 규칙은 **같은 테마 안에서 itemKey 중복 금지**로 바꾼다). 소스 태그(GitHub topics·HF 태그)는 테마로 쓰지 않는다.
- 태그 정규화(`TagNormalizer`): 소문자, `_`·공백 → `-`, 앞뒤 `-` 제거, 끝 `s` 복수형 단순 제거(`llms`→`llm`, `agents`→`agent`; 단 `ss`로 끝나면 제외), 설정의 동의어 표(`synonyms`, 예: `local-llm`←`on-device-llm`, `text-to-speech`←`tts`, `image-generation`←`text-to-image`)와 `themes.json`의 `overrides`(태그 → 테마) 적용.
- 제외: 설정 `excludeThemes`(너무 넓은 태그: `open-source`, `open-source-model`, `hf-space`, `model-release`, `ai`, `llm`, `agent`, `ai-agent`, `github`, `productivity` 등), 그리고 4주 관측 항목의 **30% 이상**에 붙은 태그(자동, 리포트 데이터 상태에 "너무 넓어 제외한 태그" 목록 표시).
- 테마 이름: 태그 그대로(kebab-case) + 표시 이름은 같은 테마 안에서 가장 많이 나온 **주제명 상위 2개**를 예시로 붙인다(예: `image-generation` · 예: MiniMax H3 Image, PrunaAI P-H3). 테마 행에 **주제(제품) 예시 최대 3개**와 대표 근거를 둔다.
- 기존 주제 키 묶기(ThemeMapper의 Jaccard·대표 기준 묶기)는 **주제 예시를 합칠 때만** 쓴다(같은 제품 이름이 날마다 다른 키로 나온 경우). 테마 결정에는 쓰지 않는다.
- `themes.json`은 `version` 3: `overrides`(태그 → 테마), 자동 제외 목록 기록. 버전 다르면 재생성, overrides 유지(1회차 규칙).
- 뜨는 테마 기준 "이번 주 ≥ 2건"은 유지. ◆·과열·증가율 규칙(1회차 4번 일평균 포함)은 테마 단위로 그대로.

## 2. OSS 속도 부풀림 수정
- 실제: `blender-ai-mcp-addon` rawScore 409, 생성 2026-11-19 14:43 → 하루 +1707로 표시. 스냅샷 간격이 1일 미만인데 하루치로 환산했기 때문.
- 스냅샷 방식은 **처음·마지막 스냅샷 간격이 1일 이상일 때만** 쓰고, 아니면 생성일 방식(rawScore ÷ max(생성 후 일수, 1)). 생성일 방식도 일수는 실수 그대로 쓰되 최소 1.0.
- 의심 표시 기준을 **포크/스타 < 0.005 그리고 스타 ≥ 200**으로 낮춘다(설정값).

## 3. 표시
- 텍스트·HTML 뜨는 테마 표에 "예시" 칸(주제명 최대 2개, 각 30자 자르기).
- 데이터 상태에 "너무 넓어 제외한 태그" 표시.

## 테스트
- 태그 정규화(복수형·동의어·`ss` 예외·overrides), 넓은 태그 자동 제외(30%), 고정 제외.
- 항목이 태그 2개면 두 테마에 각각 1건, 같은 테마에서 같은 itemKey는 1건(새 분류 + 재등장 겹침 포함).
- 재등장 항목은 원본 분류의 태그로 테마 배정(이번 분류가 있으면 이번 태그).
- 테마 행의 주제 예시가 같은 제품의 다른 주제 키를 합쳐서 보여 줌.
- OSS 속도: 간격 0.25일 스냅샷 2개 → 생성일 방식 사용; 간격 2일 → 스냅샷 방식. 의심 기준 200.
- 1회차 테스트 중 "테마 = 주제 묶음" 전제 테스트는 새 구조에 맞게 고친다(지운 테스트는 이유를 보고).
