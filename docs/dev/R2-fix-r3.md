# R2 수정 지시 — 3회차 (OpenAI 높음 2·중간 3·낮음 1, Claude 중간 3·낮음 2)

규칙은 R2와 같다.
- 커밋하지 않는다. `docs/`를 고치지 않는다(이 파일 제외).
- 실제 LLM·메일·수집 호출을 하지 않는다.
- 계측 테스트는 emulator-5554에서만 한다.
- **PC·Actions 동작은 HEAD와 같게 유지한다.**

원칙: 이중 과금·중복 메일이 없어야 하고, 그날 보고서나 메일이 **알림 없이** 빠지면 안 된다.

## 높음
1. **다른 날짜 Batch 결과를 오늘 실행이 내려받으면 그 날짜 보고서가 빠진다.** (OpenAI 1)
   - 이어받기의 실행 자격을 넓힌다. 해당 날짜의 실행 기록이 없고, 아래 둘 중 하나면 진행한다.
     - 미결 Batch가 있다.
     - 정산된 결과는 있는데 그 날짜 보고서가 아직 게시되지 않았다.
   - 진행할 때는 받아 둔 결과를 재사용해 게시·메일까지 한다. 추가 과금은 없어야 한다.
   - 이어받기 워커가 이미 끝났거나 없는 경우: 오늘 실행이 다른 날짜 결과를 정산했으면 그 날짜의 이어받기를 다시 예약한다. 그것이 어려우면 "어제 결과를 게시하지 못함" 알림을 띄운다.
   - 테스트: 어제 Batch가 끝나 오늘 실행이 결과를 내려받은 경우, 어제 보고서가 1회만 게시되고 추가 LLM 호출이 0회인지 확인한다.
2. **대기열 선반영이 실행 중인 예비 워커를 스스로 취소한다.** (OpenAI 2, Claude B4)
   - 실행 시작 훅(`beforeRun`)에서 `SettingsSet`을 반영할 때 예약 재등록(`register(update = true)`)을 하지 않는다.
   - 재등록은 실행이 끝난 뒤(`finishRun`)에 한 번 한다. 또는 실행 중에는 KEEP을 쓴다.
   - 테스트: 대기열에 설정 변경이 남은 채로 예비 워커가 시작해도 실행을 끝까지 마치는지 확인한다.

## 중간
3. **시스템 취소·재시도 차단을 알린다.** (OpenAI 3, Claude B3)
   - 시스템 취소(타임아웃·종료)로 끝났고, 비용이 나서 그날 자동 재시도가 막혔으면 실패 알림을 띄운다. 게시 뒤라 메일만 대기 중이면 "메일 대기" 알림을 띄운다.
   - 예비 워커가 `mayRetry()`가 거짓이라 종료할 때, 그날 기록이 없으면 실패 알림을 한 번 띄운다(같은 날 중복 알림 없음).
   - `status().missed`에 시스템 취소와 유료 실패도 반영한다.
4. **메일 결과를 알림에 드러낸다.** (OpenAI 4, Claude B2)
   - 실행 결과에 메일 상태를 담는다: 보냄 / 대기(마감·취소) / 실패(SMTP 거절 등).
   - 보고서는 게시됐는데 메일이 대기나 실패면, 완료 알림 문구를 "카드는 만들었지만 메일은 대기/실패"로 바꾼다. 실패 사유는 비밀값 없이 짧게 쓴다.
   - **마감을 넘겼을 때 메일을 미루는 동작은 앱 경로(`runDate != null` 등 앱 실행 옵션)에만 적용한다.** PC·Actions는 HEAD와 같이 메일을 보내고 마감 초과 이슈만 남긴다.
5. **메일 기록이 실패해도 게시는 막지 않는다.** (Claude B1)
   - `beforePublish`(게시 직전 메일 기록)에서 예외가 나면 이슈로 남기고 게시를 계속한다.
   - 이 경우 메일 단계는 기존 규칙대로 처리한다(기록 실패면 `RECORD_FAILED` 등).
   - 테스트: `mail/sent.json`이 손상돼도 보고서가 게시되는지 확인한다.
6. **일요일 트렌드 메일도 먼저 기록한다.** (OpenAI 5) 트렌드 게시 직전에도 일일 메일과 같은 방식으로 재시도 기록을 남긴다. 첫 SMTP 전에 취소돼도 다음 실행에서 1회만 보내져야 한다. 테스트를 추가한다.

## 낮음
7. 이미 실행 기록이 있는 날에는 `cancelByUser`를 무시한다. 성공한 날에 누락 경고가 뜨면 안 된다. (Claude B5)
8. 배터리 예외 필요 상태와 알림을 지운다. 앱 시작·서비스 실행·워커 시작 때 `isIgnoringBatteryOptimizations`가 참이면 지운다. (OpenAI 6)
9. `failedLocalChanges`를 표시하는 화면은 R3에서 만든다. 지금은 상태 노출만 유지하고, `onStart`의 다른 호출도 `runCatching`으로 감쌌는지 확인한다. (Claude 11)
