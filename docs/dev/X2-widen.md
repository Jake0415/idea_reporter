# X2 — 넓혀 보기: 미니 카드(F-45) + 골라서 키우기(F-46)

사용자 결정(2026-11-26): 카드나 추적 아이디어에서 [넓혀 보기]를 누르면 **미니 카드 3~5개**를 받는다. 그중 고른 것만 완전한 카드로 키운다. 렌즈는 X1의 6개를 쓰고, 설정에서 끈 렌즈는 쓰지 않는다.
전제: X1(F-42·F-43·F-44)이 들어가 있다. 렌즈 리소스, `expansion` 설정, IdeaCard의 `kind`·`lens`·`speculation`·`targetCustomer`·`coreTech`·`pain`, 반복 막기를 다시 쓴다.

## 규칙
X1-expand.md의 규칙과 같다. 하위 호환과 R3·R4·C1 구조(공통 실행 상태, 복구 대기 차단, 요청 예산·별도 비용 기록·월 차단, 메일 수신 재확인)를 그대로 쓴다.

## 1단계 F-45 미니 카드 만들기 (요청형, 유료)
**진입**
- 카드 상세(SC-02)와 추적 상세에 [넓혀 보기] 버튼을 둔다. 확장 카드에서도 누를 수 있다.

**렌즈 고르기**
- 켜진 렌즈가 칩으로 보인다. 기본으로 3개가 자동 선택된다(X1의 돌아가기·피드백 가중치를 그대로 씀).
- 1~5개까지 고를 수 있다. 미니 카드는 렌즈 하나당 1개다.

**견적 → 확인 → 실행**
- core에 `estimateWiden(source, lensIds)`와 `runWiden(source, lensIds, approvedMaxUsd)`를 둔다. `source`는 카드 id 또는 추적 id다.
- 입력
  - 원래 카드의 제목, 한 줄 설명, 문제, 대상 고객, 핵심 기술, 불편, 근거(SignalRef)
  - 원래 카드에 인용된 신호의 요약
  - 최근 카드 조합(반복 막기용)
  - 고른 렌즈 정의
- 모델: 설정의 카드 작성 단계 모델을 쓰고, 대체 공급자 규칙도 같다. 출력은 구조화된 출력으로 강제한다.
- 프롬프트: 새 리소스 `prompts/widen.md`. PromptCatalog에 등록해서 사용자가 고칠 수 있게 한다(SC-16 목록에 "넓혀 보기"로 보임).
- 웹 검색은 쓰지 않는다. 미니 카드는 가볍게 만든다.
- 비용
  - C1 요청 예산을 그대로 쓴다: 요청 1건 상한 `requestCardUsd`, 요청 하루 최대 `requestDailyUsd`, `out/cost-ledger-requested/`, 월 차단.
  - 실행 직전에 상한을 다시 확인한다.
- 실행: CollectorRunService(공통 실행 상태)로 돌리고 [취소]를 둔다. 매일 실행 중이거나 복구 대기 중이면 거절한다.

**미니 카드 형식 `MiniCard`**
- `id`, `sourceId`, `lens`
- `title`(15단어 이하), `oneLiner`, `targetCustomer`, `pain`
- `whyThisLens`: 렌즈를 이렇게 적용한 이유 한 문장
- `biggestRisk`
- `speculation`: 1개 이상
- `refs`: 원래 카드 근거 중 쓴 것. 원래 카드에 없는 URL은 거부한다.

**검증(코드)**
- 고른 렌즈마다 최대 1개만 받는다.
- 렌즈 id가 맞지 않거나, 필수 칸이 비었거나, 원래 카드 밖의 근거를 인용하면 그 미니 카드는 버린다.
- 반복 막기(F-42)로 최근 카드나 같은 묶음의 다른 미니 카드와 같으면 버린다.
- 버린 이유는 결과에 남겨 화면에 "n개는 조건이 맞지 않아 뺐습니다"로 보여 준다.

**저장**
- `out/widen/<날짜>-<id>.json`에 저장한다. 원래 카드 id, 렌즈, 미니 카드 목록, 버린 이유, 비용을 담는다.
- Room에 반영한다.
- 매일 결과 파일과 메일 상태는 건드리지 않는다.
- 백업은 "없는 것만 채우기" 규칙으로 포함한다(`out/widen/**`).

## 2단계 F-46 골라서 키우기 (요청형, 유료)
- 미니 카드마다 [카드로 키우기]가 있다.
- C1의 요청 카드 흐름을 다시 쓴다.
  - 근거 = 원래 카드 근거 + 미니 카드
  - 근거 보충, 견적, 추가 조사 선택, 상한 재확인, `out/requested` 저장, "요청" 배지를 그대로 쓴다.
- 결과 카드는 `kind: "expanded"`, `lens`, `speculation`을 갖는 완전한 카드다. "AI 확장 · 렌즈 이름" 칩과 "요청" 배지가 함께 붙는다.
- 키운 미니 카드에는 "카드로 만듦 ›" 표시가 붙고, 누르면 그 카드로 간다.

## 화면 (SC-17 넓혀 보기)
- 머리: 원래 카드 제목과 "넓혀 본 아이디어 n개"
- 렌즈 칩 선택 → 하단 고정 바 "렌즈 n개 · 추정 $0.0x · [넓혀 보기]"
- 결과 목록(미니 카드)
  - "AI 확장 · 렌즈 이름" 칩
  - 제목, 한 줄 설명
  - 대상 고객 · 불편
  - "AI 제안(추정)" 목록(접기)
  - 가장 큰 위험
  - [카드로 키우기]
- 같은 카드를 다시 넓혀 보면 이전 묶음이 날짜순으로 위에 쌓인다.
- 보관함(SC-03)에서 넓혀 본 기록이 있는 카드에는 "넓혀 본 아이디어 n ›"를 표시한다.
- 빈 상태와 실패 상태
  - 비용 0인 실패만 [다시 시도]를 허용한다.
  - 예산 초과는 C1과 같은 문구를 쓰고 설정 > 운영 설정 > 예산으로 안내한다.
- 다크 모드, 글자 200%, 48dp 터치 영역을 지킨다.
- 메일: 넓혀 보기 결과는 메일로 보내지 않는다(앱에서만 봄). 키운 카드는 C1 규칙대로 선택 메일을 보낸다.
