# P16 — 5단계: 앱 화면 (보기·조작 앱)

## 사용자 결정 (2026-11-23)
- 앱은 보기·조작 앱이다. 수집·LLM·메일은 GitHub Actions가 한다. 앱은 P15의 동기화·Room·대기열을 쓴다.
- 검증은 에뮬레이터·자동 테스트로 한다. 화면이 완성되면 사용자 폰에 설치한다.

## 설계 기준
- `docs/menu.md` §3·§4 (SC 번호, 화면 명세), §5 카드 블록
- `docs/design-tokens.md` + `mockup/tokens.css`(색·모서리·글꼴): A 피드 톤
- 시각 참고: `mockup/astryx-review/src/App.tsx`(SC-00~16 시안)
- 용어: `docs/design.md` 맨 앞 용어집(쓸 수 있는 기술 / 사람들의 요청·불편 / 이미 나온 제품, 단계별 건수 등)
- 계약: `core` `collector.data` KDoc(inbox 요청 종류·파일명, `analyze.yml` 입력, 새 requestId 규칙)

## 규칙
- 커밋하지 않는다. `docs/`는 고치지 않는다. 비밀값·주소를 기록하지 않는다.
- 실제 GitHub API 호출, push, workflow 실행을 하지 않는다. 테스트는 MockWebServer와 샘플 데이터로 한다.
- 계측 테스트는 `emulator-5554`에서만 돌린다. 실제 폰에는 설치하지 않는다.
- 모든 사용자 문구는 한국어로 쓰고 용어집을 따른다. 하드코딩하지 말고 `strings.xml`에 둔다.

## 메뉴 명세 → 보기·조작 앱으로 바꾸기
| 명세 | 이 앱에서 |
|---|---|
| SC-00 키·메일 입력·첫 실행 | **저장소 연결**: owner/repo 입력, GitHub 토큰 입력(필요 권한 안내: 이 저장소만, Contents read/write + Actions write, Workflows 권한 없음), [연결 확인](manifest 읽기), 알림 권한 요청, [첫 동기화] |
| "지금 실행" 버튼 | `daily.yml` workflow_dispatch 실행. 실행 중이면 버튼을 비활성화하고 "Actions에서 실행 중 — 끝나면 동기화" 표시. 최근 dispatch 시각은 Room에 저장 |
| ★ | inbox `track.start` + `feedback(STAR)`. 화면에는 바로 반영(낙관적)한다 |
| 관심 없음(이유) | inbox `feedback(NOT_INTERESTED, reason, memo≤500자)` |
| 추적 키워드 편집·종료 | `track.keywords`(10개·각 50자) / `track.stop` |
| SC-15/16 프롬프트 | 보기·편집·기본값과 비교·되돌리기 → `prompt.set`/`prompt.reset`(baseHash 포함, 20,000자 상한). **시험 실행은 하지 않는다(나중)** — "시험 실행은 나중에 제공" 안내 |
| SC-11 키·모델·메일 | **운영 설정**: 매일 실행 켜기/끄기·예산 설정(`settings.set`의 허용 키만), GitHub 토큰 교체·삭제(끝 4자리만 표시), 동기화 주기. LLM 키·메일 설정은 "GitHub Secrets에서 관리" 안내와 설정 문서 링크 |
| SC-07 출처 관리·SC-09 내 기준 | 이번에는 **읽기 전용** 화면(현재 값 표시)으로 둔다. 편집은 나중(계약 확장 필요) |

**요청 상태 표시:** inbox 요청이 걸린 항목에 상태 칩을 붙인다. 상태는 `대기 중` → `보냄` → `반영됨` / `거부(사유)`이다. 거부되면 낙관적 표시를 되돌리고 사유를 한 줄로 보여 준다. `internal_error`나 `확인 필요`면 [다시 요청] 버튼을 띄운다. 다시 요청할 때는 새 requestId를 쓴다.

## 만들 화면 (MVP)
- 하단 탭 4개: 오늘·추적·보관함·설정. 아이콘에 작은 글자 라벨을 붙이고, 선택된 탭은 채운 아이콘으로 표시한다.
- **SC-00** 저장소 연결: 위 표 참고. 토큰은 P15 `KeystoreSecretProvider`에 저장한다.
- **SC-01** 오늘의 카드
  - 맨 위: 추적 요약(A안, menu.md §4 SC-01 그대로)
  - 날짜·마지막 실행·오늘 비용, "단계별 건수 · 수집 n → 카드 후보 n → 카드 n", 실패 출처 띠
  - 카드 목록: 제목·한 줄 설명·분류·배지·★
  - 아래로 당기면 동기화
  - [지금 실행]
  - 상태: 동기화 전, 오늘 결과 없음(어제 카드 + "다음 실행 07:00"), 분류 Batch 대기, 동기화 실패
- **SC-02** 카드 상세: menu.md §5의 블록 순서를 따른다.
  - 근거는 쓸 수 있는 기술 / 사람들의 요청·불편 / 이미 나온 제품으로 나누고, 보충 자료(웹 검색)는 별도 칸에 둔다.
  - 근거 원문은 브라우저로 연다.
  - ★·관심 없음(이유 시트) 버튼을 둔다.
- **SC-13** 추적 목록, **SC-14** 추적 상세: menu.md 명세대로 만든다. 관련 글 수 화살표에는 글자를 함께 쓴다.
- **SC-03** 지난 카드: 날짜별로 묶고, 필터(★만·분류·관심 없음 숨기기)와 FTS 검색을 둔다.
- **SC-06** 설정 홈: 저장소·동기화 상태·운영 설정·프롬프트·실행 기록·정보(버전·오픈소스 고지)를 둔다.
- **SC-10/10a** 실행 기록: data 브랜치 `runs/`를 읽어 결과·단계별 건수·비용·Batch 여부·issues를 보여 준다.
- **SC-15/16** 프롬프트: 위 표 참고. 편집기는 고정폭 글꼴, 글자 수, 저장하지 않고 나갈 때 확인을 둔다.
- 딥 링크 `ideacollector://card/<id>`는 SC-02로, `ideacollector://track/<id>`는 SC-14로 보낸다.
- 알림을 누르면 해당 화면으로 간다(P15 알림).

트렌드·사업성 분석 화면(SC-17~28, `mockup/trend.html`)은 **P17**에서 만든다. 이번에는 탭을 만들지 않는다.

## 디자인
- `mockup/tokens.css` 값으로 Compose `MaterialTheme`(라이트·다크)·`Typography`·`Shapes`를 완성한다. 기기 기본 글꼴을 쓴다.
- 카드는 흰 바탕에 얇은 테두리, 그림자는 design-tokens.md의 확정 사항을 따른다.
- 접근성
  - 터치 영역 48dp 이상
  - 대비 WCAG AA
  - 모든 아이콘 버튼에 `contentDescription`
  - 화살표·색만으로 의미를 전달하지 않는다
  - 글자 크기 200%에서도 레이아웃이 깨지지 않는다
- 빈 상태·오류 상태·로딩 상태를 모든 화면에 둔다.

## 샘플 데이터
- debug 빌드에 **샘플 데이터 넣기**(개발 화면)를 만든다. `core` 테스트 픽스처 또는 실제 out JSON 형식을 따른 카드 5개·추적 3개·실행 기록·프롬프트를 Room에 넣는다. UX 리뷰 캡처용이다.
