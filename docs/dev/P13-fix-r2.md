# P13 수정 지시 — 2회차 (OpenAI 높음 3·중간 4·낮음 1, Claude 중간 3·낮음 3)

규칙은 같다. 커밋·docs 수정·실제 호출 금지.

**추가 원칙: 복구할 수 없는 상태는 반드시 끝이 있어야 한다.** 기한이 지나거나 복구가 불가능하면 격리하고 보수적으로 정산한다. 그 뒤로는 **오늘 실행을 막지 않는다.**

## 높음
1. **ID를 잃은 Batch 복구**
   - `custom_id`에 실행마다 고유한 값을 넣는다. 형식은 `<stage>-<runDate>-<runId 8자>-<묶음번호>`이고, `runId`는 의도 기록에 저장한다. 다른 실행의 Batch를 잘못 채택하지 않게 하기 위해서다.
   - 후보 채택 조건은 "결과 ID가 의도 기록의 ID 집합의 **부분집합**이고 하나 이상 일치"로 바꾼다(완전 일치를 요구하지 않는다).
   - 채택한 뒤 빠진 ID는 기존 5번 규칙(재조회 → 추정 정산 → 동기)으로 처리한다.
   - 아직 `ENDED`가 아닌 후보도 채택하고, 이후는 일반 대기 경로로 처리한다.
   - `list` 기준 시각은 의도 시각에서 10분을 뺀다. 생성 시각이 그보다 오래된 batch가 나오면 페이지 넘기기를 멈춘다.
2. **대기 상태는 반드시 끝난다.** 체크포인트·의도 기록마다 상태를 판정한다.
   - 다음 경우는 `out/batch/quarantine/`으로 옮긴다(격리).
     - 깨진 파일(파싱 실패)
     - 지속적인 404(2회 연속 실행)
     - 공급자 키 없음이 48시간 넘게 계속됨
     - 의도 기록 48시간 경과
     - 그 밖의 복구 불가
   - 격리할 때는 남은 예약을 예약액 그대로 정산(보수적)하고, 실행 기록에 issue를 남긴다. 키 없음은 키가 생기면 다시 시도할 수 있게 48시간까지만 대기한다.
   - **분류 대기 차단은 "오늘 실행이 이번에 제출한 오늘 분류 Batch"에만 적용한다.** 지난 날짜나 격리 대상 체크포인트는 오늘 파이프라인을 막지 않는다.
   - 복구 처리 전체에 시간 상한을 둔다. 기본 10분이고, 넘기면 남은 것은 다음 실행으로 넘기고 오늘 실행을 계속한다.
3. **예약 누수**
   - 순서를 이렇게 바꾼다.
     1. 예약 ID를 먼저 만든다.
     2. 그 ID 목록을 의도 기록에 **먼저** 원자적으로 저장한다.
     3. 원장에 예약한다.
     4. 제출한다.
   - 의도 기록은 있는데 원장 예약이 없으면 해제할 것이 없다. 원장 예약은 있는데 의도 기록이 없는 경우는 생기지 않는다.
   - 정산 루프는 항목별로 `try`해서, 하나가 실패해도 나머지를 계속 정산한다. 실패한 항목은 issue로 남긴다.
4. **제출 전 로컬 예외는 확정 실패로 본다.** (Claude) 요청이 나가기 전의 예외(직렬화, `system().get()`, 파라미터 생성 등)는 의도 기록을 지우고 동기로 진행한다. "불확실"은 HTTP 요청을 보낸 뒤 응답을 받지 못한 경우만이다. 테스트: 로컬 예외 → 동기, 의도 기록 없음.

## 중간
5. **메일 보류 범위.** 분류 대기로 보류하는 것은 **그날 daily 메일 1건**뿐이다. 다른 날짜 메일 재시도와 트렌드·분석 메일은 막지 않는다. 대신 전날 Batch가 미결이면 **그 날짜의** daily 재발송만 보류한다.
6. **보관 정리는 파일 단위로 한다.** 결과 파일은 개별 상태로 정리한다. 기준은 다음 셋 중 하나다.
   - 소비 완료 표시가 있고 7일 지남
   - 격리된 지 30일 지남
   - 대응하는 체크포인트가 없고 7일 지남
   - `.done` 등 포인터 삭제가 실패하면 결과 파일을 지우지 않는다.
7. **지난 날짜 결과도 재사용한다.** (Claude) 지난 날짜 Batch 결과(`results.jsonl`)는 itemKey 기준으로 보관한다. 오늘 후보에 같은 itemKey가 있으면 동기로 다시 부르지 말고 재사용한다(같은 검증을 거친다). 재사용 기간은 `recentTopicDays` 이내다.
8. **작성 예산 보장.** 보충 자료를 작성 입력에 넣을 때 한도를 둔다.
   - 개수: 최대 3개
   - 제목: 120자
   - 설명: 300자
   - 이 한도를 기준으로 작성 여유분을 계산한다.
   - 재개 결과가 현재 요청과 맞지 않아 동기로 넘어갈 때도, 저장해 둔 검증 링크를 동기 작성 입력에 넘긴다.
9. **마감.**
   - 마감은 **프로세스 시작 시각**(`startedAt`) 기준으로 계산한다.
   - Batch 폴링은 마감 5분 전에 멈추고, 취소·결과 다운로드·보고서 저장 여유를 남긴다.
   - 저장·발행이 마감을 넘기면 보고서는 저장하고 issue를 남긴다.
   - P14 workflow의 `timeout-minutes 150`과 맞추려면 `deadlineMinutes` 기본값을 130으로 바꾼다. 빌드·checkout·push 여유를 위해서다.
