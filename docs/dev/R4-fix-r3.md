# R4 수정 지시 3회차 — 범위 단순화

근거: R4 3회차 리뷰(OpenAI 높음 4·중간 1, Claude 높음·중간 없음·낮음 2). 원장 병합과 예산 가져오기는 고칠 때마다 새 경계 사례가 나왔다. 그래서 **이 둘은 가져오지 않는 쪽으로 단순화한다**. 규칙은 [R4-fix-r2.md](R4-fix-r2.md)와 같다.

## 결정(Claude, 단순화)
1. **비용 원장은 가져오지 않는다**
   - 백업에는 비용 기록을 "참고용"으로만 넣는다. 아예 빼도 된다.
   - 가져올 때 현재 폰의 원장(`cost-ledger*`, `prior-runs`, `.blocked`, 예약)은 그대로 둔다.
   - 원장 병합 코드와 그 테스트는 지운다. 대신 "가져오기 전후로 원장 파일이 바이트 단위로 같다"는 테스트를 넣는다.
   - 미리보기와 `backup_preview_details` 괄호 문구는 "(비용 기록과 예산은 이 폰 것을 그대로 둡니다)"로 바꾼다.
2. **예산 설정(`budget.json`)도 가져오지 않는다**
   - 현재 폰의 예산을 항상 유지한다.
   - 예산 완화 확인 화면과 그 코드·문구·캡처를 지운다.
   - 내보내기에는 넣어도 되지만 가져오기에서는 무시한다.
   - `backup_help`에서 "실행 기록" 뒤에 들어 있던 비용 언급을 빼고, "예산은 새 폰에서 다시 정하세요"를 덧붙인다.

## 코드
3. **워커 경합:** 실행권(공통 실행 상태·run lock)을 얻은 **직후** 복구 상태가 READY인지 다시 확인한다. 아니면 실행권을 반납하고 실패나 시도 횟수를 기록하지 않은 채 끝낸다. 서비스·워커·지연 워커 모두 같다.
4. **복구 대기 중 Batch 이어받기:** PENDING이거나 LOADING일 때 Deferred·Backup·Batch 이어받기 워커는 `Result.success()` 대신 `Result.retry()`를 돌려준다. READY로 바뀌면 `register()`와 `recoverBatch`를 다시 부른다.
5. **스냅샷 유실 시 복구 대기 해제**
   - 저널을 쓰기 전에 스냅샷 파일과 디렉터리가 디스크에 반영돼 있어야 한다(fsync 또는 이에 준하는 방법).
   - 저널이 가리키는 스냅샷이 없거나 깨졌으면, 현재 파일을 그대로 두고 저널을 "복구 불가"로 닫는다. 그리고 READY로 돌아간다.
   - 이때 화면에 "이전 가져오기를 되돌릴 자료가 없어 지금 상태로 계속합니다. 필요하면 백업을 다시 가져오세요."를 한 번 보여 준다.
   - 테스트를 넣는다.
6. **RSS 짧은 토큰**
   - 피드 제외에 쓰는 민감 쿼리 판별(이름이 privateField에 걸리거나 값이 6자 이상)을 함수 하나로 묶는다. RSS 어댑터의 결과 정제(항목 링크)와 백업 내보내기(저장된 일일 결과의 모든 URL) 양쪽에서 이 함수를 쓴다.
   - 걸린 쿼리 파라미터는 값을 `[redacted]`로 바꾼다.
   - 테스트를 넣는다.
