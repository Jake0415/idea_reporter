# P14 수정 지시 — 3회차 (Claude 통과·낮음 2, OpenAI 높음 1·중간 4·낮음 2)

규칙은 같다. 커밋·docs 수정·실제 실행·push 금지.

## 높음
1. **러너가 중간에 끊겨도 과금 기록이 원격에 남게 한다.**
   - **분석:** `running` 표시를 push할 때 **비용 예약(최대 추정액)**도 원장에 기록해 함께 push한다.
     - 러너가 사라지면 다음 실행은 그 예약을 보수적으로 정산된 것으로 본다. 기존 미정산 예약 처리 규칙을 따른다.
     - 정상 종료하면 실제 금액으로 정산한다.
   - **daily Batch:** `core`에 체크포인트 훅을 둔다.
     - 훅은 환경 변수 `COLLECTOR_STATE_HOOK`(명령 경로)이고, Batch 의도 기록·원장 예약 직후와 batchId를 받은 직후에 호출한다.
     - 훅은 `actions-data.sh publish-state`로 **공개 Batch 메타데이터와 원장만** data 브랜치에 push한다.
     - 의도 기록 직후 훅이 실패하면 **Batch를 제출하지 않고** 동기로 진행한다. 제출 전이라 이중 과금이 없다.
     - batchId를 받은 뒤 훅이 실패하면 issue만 남기고 계속한다. 로컬 체크포인트는 남는다.
     - 훅이 없으면(PC) 지금처럼 동작한다.
   - 테스트:
     - 훅 실패 시 제출 0건
     - 훅 호출 순서
     - 분석 `running` push에 예약 포함
2. **재구성 push가 원격에만 있는 기록을 지우지 않게 한다.**
   - 충돌 해결기가 실패해 `origin/data`에서 다시 만들 때는 미러링(삭제 포함)하지 않는다. **로컬 출력을 원격 위에 덧씌운다.**
   - 삭제는 병합된 트리에 보관 규칙(historyDays 등)을 다시 계산해서 한 것만 허용한다.
   - 원격에만 있는 분석 결과·큐·원장·Batch 메타데이터·inbox-results는 보존한다.
   - 테스트: 원격에만 있는 파일 보존.

## 중간
3. **메일 단계 견고성.**
   - 각 push에 시간 제한(기본 3분)을 둔다.
   - 한 건의 push 실패는 그 건만 "보내지 않음(다음 실행 재시도)"로 처리한다. 다음 건은 계속한다.
   - 분석 메일에도 남은 시간 10분 검사를 적용한다.
   - `sending` push 직후 SMTP 전에 job이 끊기면 `unknown`이 된다. 이는 보수적 동작으로 유지한다. 대신 `scripts/actions-setup.md`의 남은 위험 설명에 "unknown이면 받은편지함 확인 후 `--resend`"를 쓰고, 결과 push 실패와 발송 전 유실을 구분해 적는다.
4. **유효한 요청 ID의 처리 오류는 그 ID로 결과를 남긴다.** 파일명·본문 ID·스키마가 유효하면, 적용 중 오류(baseHash 불일치, 저장 오류 등)는 **원래 requestId의 결과 슬롯**에 `rejected`/`internal_error`와 사유로 기록한다. `invalid-*`는 ID를 알 수 없거나 무효일 때만 쓴다. 테스트를 추가한다.
5. **국제화 이메일.** 이메일 정규식의 로컬부·도메인을 유니코드 문자(`\p{L}\p{N}`)까지 넓힌다. 디코딩 뒤에도 같은 정규식을 적용한다. 테스트: `ops@bücher.example`.

## 낮음
6. 큐 파일이 없는 `running`도 daily 복구 대상으로 삼는다. `inbox-results`에서 `running`이고 6시간 이상 지난 것은 "확인 필요"로 전환한다.
7. `scripts/actions-setup.md` 남은 위험에 한 줄 추가: "Batch 제출 후 상태 push 전에 러너가 끊기면 같은 날 수동 재실행에서 재제출될 수 있음(훅으로 대부분 막음, 금액 하루 수 센트)". (Claude)
