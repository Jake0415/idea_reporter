# P12 — 표시 용어 쉽게 바꾸기

근거: [docs/terminology-plan.md](../terminology-plan.md). 사용자가 2026-11-23에 "풀어 쓴 이름"을 골랐다.

## 규칙
- 커밋하지 않는다. `docs/`는 고치지 않는다(문서는 Claude가 고친다).
- 비밀값·주소를 기록하지 않는다. 실제 메일 발송, LLM 호출, 스케줄러 등록은 하지 않는다.
- **바꾸는 것은 사용자가 읽는 문구뿐이다.** 다음은 바꾸지 않는다.
  - 코드 식별자: `tech-signal`·`demand-signal`·`market-signal`, `techSignals`·`demandSignals`·`competitors`, `SignalRef`, enum 이름, JSON 필드명.
  - 저장 파일 형식과 이미 저장된 기록의 읽기.
- 프롬프트 본문(`prompts/ideas.md`·`classify.md`·`track.md`, 각 프로필의 `match.md`·`analysis.md` 본문)은 이번에 고치지 않는다. 단, `match.md`·`analysis.md`의 **첫 줄 제목**은 아래 이름에 맞춘다.
- 문구가 LLM에 되돌려 보내지는 경우(재시도 피드백 등)도 뜻이 같으면 바꿔도 된다. 다만 코드가 문자열을 비교해 분기하는 곳(예: `BUDGET_LIMIT`, `MONTHLY_TOTAL_EXCEEDED`, 메일 알림 문자열 비교)이 깨지지 않게 상수를 함께 바꾸거나 그대로 둔다.

## 바꿀 용어

| 지금 | 바꿀 말 |
|---|---|
| 기술 신호 | 쓸 수 있는 기술 |
| 수요 신호 | 사람들의 요청·불편 |
| 시장 신호 / 경쟁 신호 | 이미 나온 제품 |
| 경쟁 제품 (프로필 이름) | 이미 나온 제품 |
| 수요·경쟁 (근거 칸 이름) | 요청·불편 또는 이미 나온 제품 |
| 신호 강도 (출력에 있으면) | 관련 글 수(최근 7일) |
| 깔때기 | 단계별 건수 |
| 점수 통일 | 점수 맞추기 |
| 보강 | 댓글·과거 기록 붙이기 |
| 후보 (단계 이름·메일 제목) | 카드 후보 |
| 프로필 (출력 문구) | 분류 |
| 임계값 통과 | 기준 점수 통과 |
| 인용 (검증·탈락 사유) | 근거 링크 |
| 인용 이유 비어 있음 | 근거 링크 설명 비어 있음 |
| 블록-프로필 불일치 | 근거 칸과 분류가 맞지 않음 |
| 분류 상한 초과: X (최대 n) | 같은 분야 카드 수 초과: X (최대 n) |
| 수신 n명 | 받는 사람 n명 |
| 과열 / (과열) | 제품 몰림 / (제품 몰림) |
| 과열 경고 · X 시장 신호 n건 | 제품 몰림 · X 이미 나온 제품 n건 |
| 과열 경고 · X 저장소 n개 | 저장소 몰림 · X 저장소 n개 |
| (의심) | (스타 조작 의심) |
| 재등장 미매핑 n건 | 테마에 못 넣은 반복 글 n건 |
| 희소 태그 n개 제외 | 너무 드문 태그 n개 제외 |
| 포크/스타 | 포크 비율 |
| 트렌드 표 열 "수요"·"시장" | "요청·불편"·"이미 나온 제품" |

추가: 트렌드 리포트(텍스트·HTML)에서 ◆가 처음 나오는 곳 근처에 한 줄 설명 "◆ = 사업성 분석을 요청할 만한 테마"를 넣는다(후보가 0개면 생략).
