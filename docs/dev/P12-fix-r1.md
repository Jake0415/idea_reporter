# P12 수정 지시 — 1회차 (Claude 통과·중간 1, OpenAI 높음 0·중간 2·낮음 2)

규칙 동일(커밋·docs 수정·비밀값/주소 기록 금지, 실제 발송·LLM·스케줄러 등록 금지, 식별자·저장 형식·프롬프트 본문 유지).

1. **[중간, 둘 다] 트렌드 리포트 "제품 몰림" 섹션에 저장소 몰림이 섞임** — 섹션 제목을 "몰림(제품·저장소)"으로 바꾸고, 그 아래 줄은 지금처럼 "제품 몰림 · …" / "저장소 몰림 · …"으로 종류를 앞에 붙여 구분한다. 텍스트·HTML 모두. 테마 표의 꼬리표 "(제품 몰림)"은 그대로.
2. **[중간, OpenAI] `PromptCatalog` 초기화가 `ProfileLoader.loadDefaults()` 전체 검증에 묶임** — 표시 이름 때문에 공통 프롬프트(`ideas`, `criteria` 등) 조회까지 실패할 수 있다. 프로필 표시 이름은 실패해도 공통 프롬프트에 영향이 없게 바꾼다: 예) 각 `profile.json`의 `name`만 가볍게 읽고 실패하면 프로필 ID를 표시 이름으로 쓴다(검증·예외 전파 없음). 테스트: 프로필 이름을 못 읽는 상황에서도 `ideas` 프롬프트 정보 조회가 된다(주입 가능한 구조로 만들거나 이름 조회 함수를 분리해 테스트).
3. **[낮음] 금지어 테스트 범위 확대** — 일일 메일 fixture에 카드 1장(근거 포함)과 검증 이슈 1건을 넣고, 트렌드 쪽은 `TrendAnalyzer`를 거친 결과(스팸 묶음 또는 몰림 테마가 있어 summary에 경고가 생기는 입력)를 렌더해 "신호"·"깔때기"·"미매핑"·"희소"·"과열"이 없는지 확인. `MailDelivery`의 "받는 사람 n명" 출력도 기존 테스트에서 한 번 확인.
4. **[낮음] 문구 다듬기**
   - `IdeaGenerator`: "X 근거 없음(근거 링크 없음)" → "X 근거 링크 없음", 무효가 있을 때 "X 근거 링크 없음(n건 무효: …)". "쓸 수 있는 기술을 포함한 카드 후보를…" → "쓸 수 있는 기술 항목을 포함한 카드 후보를…".
   - `Classifier`: "후보에 없는 분류(X)" → "허용된 분류가 아님(X)".
5. **[낮음] `AnalysisRun.kt:84` 들여쓰기** 원래대로.
