# R3 수정 지시 — 1회차 (코드: OpenAI 높음 3·중간 7·낮음 2, Claude 높음 1·중간 6·낮음 3 / UX: 높음 7·중간 8·낮음 5 / 사용자 결정 A~D)

규칙은 R3와 같다.
- 커밋하지 않는다. `docs/`를 고치지 않는다(이 파일 제외).
- 실제 LLM·메일·수집 호출을 하지 않는다.
- 계측 테스트와 캡처는 emulator-5554에서만 한다.
- 비밀값·주소를 기록하지 않는다.
- 문구는 `strings.xml`에 두고 화면 용어 규칙(쉬운 말)을 따른다.

## 사용자 결정 (2026-11-24)
- **A. 마법사 버튼:** 하단 고정 바 [이전 | 다음].
  - 단계 안 동작([확인]·[테스트 발송])은 해당 입력 바로 아래에 둔다.
  - 건너뛰기류("메일 받지 않기"·"기본값으로 건너뛰기")는 바 위의 텍스트 버튼으로 둔다.
- **B. SC-01 경고 띠:** 가장 급한 것 하나만 보여 주고 "외 n건 ›"로 묶는다.
  - 우선순위: 키 없음·실행 실패 > 오늘 실행 안 됨 > 배터리·정각 권한 > 메일 실패 > 예산 초과.
  - "외 n건 ›"을 누르면 경고 목록(시트)을 보여 준다.
- **C. SC-11 구조:** 한 페이지를 유지하고 구역 제목(일정 · 권한 · 메일 · AI 키 · 모델 · 예산 · 고급)을 붙인다.
- **D. 메일 결과:** SC-01 상단 상태 줄 끝에 항상 표시한다. 예: "· 메일 보냄" / "· 메일 대기" / "· 메일 실패 ›". 실패를 누르면 SC-11 메일 구역으로 간다.

## 코드 — 높음
1. **R2에서 올라온 기기의 키·자동 실행이 막힌다.** (OpenAI 1, Claude 3·4)
   - `key-confirmation` 기록이 없는 기존 키는 쓸 수 있는 것으로 이관한다.
   - 키 재확인은 인증 오류(401/403)일 때만 실패로 기록한다. 네트워크 오류·시간 초과는 상태를 바꾸지 않고 "확인하지 못함(다시 시도)"으로 보여 준다.
   - Batch 회수(이미 낸 결과)에는 키 상태 거름을 적용하지 않는다.
   - 자동 실행 조건은 "쓸 수 있는 키가 있음"만 본다. 첫 실행 완료 여부를 조건에 넣지 않는다.
   - 마법사를 마치지 않은 상태는 별도 사유("첫 설정을 마쳐 주세요")로 알린다. "AI 키 없음"으로 알리지 않는다.
   - 대안: 첫 실행 전에는 알람을 등록하지 않는다. 둘 중 일관된 쪽을 택해 보고한다.
2. **SC-09 저장이 기준 문서를 덮어쓴다.** (Claude 1, OpenAI 중간 3)
   - 파서가 `- **개발 범위:** …`처럼 굵은 표시가 있는 형식과 이름 차이("수익화"/"수익화 방식")를 받아야 한다. 기본 `criteria.default.md`를 읽으면 다섯 칸이 채워져야 한다.
   - 저장할 때는 양식에 해당하는 줄만 바꾸고, 나머지 줄(제목·선호·자유 서술·SC-16에서 손으로 고친 내용)은 그대로 둔다.
   - 실행 중 두 번 저장할 때 같은 기준 해시로 두 번째가 실패하지 않게 한다. 대기열 반영 때 최신 본문 기준으로 병합한다.
   - 테스트: 기본 파일 왕복, 자유 서술 보존.
3. **사업성 분석이 요청 상한을 넘을 수 있다.** (OpenAI 2)
   - 실행 직전에 core에서 현재 저장된 `analysisRequestUsd`·월 상한으로 다시 판단한다. UI가 넘긴 예약액이 현재 상한을 넘으면 실행하지 않고 견적을 다시 받게 한다.
   - `AUTO_FIT`으로 맞춘 구성은 그 구성의 견적 금액으로 승인한다.
   - 상한을 바꾸면 이전 견적은 무효로 한다.
4. **[테스트 발송]만 해도 운영 메일 설정이 바뀐다.** (OpenAI 3)
   - 테스트 발송은 입력 중인 값으로 임시 메일러를 만들어 보낸다. 저장하지 않는다.
   - [저장]을 눌렀을 때만 세 값(받는 주소·보내는 주소·앱 비밀번호)을 한 번에 원자적으로 저장한다.

## 코드 — 중간
5. **메일 입력에 FLAG_SECURE를 건다.** (OpenAI 중간 1, Claude 2)
   - 앱 비밀번호 칸이 보이는 동안(마법사 2단계, SC-11 메일) `SecureTokenInput`을 적용한다.
   - 주소 칸은 가리지 않는다(`secret=false`, Email 키보드). 형식 오류는 칸 아래에 이유를 보여 준다.
6. **SC-11 연속 저장이 앞선 변경을 되돌린다.** (OpenAI 중간 2) 저장할 때는 바뀐 필드만 대기열에 넣는다. 폼은 대기 중인 변경까지 반영한 값을 보여 준다.
7. **출처 프로필 배정을 검증한다.** (Claude 5, UX 4)
   - 자유 입력 대신 "분류 기준" 칩 3개(쓸 수 있는 기술 / 사람들의 요청·불편 / 이미 나온 제품)로 고르게 하고, 최소 1개를 고르게 한다.
   - 저장 전에 `ProfileLoader.validateRouting`을 통과해야 한다.
   - 저장 대상 sourceId가 없으면 오류로 처리한다.
8. **연결 테스트 확인 문구를 실제 동작과 맞춘다.** (OpenAI 중간 4)
   - 확인 창에 요청 수를 적는다. 예: "검색어 3개 → 3번 접속, 요금 없음".
   - RSS 피드가 모두 실패하면 "0건" 대신 실패로 보여 준다.
9. **첫 실행의 Batch 대기를 실패로 보이지 않는다.** (OpenAI 중간 5)
   - 마법사 5단계에서 Batch 대기로 끝나면 "카드는 잠시 뒤 나옵니다(묶음 처리 대기)"로 보여 주고 완료로 처리한다.
   - 이후 워커가 게시하면 오늘 화면에 반영되게 한다(Room·Flow 관찰).
10. **시험 실행·분석 상태를 회전과 프로세스 종료에서 보존한다.** (OpenAI 중간 6)
    - 호출은 화면 코루틴이 아니라 ViewModel이나 앱 범위에서 실행한다.
    - 승인·결과·선택 후보·견적은 저장 상태에 둔다(비밀값 제외).
    - 진행 중인 유료 호출을 회전 때문에 다시 승인하게 하지 않는다.
11. **R2 상태 표시를 바로잡는다.** (OpenAI 중간 7)
    - `batch-expired-*`인 날짜도 실행 기록의 "Batch 결과 미게시"에 포함한다.
    - 시스템 취소와 사용자 취소를 구분해 SC-01 사유 문구에 쓴다.
    - 다른 날짜 메일 실패 건수는 영구 저장해 프로세스가 종료돼도 남게 한다.
12. **SC-01이 예외로 죽지 않게 한다.** (Claude 6) `LaunchedEffect`의 `runtime()`·`scheduledMailStatus` 블록 전체를 `runCatching`으로 감싸고, 실패하면 해당 표시만 생략한다.
13. **권한 상태를 즉시 갱신한다.** (Claude 7)
    - 알림 허용 여부를 ON_RESUME 카운터와 묶은 상태로 읽어, 돌아왔을 때 다시 그리게 한다.
    - 요청할 수 없으면(두 번 거절, Android 12 이하) 앱 알림 설정 화면(`ACTION_APP_NOTIFICATION_SETTINGS`)을 연다.

## 코드 — 낮음
14. 시험 실행·메일 테스트는 실행 중이면 버튼을 끄고 "실행 중에는 할 수 없습니다"를 보여 준다. 시험 실행 확인 창에 남은 일일 예산도 보여 준다. (Claude 8)
15. AI 키 [삭제]는 확인 창을 띄운다. 마지막 키라면 "매일 실행이 멈춥니다"를 경고한다. (Claude 9)
16. 접근성: 스위치와 [켜기] 버튼에 대상 이름을 넣는다(예: "알림 켜기", "Wi-Fi에서만 실행"). 스위치는 라벨과 합쳐 하나의 토글로 읽히게 한다. (Claude 10, OpenAI 낮음 1)

## UX (높음·중간 반영, 문구는 제안을 기준으로 다듬어도 됨)
17. **SC-00 1단계**
    - 소제목: "AI가 카드를 쓰려면 키가 하나 필요합니다".
    - 요금 안내: "사용한 만큼 공급자에 요금이 나갑니다(하루 상한은 설정에서 변경)". 상한 금액은 실제 설정값으로 보여 준다.
    - 입력란마다 "키 받는 곳 ↗" 링크와 형식 힌트를 둔다.
    - 상태 문구는 [확인]을 누른 뒤에만 보인다.
    - 오늘 화면용 빈 문구가 이 단계에 섞여 있으면 뺀다.
18. **SC-00 4단계와 SC-11 권한**
    - 항목마다 이유를 한 줄로 단다.
      - 알림: "실행 진행과 실패를 알려 드립니다"
      - 정각 실행: "정한 시각에 정확히 시작합니다"
      - 배터리 예외: "폰이 절전 중이어도 실행되게 합니다"
    - 꺼진 항목이 있을 때: "꺼진 항목이 있으면 실행이 몇 시간 늦거나 건너뛸 수 있습니다".
    - 삼성 기기면 배터리 항목 아래에 경로를 안내한다. 이 안내가 실제로 보이게 한다.
    - 켜짐은 ✓, 꺼짐은 경고 아이콘과 [켜기]로 보여 준다.
19. **SC-00 5단계:** "약 3~5분 걸립니다. 예상 비용 약 $x. 결과는 오늘 화면과 메일로 받습니다."를 넣는다. 금액은 추정값을 쓰고, 없으면 금액 부분을 생략한다. 실패하면 같은 자리에 사유와 [다시 시도]를 보여 준다.
20. **SC-01 실행 중**
    - ↻ 자리에 48dp 원형 진행 표시와 "실행 중" 라벨을 둔다.
    - 띠: "실행 중 · 2/5 분류 중"과 [취소]. 남은 시간은 추정할 수 있을 때만 표시한다.
21. **SC-01 경고 문구에 이유와 할 일을 넣는다.**
    - "AI 키가 없어 실행할 수 없습니다 · 키 등록 ›"
    - "절전 때문에 오늘 실행이 멈췄습니다 · 배터리 예외 켜기 ›"
    - "오늘 실행 안 됨 · 제시간에 시작하지 못함 ›" / "· 취소함" / "· 실행 실패 ›"
    - "오늘 예산을 다 써서 카드를 만들지 못했습니다 · 예산 보기 ›"
    - 비활성 ↻를 누르면 같은 이유를 스낵바로 보여 준다.
22. **SC-01 정리**
    - 날짜 줄에서 중복된 마지막 실행 시각을 빼고 "11월 24일 (화) · 비용 $0.00"으로 쓴다.
    - "★로 아이디어를 추적해 보세요"는 카드 목록 아래 회색 한 줄로 옮기고, ★를 한 번 쓰면 숨긴다.
23. **다크 모드 선택 탭 대비:** 선택 알약은 진한 회색(토큰에 맞춰), 아이콘은 포인트색 또는 흰색으로 해서 대비 3:1 이상으로 맞춘다. 필요하면 `mockup/tokens.css`의 다크 토큰을 추가한다(MailTheme 대조 테스트 유지).
24. **용어**
    - "프로필 배정" → "분류 기준"(칩).
    - "LLM 키" → "AI 키".
    - 화면에 보이는 "Batch" → "묶음 처리"(코드 식별자는 그대로).
    - 예산 단위는 "(달러)"로 통일하고, 빈 월 예산 칸에는 "비우면 상한 없음" 도움말을 단다.
25. **SC-11:** 구역 제목(결정 C)을 붙이고, "다음 실행"은 실행 시각 아래에 둔다. 저장 계열 안내는 다음과 같이 한다.
    - 저장 직후 스낵바: "저장했습니다 · 지금 실행이 끝나면 반영됩니다"(실행 중일 때).
    - 반영 실패: 맨 위 경고 띠 "변경 n건을 반영하지 못했습니다 · 다시 시도 / 버리기". [버리기]는 확인 창을 띄운다.
    - 예약 갱신 대기: "실행이 끝나면 새 시각이 적용됩니다".
26. **SC-07 상세:** [연결 테스트]는 테두리 버튼, [저장]은 하단에 고정한다. 통계는 "0.0건" 대신 "0건"으로, 기록이 없으면 "아직 기록 없음"으로 쓴다.
27. **SC-09·SC-00 3단계**
    - 라벨: "같은 분류 카드 최대 n개", "카드당 태그 최대 n개", "내 ★·숨김 기록 중 참고할 개수".
    - 빈 칸에는 기본값을 회색 힌트로 보여 준다.
28. **사업성 분석**
    - 중복된 제목을 뺀다.
    - 설명: "트렌드 리포트에서 뜨는 주제(◆)를 고르면 예상 비용을 보여 드립니다. 실행 전에 한 번 더 확인합니다".
    - 버튼: "예상 $x · 분석 실행".
29. **낮음(가능하면)**
    - SC-16: 본문 왼쪽 정렬, 상단 바 고정.
    - SC-15: 항목별 한 줄 설명.
    - ↻는 머티리얼 Refresh 아이콘, 48dp, contentDescription "지금 실행".
    - 버튼은 최소 폭 + 감싸기로 바꿔 200%에서 잘리지 않게 한다.
