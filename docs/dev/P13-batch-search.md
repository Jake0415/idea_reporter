# P13 — 6단계(1): Batch API + 보충 웹 검색

사용자 결정(2026-11-23): 6단계는 **Batch API, 보충 웹 검색, runner + GitHub Actions**를 모두 만든다. 이 지시서는 앞의 두 가지만 다룬다. runner와 Actions는 P14에서 한다.

## 규칙
- 커밋하지 않는다. `docs/`는 고치지 않는다.
- 비밀값·주소를 기록하지 않는다.
- **실제 LLM 호출·실제 Batch 제출·실제 웹 검색은 하지 않는다.** 테스트는 MockWebServer나 가짜 공급자로만 한다.
- Anthropic 공식 Java SDK를 쓴다(이미 의존성에 있음). 클래스·메서드 이름은 추측하지 말고 의존성 jar(`javap` 등)나 SDK 문서로 확인한다.
  - Batch: `com.anthropic.models.messages.batches`
  - 웹 검색 도구: `WebSearchTool20260209` (`com.anthropic.models.messages`)
- 화면 용어는 `docs/design.md` 맨 앞 용어집을 따른다. 예: "근거 링크", "쓸 수 있는 기술", "사람들의 요청·불편", "이미 나온 제품".

## A. Batch API (Anthropic)

목적: 아무도 기다리지 않는 분류 호출을 Batch로 보내 비용을 약 50% 줄인다.

1. **설정.** `pipeline.default.json`에 아래 값을 추가한다.
   ```json
   "batch": { "classify": true, "backfill": true, "generate": false, "pollSeconds": 30, "maxWaitMinutes": 90 }
   ```
   - 기본값은 분류(일일)와 과거 채우기 분류를 켜고, 카드 작성은 끈다.
   - 공급자가 OpenAI인 단계는 지금 동기 호출 그대로 둔다. 로그에 "Batch 미지원 공급자 · 동기 실행"을 남긴다.
2. **동작.**
   - 분류 요청 묶음(기존 `classifyBatchSize` 단위)을 Message Batch 하나로 제출한다.
     - 요청마다 `custom_id`를 붙인다. 형식은 `<stage>-<runDate>-<묶음번호>`처럼 결정적으로 만든다.
     - 프롬프트 캐싱·구조화 출력·effort는 동기 요청과 같은 파라미터를 쓴다(동기 요청 빌더를 재사용).
   - `pollSeconds` 간격으로 상태를 확인하고, 끝나면 결과를 받아 `custom_id`로 원래 묶음에 맞춘다.
   - 결과 파싱·스키마 검증·분류 검증은 기존 동기 경로와 같은 코드를 거친다.
3. **중단과 재개.**
   - 제출 직후 `out/batch/<runDate>-<stage>.json`에 batch id, 요청 `custom_id` 목록, 예약 금액, 제출 시각을 원자적으로 저장한다.
   - 같은 날 같은 단계를 다시 실행했을 때 이 파일이 있고 batch가 살아 있으면 **새로 제출하지 않고 기존 batch 결과를 받는다**(이중 과금 방지).
   - 다 받으면 파일을 지우거나 완료로 표시한다.
4. **실패와 대체.**
   - `maxWaitMinutes`를 넘기면 batch를 취소(cancel)하고, 남은 묶음만 동기로 실행한다.
     - 끝난 요청 결과는 버리지 않는다.
     - 취소 요청 뒤에도 이미 끝난 결과가 있으면 받아 쓴다.
   - 개별 요청이 errored·expired·canceled이면 그 묶음만 동기로 재시도한다(1회).
   - batch 제출 자체가 실패하면 전체를 동기로 실행한다.
   - 이 모든 경우를 실행 기록 issues에 짧게 남긴다. 예: "Batch 시간 초과 · 3묶음 동기 실행"
5. **비용.**
   - 가격표(`models.default.json`)에 batch 할인율을 둔다. 기본 0.5, 입력·출력 모두 적용, 캐시 읽기·쓰기도 같은 비율.
   - 예약은 batch 가격 기준 최대 출력으로 잡는다. 동기 대체로 넘어가면 동기 가격으로 다시 예약한다(`CostGuard` 기존 흐름 재사용).
   - `LlmCall`에 `batch: Boolean`(기본 false) 필드를 추가한다. 비용 기록과 실행 기록(SC-10)에 Batch 여부가 남게 한다.
   - 이전 기록 읽기 호환을 유지한다(기본값 있는 필드).
6. **시간.**
   - 일일 실행은 Batch를 기다리는 만큼 늦어질 수 있다.
   - `--scheduled` 07:00 실행에서도 그대로 동작하게 하고, 메일 머리에 "분류 Batch 대기 n분"을 표시한다. 1분 미만이면 생략.
7. **테스트.** MockWebServer로 Batch 생성·조회·결과 엔드포인트를 흉내 낸다. 확인할 것:
   - 정상
   - 진행 중에 재실행하면 재개(제출 0회)
   - 시간 초과 → 취소 + 남은 묶음 동기
   - 개별 errored → 그 묶음만 동기
   - 제출 실패 → 전체 동기
   - 비용이 할인가로 기록됨
   - OpenAI 단계는 동기
   - 기존 `pipeline.json`(batch 항목 없음)을 그대로 읽음

## B. 보충 웹 검색 (카드 작성 보조)

목적: 카드 작성 때 수집 후보만으로 부족한 근거를 Claude 웹 검색으로 보충한다. **수집 근거를 대신하지는 않는다.**

1. **설정.** 기존 `"supplementSearch": { "enabled": false, "maxUses": 3 }`를 유지하되 기본값을 `enabled: true`로 바꾼다(사용자가 이 기능을 고름). 추가 필드:
   - `allowedDomains`: 기본 빈 목록, 비면 제한 없음
   - `blockedDomains`: 기본 빈 목록
2. **방식.** 둘 중 SDK·API에서 검증되는 쪽을 고르고 이유를 보고한다.
   - (a) 카드 작성 호출(`generate`)에 `WebSearchTool20260209`(`maxUses` = 설정값)을 붙인다. 구조화 출력과 서버 도구를 함께 쓸 수 있는지 SDK로 확인한다.
   - (b) 카드 작성 **전** 별도 1회 호출(분류 모델)로 상위 카드 후보 주제를 검색한다. 결과를 `{url, title, note}` 목록으로 받아 작성 입력에 "보충 자료"로 붙인다.
3. **근거 규칙 (코드 강제).**
   - 보충 검색으로 얻은 URL은 **응답의 `web_search_tool_result` 블록에 실제로 나온 URL일 때만** 인정한다. 비교 전에 정규화한다.
   - 카드 JSON에 선택 블록 `supplementRefs: [{url, title, note}]`를 추가한다(최대 3개).
   - 이 블록은 **필수 근거 조건(쓸 수 있는 기술 1개 이상 + 사람들의 요청·불편 또는 이미 나온 제품 1개 이상)을 채우지 못한다.** 검증 규칙도 그대로 둔다.
   - 검증에 실패한 보충 링크는 지우고 "보충 근거 링크 n건 제거"를 issues에 남긴다.
   - 메일·`HtmlRenderer`에는 "보충 자료(웹 검색)" 작은 칸으로 따로 표시한다. 수집 근거와 섞지 않는다.
4. **프롬프트.** `ideas.md` 본문은 고치지 않는다. 보충 자료와 `supplementRefs` 사용 규칙은 **코드가 사용자 메시지에 붙이는 지시**로 넣는다. 사용자 수정 프롬프트와 충돌하지 않게 하기 위해서다.
5. **비용.**
   - 웹 검색 요금(검색 1회당 가격)을 가격표에 둔다. 기본값은 공식 가격 기준으로 하고, 출처 확인이 안 되면 `priceUnverified`로 표시한다.
   - 사용 횟수는 응답 usage의 server tool 사용량으로 센다.
   - 예약은 `maxUses`회 검색 + 토큰 최대치로 잡는다.
   - 일일 예산이 부족하면 검색 없이 카드 작성을 진행하고 "예산 부족 · 보충 검색 생략"을 남긴다.
6. **실패.** 검색 도구 오류·거부·시간 초과는 카드 작성을 막지 않는다. 검색 없이 진행하고 issue를 남긴다.
7. **테스트.** 가짜 응답으로 확인할 것:
   - 검색 결과 URL을 인용한 `supplementRefs`는 유지된다.
   - 결과에 없는 URL은 제거된다.
   - 보충 근거만 있는 카드는 필수 근거 조건으로 탈락한다.
   - 검색 비용이 기록된다.
   - 예산 부족이면 생략된다.
   - 꺼져 있으면 도구를 붙이지 않는다.
   - 렌더 결과에 "보충 자료" 칸이 따로 보인다.
