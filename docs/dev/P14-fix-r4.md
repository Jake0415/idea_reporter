# P14 수정 지시 — 4회차(마지막) (Claude 통과·중간 1, OpenAI 높음 1·중간 3)

규칙은 같다(커밋·docs 수정·실제 실행·push 금지).

1. **[높음] 상태 훅과 게시 명령 전체에 시간 제한을 둔다.**
   - Kotlin은 훅과 게시 프로세스를 `waitFor(timeout)`으로 기다린다. 기본값은 훅 8분, 메일 게시 5분이다. 시간이 지나면 `destroyForcibly`로 끊고 실패로 처리한다.
   - 제출 전 훅이 시간 초과되면 → 제출하지 않고 동기로 넘어간다.
   - 제출 후 훅이 시간 초과되면 → issue를 남기고 계속한다.
   - `actions-data.sh` 안의 `fetch`·`rebase`·`push`·JVM 호출을 모두 `timeout`으로 감싼다.
   - 테스트: 멈추는 가짜 훅을 쓰면 제한 시간 안에 반환되고 제출이 0건이다.
2. **[중간, 둘 다 지적] dirty 작업 트리에서도 rebase가 된다.**
   - 상태 훅과 게시 루프에서 rebase는 `--autostash`로 한다.
   - `rebase --abort`는 실패해도 넘어간다(`|| true`). 이후 재구성 경로로 이어간다.
   - 처리한 inbox 파일 삭제는 상태 훅 커밋에 함께 넣어도 된다. 원격에서 새로 추가된 inbox는 보존한다.
   - 테스트: 실행 도중 원격에 inbox가 추가되면 훅이 성공한다(로컬 git 저장소 두 개로 흉내).
3. **[중간] 최종 게시는 항상 덧씌우기 방식으로 한다.**
   - 기본 미러링(로컬에 없으면 삭제)을 없앤다.
   - 삭제는 아래 세 가지만 허용한다.
     - 병합 트리에 보관 규칙을 적용한 결과
     - 이번 실행이 처리한 inbox 파일
     - `data-pull` 시점 스냅샷에 있었고 이번 실행이 **의도적으로 지운** 파일. 스냅샷 목록을 `data-pull`이 저장한다.
   - 그 외에 원격에만 있는 파일은 보존한다. 예: 중간 훅이 가져온 기록, 다른 실행의 기록.
   - 테스트: 중간 push 뒤 원격에 생긴 파일이 최종 게시에서 남는다.
4. **[중간] 결합 문자 이메일.** 정제 전에 문자열을 NFKC로 정규화한다. 정규식 문자 집합에 `\p{M}`을 더한다. 테스트: `é@bücher.example`(e + U+0301).
