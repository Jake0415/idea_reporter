# X1 수정 1회차 (OpenAI 코드 리뷰 + Claude 코드 리뷰 + Claude UX 리뷰 합의)

규칙은 X1-expand.md와 같다. 커밋하지 않는다. 끝나면 완료 기준의 Gradle 작업을 모두 통과시킨다.

## 코드

**1. [높음] 예전 카드와의 반복 판정이 너무 넓다** (CardRepetition)
- **문제:** 새 필드(`targetCustomer`·`coreTech`·`pain`)가 빈 예전 카드는 기술 주제 키 하나만 같아도 REPEAT가 된다. 업그레이드 직후 14일 동안 카드가 0~1장으로 줄 수 있다.
- **수정:**
  - 예전 카드는 "기술 주제 키 일치 **그리고** 제목 토큰 겹침 0.3 이상"일 때만 반복으로 본다.
  - 제목 겹침 0.6 이상 규칙은 그대로 둔다.

**2. [높음] 고객 이름만 같아도 반복이 된다** (CardRepetition)
- **수정:** 고객이 같을 때는 `pain` 또는 `coreTech`의 토큰 겹침이 0.3 이상인 경우를 함께 요구한다.
- 불용어에 `ai`, `도구`, `서비스`, `앱`, `플랫폼`, `자동`을 더한다.

**3. [높음] 요청 카드(F-41)가 돈을 쓴 뒤 REPEAT로 버려진다**
- **수정:** 요청 카드에서는 REPEAT를 탈락이 아니라 경고로만 처리한다.
  - caveat에 "최근 카드와 비슷함: <제목> (<날짜>)"를 붙인다.
- 매일 카드와 확장 카드는 지금처럼 버린다.

**4. [높음] 업데이트 전에 결제한 생성 Batch를 복구하면 전부 탈락한다**
- **원인:** 이전 스키마 응답에는 새 필드가 없어 MISSING_FIELD가 된다.
- **수정:** 저장된 생성 요청에 스키마 버전(또는 새 필드 포함 여부)을 기록한다. 이전 버전 요청의 응답에는 새 필드 필수 규칙과 확장 규칙을 적용하지 않는다.
- 이어받기 테스트를 추가한다.

**5. [중상] `kind` 값이 아무 값이나 들어오면 카드가 통째로 탈락한다**
- **수정:**
  - 스키마에서 `kind`를 `enum ["daily","expanded"]`로 제한한다.
  - 검증에서는 `seedId`가 없거나 `kind`가 "expanded"가 아니면 "daily"로 맞춘다.
- 사용자가 ideas 프롬프트를 고쳐 둔 경우를 대비한다. 새 필드 설명이 프롬프트에 없어도 동작해야 하므로, 새 필드와 확장 지시의 핵심은 코드가 사용자 메시지(입력 데이터 설명)에 붙인다.

**6. [중간] 확장 카드가 근거 있는 매일 카드를 밀어낸다**
- **원인:** 지금은 `sortedByDescending { kind == expanded }` 때문에 확장 카드를 먼저 검증한다.
- **수정:** 매일 카드를 먼저 검증한다. 확장 카드는 그다음 남은 자리에만 넣는다(`ideaCount` 안, 최대 `cardsPerDay`).
- 확장 카드가 매일 카드와 중복이면 확장 카드를 버린다.

**7. [중간] 확장 카드에 씨앗 밖 보충 자료가 남는다**
- **수정:** 확장 카드는 `supplementRefs`를 비운다.

**8. [중간] 확장만 켜져 있어도 근거가 부족한 날 유료 호출이 시작된다**
- **수정:** 확장 때문에 생성 전 조기 종료 조건이 바뀌지 않게 한다. 매일 카드 조건(기술 1개 이상 + 수요 또는 경쟁 1개 이상)을 못 채우는 날은 전처럼 생성을 건너뛴다.
- 가짜 공급자로 호출 횟수 테스트를 추가한다.

**9. [중간] 카드의 대상 고객과 씨앗이 어긋난다**
- **수정:** 확장 카드의 정규화한 `targetCustomer`가 씨앗의 고객과 같거나 포함 관계일 때만 통과시킨다. 아니면 새 탈락 이유 `SEED_MISMATCH`로 버린다.
- 일치한 씨앗만 씨앗 기록에 남긴다.

**10. [중간] 씨앗이 다양하지 않고, 반복 규칙과 맞물려 확장 카드가 계속 버려진다**
- **수정:**
  - 씨앗을 만들 때 최근 `recentCardDays` 카드의 (기술 주제, 고객) 조합을 미리 뺀다.
  - 기술과 고객을 번갈아(round-robin) 골라서 씨앗 3개가 서로 다른 기술 또는 고객이 되게 한다.
  - 렌즈 점수가 같을 때는 날짜를 기준으로 시작 렌즈를 돌린다.
  - 피드백 가중치는 "가중치 × 7일"로 안 쓴 일수와 합친다. 아래 한도는 유지한다.
- 씨앗 기록 파일은 `seedHistoryDays`보다 오래된 줄을 정리한다.

**11. [중간] 앱과 core가 대상 고객을 다르게 읽는다**
- **문제:** 앱 SC-09는 criteria의 `- 대상 고객: …`를 읽지만 core 씨앗 코드는 못 읽는다.
- **수정:** core에 파서 하나를 두고 앱과 core가 함께 쓴다.

**12. [중하] REPEAT가 하나만 섞여도 재시도가 막힌다**
- **수정:** 탈락 이유가 모두 REPEAT일 때만 재시도를 막는다.

**13. [중간] 요청 카드의 날짜 기준이 잘못됐다**
- **수정:** 반복 검사의 날짜는 파일명의 후보 날짜가 아니라 실제 만든 날(`report.startedAt`)로 판정한다. 요청 실행 자체의 검사 범위도 실행일을 기준으로 잡는다.

**14. [낮음] Expansion 설정값을 검증하지 않는다**
- **수정:**
  - `cardsPerDay`는 0..2, `seedCount`는 0..6, `seedHistoryDays`는 0 이상으로 제한한다. 범위를 벗어나면 설정 로더 검증에서 거부한다(백업 가져오기도 같은 검증).
  - `myFields`는 앞 5개만 쓰고 각 30자로 자른다.

**15. [낮음] 테스트를 보강한다**
- 렌즈 하나를 바꾼 저장이 대기열을 거친 뒤에도 다른 렌즈, `seedCount`, 기본값을 유지하는지
- 예전 형식 카드 JSON이 든 Room에서 보관함과 상세가 열리는지
- 확장 UI를 다크 모드와 글자 200%에서 명시적으로 검증하는지

## UX (이름 통일: 사용자에게는 "넓혀 본 아이디어", 코드 식별자는 그대로)

**1. [높음] 상세의 "AI 제안(추정)" 구역**
- 근거 구역(쓸 수 있는 기술, 사람들의 요청·불편, 이미 나온 제품, 원문) **뒤로** 옮긴다.
- surfaceVariant 바탕 상자로 감싼다. 경고 노랑은 쓰지 않는다.
- 제목 아래에 안내를 붙인다: "출처로 확인되지 않은, AI가 넓혀 본 추정입니다."
- 메일도 같은 순서와 문구를 쓰고, 제목은 `T.strong`으로 한다.

**2. [높음] 이름을 통일한다**
- 설정 구역 이름: "넓혀 본 아이디어"
- 스위치: "넓혀 본 아이디어 받기(하루 1장)"
- 칩: "AI가 넓힘 · <방법 이름>". 앱과 메일 모두 같게 한다.

**3. [중간] "렌즈"라는 말을 화면에서 없앤다**
- 스위치 목록 위 소제목을 "넓히는 방법"으로 한다.
- 모두 끔 안내: "넓히는 방법이 모두 꺼져 있어 넓혀 본 아이디어를 만들지 않습니다". 정보 배너 톤(파랑 계열)으로 보여 준다.

**4. [중간] 구역 설명을 추가한다**
"하루 카드 중 1장을 AI가 오늘 자료에서 다른 고객·시장으로 넓혀 봅니다. 근거가 없는 부분은 'AI 제안(추정)'으로 따로 표시합니다."

**5. [중간] 큰 스위치를 끄면**
- 방법 스위치 6개를 비활성(interactive=false)으로 바꾼다.
- 안내는 "꺼져 있어 매일 카드만 받습니다"로 바꾼다.

**6. [중간] "내 분야·경험" 칸**
- "넓혀 본 아이디어" 구역 안, 큰 스위치 아래로 옮긴다.
- 도움말: "넓혀 볼 때 대상 고객으로 먼저 씁니다. 한 줄에 하나씩, 최대 5개. 예) 회계, 초등 교육, 부동산 중개"
- 오류: "5개까지, 한 줄에 30자까지 쓸 수 있습니다"

**7. [중간] 글자 200% 캡처를 추가한다**
- `out/screens/X1/font200`에 today, detail, criteria 화면을 찍는다.
- 칩(Tag)에 `maxLines = 1`과 `overflow = Ellipsis`를 준다.

**8. [낮음] 칩 순서와 모양**
- 순서는 앱과 메일 모두 분류 → AI가 넓힘 → 파란 배지로 맞춘다.
- "AI가 넓힘" 칩은 바탕 없는 테두리형(회색 테두리 + 본문 회색 글자)으로 한다.
  - MailTheme에 `Tone.OUTLINE`을 추가한다.
  - 앱 Tag에도 같은 변형을 둔다.
  - MailTheme 토큰 대조 테스트를 갱신한다.

**9. [낮음] 메일 "넓혀 본 아이디어" 구역**
- 구역 제목 아래에 안내를 붙인다: "오늘 자료에서 출발해 AI가 다른 고객·시장으로 넓혀 본 아이디어입니다. 추정이 섞여 있습니다." 텍스트 본문에도 같은 문구를 넣는다.
- core caveat 문구는 "사람들의 요청·불편 자료 없음 — AI 추정"으로 바꾼다.

**10. [낮음] 방법 이름**
- "B2C↔B2B 바꾸기"를 "개인용 ↔ 기업용 바꾸기"로 바꾼다.
- 설명: "개인용 서비스를 팀·기업용으로, 또는 그 반대로"

**11. [참고] 분류 칩**
- 오늘 화면과 상세의 분류 칩에 원래 id(예: dev-tools)가 보인다. 메일처럼 분류 이름(categories.json의 name)으로 보여 준다.
