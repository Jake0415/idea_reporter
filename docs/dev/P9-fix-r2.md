# P9 S3 수정 지시 — 2회차 (Claude 통과·낮음 4, OpenAI 높음 1·중간 4·낮음 2)

규칙 동일(커밋·docs 수정·키 출력 금지, 실제 LLM 호출 금지).

## 높음
1. **일회성 상한 초과 정산 후 차단 우회** (OpenAI) — 정산 초과 차단의 기준을 "그 실행에 적용된 상한"(일회성 `--budget`이면 그 값)으로 기록하고, 해제 조건은 **사용자가 설정의 요청 상한 또는 분석 월 상한을 바꿨을 때**(설정 파일 수정 시각/값 변경 감지) 또는 다음 달로 한다. 기본 상한이 정산액보다 크다는 이유만으로 자동 해제하지 않는다. `--budget-status`에 차단 상태·사유·해제 방법 표시(Claude 낮음). 테스트: `--budget 0.40` 실행이 0.60으로 정산 → 다음 요청 차단 → `--set-budget`으로 상한 변경 후 해제.

## 중간
2. **전부 INVALID인 결과 재사용** (OpenAI) — 재사용 조건에 "INVALID가 아닌 기회 분야 ≥ 1" 추가. 테스트.
3. **효과 없는 맞춤안** (OpenAI) — 맞춤안 목록은 **예약액이 직전 단계보다 실제로 줄어드는 것만** 남긴다(같으면 생략). 재사용 키는 단계 번호가 아니라 **실제 구성 값**(테마 목록, 테마별 실제 근거 수, 추론 강도, maxOutputTokens)으로. 테스트(근거 6건 이하 테마).
4. **리포트 근거 URL 불일치로 누락** (OpenAI) — 상세 조회는 itemId로 먼저 찾고(URL 다르면 리포트 URL을 그대로 쓰고 경고 집계), 못 찾으면 리포트의 제목·URL·프로필·점수만으로 근거를 만든다(본문·댓글 없음 표시). 인용 검증 키는 리포트 URL. 테스트.
5. **문자 상한 초과 시 맞춤안 평가 불가** (OpenAI) — 기본 구성이 문자 상한에 걸려도 예외로 끝내지 말고 그 구성을 "입력 상한 초과"로 표시한 뒤 맞춤안(테마 축소 포함)을 계속 평가. 모든 구성이 걸리면 C처럼 안내. 테스트.

## 낮음
6. 예산 설정 파일을 읽을 수 없으면(IOException, 디렉터리) 오류 메시지 + 기본값으로 계속. 테스트.
7. 재사용 키에 프롬프트 버전(`analysis-opportunity`·`criteria`의 version/해시) 포함(Claude). 테스트.
8. `config/analysis.local.json`의 `requestBudgetUsd`·`monthlyBudgetUsd`는 무시하고, 있으면 "budget.json 사용" 경고 한 번(Claude).
9. 맞춤 단계에서 줄이는 `maxOutputTokens`에 하한 16000(설정값) 적용(Claude).
10. CLI 연결 테스트(OpenAI 낮음): Main 경로에서 budget.json의 전체 월 상한 초과 → 일일 실행 결과 파일에 생략 사유 저장, 미설정 → 유료 단계 실행(가짜 공급자).
