# R2 수정 지시 — 4회차 (OpenAI 높음 2·중간 2·낮음 1, Claude 높음 1·중간 2·낮음 1)

규칙은 R2와 같다.
- 커밋하지 않는다. `docs/`를 고치지 않는다(이 파일 제외).
- 실제 LLM·메일·수집 호출을 하지 않는다.
- 계측 테스트는 emulator-5554에서만 한다.
- PC·Actions 동작은 HEAD와 같게 유지한다.
- **단, `daily.yml`의 cron 제거는 의도된 결정이므로 되돌리지 않는다**(`WorkflowTest`도 cron 없음 기대).

원칙: 이중 과금·중복 메일이 없어야 하고, 이미 낸 비용의 결과를 버리거나 0장 보고서로 그날을 끝내면 안 된다.

## 높음
1. **이어받기가 다음 단계 비용 예약까지 막는다.** (OpenAI 1, Claude 높음)
   - 이어받기(`resumeBatch`)에서 막는 범위를 좁힌다. 막을 것은 "이미 정산된 단계의 결과를 다시 사는 것"과 "그 날짜에 이미 게시된 결과의 재게시"뿐이다.
   - 이미 정산된 단계(classify·generate의 저장 결과)는 재사용한다.
   - 그다음 단계(generate·track 등)의 새 예약은 허용한다. 비용 상한은 그 날짜 원장과 기존 `CostGuard` 규칙으로 지킨다.
   - 테스트: 분류 Batch만 제출하고 미룬 뒤 이어받는 경우, 카드가 1장 이상 선택되면 작성 단계가 돌고 카드가 게시돼야 한다. 어제 결과를 이어받는 경우도 같은 테스트를 둔다.
2. **입력이 바뀌면 이미 과금된 생성 결과를 버린다.** (OpenAI 2)
   - 생성 Batch를 제출할 때 생성 요청의 입력 스냅샷을 체크포인트 옆에 저장한다. 입력에는 피드백·추적 등 요청 지문에 들어가는 값이 포함된다.
   - 이어받기는 그 스냅샷으로 같은 요청을 다시 만든다. 그래서 그사이 ★·피드백이 바뀌어도 지문이 일치해 저장된 응답을 쓴다.
   - 바뀐 피드백은 다음 날 실행부터 반영된다.
   - 테스트: 결과를 받은 뒤 ★를 누르고 이어받기 → 추가 LLM 호출 0회, 카드 게시 1회.

## 중간
3. **"Batch 결과를 게시하지 못했습니다" 알림이 잘못 뜨고 반복된다.** (Claude 중간-1, OpenAI 낮음)
   - 우선 해결: 오늘 실행이 다른 날짜 결과를 정산하면 그 날짜의 이어받기를 다시 예약한다. 이미 대기 중이면 그대로 둔다(KEEP).
   - 알림은 다음을 모두 만족할 때만 띄운다.
     - 그 날짜 실행이 끝나지 않았다(게시·실패·보관 기록 없음).
     - 그 날짜 이어받기 작업이 남아 있지 않다.
     - 아직 알리지 않은 날짜다(날짜별 1회).
   - 그 날짜 보고서가 나중에 게시되면 해당 알림을 지운다(같은 알림 ID로 취소).
4. **실행 중 설정 화면에서 저장하면 예비 워커가 취소된다.** (OpenAI 중간 1, Claude 중간-2)
   - `RunScheduler.save()`는 실행 중(`running` 또는 core 잠금 사용 중)이면 즉시 `register(update = true)`를 하지 않는다. "예약 갱신 대기"를 표시해 두고 `finishRun`에서 재등록한다.
   - 알람 시각만 바뀌는 등 periodic 작업을 교체할 필요가 없는 경우에는 UPDATE를 쓴다.
   - 테스트: 예비 워커 실행 중에 설정을 저장해도 실행이 끝까지 가고, 끝난 뒤 새 예약이 잡히는지 확인한다.
5. **이전 날짜 메일의 재시도 실패가 가려진다.** (OpenAI 중간 2)
   - 실행 결과의 메일 상태에 그날 실행에서 처리한 이전 날짜 재시도 결과도 포함한다. 예: "이전 메일 1건 실패".
   - 재시도 기간이 끝나 더 이상 보내지 않게 되는 메일이 생기면 실패 알림을 한 번 띄운다.

## 낮음
6. 사용자가 취소한 날(`cancelled(date)`)에는 예비 워커가 알림 없이 종료한다. 실패 알림을 띄우지 않는다. (Claude 낮음)
