# P13 수정 지시 — 4회차(마지막) (Claude 통과·낮음 3, OpenAI 중간 3·낮음 1)

규칙 동일(커밋·docs 수정·실제 호출 금지).

1. **[중간] 누락 재조회가 시간 초과되면 불완전 결과를 확정하지 않는다.**
   - `recheckMissing`이 복구 상한·마감으로 끝나면 결과 파일을 "미완료"로 저장하고 체크포인트를 유지한다.
   - 같은 날 분류는 그 Batch를 대기로 취급한다(동기 재호출 금지).
   - 누락 확정(추정 정산 → 동기)은 재조회가 **정상 완료된 뒤에도** ID가 없을 때만 한다.
   - 테스트: 재조회 시간 초과 → 동기 0건, 다음 실행에서 재조회.
2. **[중간] 정산 장애에도 끝이 있게 한다.**
   - `settleRetry`에 처음 실패한 시각(`firstSettleFailureAt`)을 저장하고, 매 실행 7일 경과를 검사한다. 7일이 지나면 `.unsettled.json`을 남기고 격리한다.
   - 깨진 체크포인트는 파일 옆 `<name>.retry.json`에 첫 실패 시각을 저장해 7일 계산을 유지한다.
   - 정산 대기 중인 같은 날짜 Batch는 결과가 이미 저장돼 있으면 **결과는 사용**하고 정산만 다음으로 미룬다. 단계 완료는 막지 않는다.
3. **[중간] Backfill 색인 손상**
   - 색인 파싱 실패는 결과 파일 손상과 구분한다. 색인을 `index.json.corrupt-<시각>`으로 옮기고, `out/batch/*.results.jsonl`과 체크포인트에서 색인을 다시 만든다.
   - 정상 결과·체크포인트를 격리하지 않는다.
   - 테스트: 깨진 색인 → 재생성, 결과 적용.
4. **[낮음] 401 타이머 초기화.** 조회가 한 번이라도 성공하면 `firstMissingKeyAt`을 즉시 지운다.
5. **[낮음, Claude] 지난 날짜 정산 완료 결과의 정리.** 재사용 기간(`recentTopicDays`)이 지나면 `.done`으로 표시해 7일 정리 대상에 넣는다. 복구 때 이미 정산된 결과 파일은 다시 읽지 않는다.
