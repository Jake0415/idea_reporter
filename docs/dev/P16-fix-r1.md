# P16 수정 지시 — 1회차

- 코드 리뷰: OpenAI 높음 2·중간 6·낮음 2, Claude 높음 2·중간 5·낮음 4
- UX 리뷰(Design 플러그인): 높음 5·중간 6·낮음 4

규칙은 P16과 같다. 커밋·docs 수정·실제 GitHub 호출·push 금지, 계측 테스트·캡처는 emulator-5554에서만 한다.

## 사용자 결정 (2026-11-24)
- **A. SC-00은 단계형 마법사로 한다.** 하단 탭 없이 1 연결 → 2 알림 허용 → 3 첫 동기화 순서다. 토큰 칸은 ●●●로 가리고 붙여넣기를 지원한다. 첫 실행 때 한 번만 보인다. 이후 설정 > 저장소에서는 같은 단계를 다시 열 수 있다.
- **B. 연결 전에는 빈 화면과 연결 안내만 보인다.** 샘플 데이터는 보여 주지 않는다. 안내 문구는 "저장소를 연결하면 매일 아침 카드가 여기 나옵니다 · 연결하기"로 한다.
- **C. '지금 실행'은 SC-01 상단 바 오른쪽의 ↻ 아이콘으로 둔다.** 크기는 48dp이고 라벨은 "지금 실행"이다. 누르면 확인 창을 띄운다. 실행 중이면 진행 표시를 한다.
- **D. '개발 화면'은 디버그 빌드에서만 보인다.** 릴리스에서는 진입점 자체가 없어야 한다.

## 높음
1. **화면 위치와 입력 보존** (둘 다 지적)
   - 내비게이션 스택을 `rememberSaveable`(Saver)이나 Navigation Compose의 저장 가능한 백스택으로 바꾼다.
   - 아래 입력도 회전·프로세스 복원 뒤에 남아야 한다.
     - 관심 없음 메모
     - 추적 키워드 편집
     - 보관함 검색어
     - 운영 설정 입력
     - 프롬프트 초안
   - 키워드 입력은 동기화가 돌아도 편집 중인 내용을 덮어쓰지 않게 한다. 편집 시작 시점의 값을 따로 둔다.
   - 딥 링크가 들어와도 저장하지 않은 프롬프트가 있으면 먼저 확인 창을 띄운다.
2. **연속 요청의 순서를 보장한다.** (Claude) 한 동작이 여러 inbox 요청을 만들 때(조용한 추적 교체: stop → start → reaction) `createdAt`을 1ms씩 늘린다. 파일명 시각은 항상 밀리초 3자리로 고정한 형식을 쓴다. `Instant.toString()`은 소수가 없을 때 생략되어 정렬 경계 문제가 생기므로 쓰지 않는다. (Claude 낮음 10)
3. **설정 읽기 크래시** (OpenAI·Claude)
   - 동기화할 때 settings 파일을 타입까지 검증한다. 실패한 파일은 격리한다.
   - 화면 디코드는 `runCatching`으로 감싸고, 실패하면 "설정 읽기 오류"를 띄운다.
   - About의 asset 열기도 같은 방식으로 처리한다.
4. **'지금 실행' 중복 방지**
   - dispatch 직전에 `dailyDispatchingAt`을 Room에 먼저 기록한다. P15 분석 dispatch와 같은 패턴이다.
   - 응답이 유실되면 바로 다시 보내지 않는다. 실행 목록 조회로 판단하고, 보이지 않으면 10분 동안 재요청을 막는다.
   - 실행 중 상태는 Room에 둔다. 회전해도 유지돼야 한다.
   - 기기 간 중복은 workflow concurrency로 직렬화된다는 점을 주석으로 남긴다. 중복 실행이 생겨도 core 규칙(같은 날 결과 교체, 메일 하루 1회)으로 안전하다.
5. **비활성 버튼에는 이유와 할 일을 함께 보여 준다.** (UX) 대상은 지금 실행·연결 확인·동기화·저장이다. 버튼 아래 한 줄로 이유와 바로가기를 둔다. 예: "저장소를 연결하면 실행할 수 있습니다 · 연결하기", "토큰을 등록하면 실행할 수 있습니다 · 토큰 등록".
6. **SC-01 실패 안내** (UX·Claude) warning 토큰을 쓴 띠로 바꾼다. 문구는 "Reddit 수집 실패 · 나머지 출처로 만들었습니다 ›"이고, 누르면 SC-10a로 간다.
7. **SC-02 근거 줄** (모두 지적)
   - 제목은 근거 요약 또는 원문 제목으로 한다. 아래에 출처 이름과 수집 시각을 둔다.
   - "원문 열기 ↗"는 따로 행동 링크로 둔다.
   - ★는 상단 바에 둔다(명세).
   - "카드 상세"와 카드 제목이 겹치는 머리를 정리한다. 상단 바에는 ←만 두고, 큰 제목은 카드 제목 하나만 남긴다.
   - 본문은 bodyMedium으로 해서 소제목보다 작게 한다.

## 중간
8. **상태를 구분해서 보여 준다.** (모두 지적)
   - 동기화 상태
     - `APP_UPDATE_REQUIRED` → "앱 업데이트 필요"
     - `NEEDS_AUTH` → 경고 띠와 "토큰 등록" 바로가기
     - 실패 → "동기화 실패 · 다시 시도"
     - 첫 동기화 실패 상태에서는 "오늘 결과 없음"과 함께 나오지 않게 한다.
   - 요청 상태 칩은 문자열 매칭이 아니라 **상태 enum**으로 판단한다. 칩: 대기 중 / 보냄 / 반영됨 / 거부(사유) / 실패 / 확인 필요 / 앱 업데이트 필요.
   - [다시 요청]은 실패·확인 필요·internal_error일 때 보인다. 거부(baseHash 불일치)일 때는 "최신 내용으로 다시 편집"을 보인다.
   - Batch 대기 띠는 **오늘 날짜의 미결 분류 체크포인트**가 있을 때만 보인다. 문구는 "분류 대기 중(묶음 처리)"로 한다.
9. **★ 부분 실패 처리** (OpenAI)
   - ★ 표시는 서버 추적 행이 생긴 것, 또는 이번 track.start 요청이 대기·반영된 것을 기준으로 한다.
   - track.start가 거부되면 피드백만 남아 있어도 ★를 끄고 사유를 보여 준다.
   - 새 추적은 SC-01 요약과 SC-13 목록에도 낙관적으로 보인다("추적 시작 중").
   - 관심 없음을 누른 카드는 바로 숨기지 않는다. "관심 없음 · 되돌리기" 상태로 접어 두고, 요청 칩이 보이게 한다. 보관함 기본 필터로 숨기는 것은 반영된 뒤에 한다.
10. **SC-00 확인값과 저장값을 맞춘다.** (OpenAI)
    - 연결을 확인하는 동안에는 입력을 잠근다. 응답이 왔을 때 요청에 쓴 값과 현재 입력이 다르면 확인을 무효로 한다.
    - 저장 순서: 새 토큰 저장 성공 → 설정 저장 → 이전 토큰 삭제. 기존 토큰을 먼저 지우지 않는다.
    - 첫 동기화는 결과가 나올 때까지 마법사 3단계에 머문다. 성공하면 오늘 탭으로 가고, 실패하면 사유와 다시 시도 버튼을 보인다.
11. **SC-16 저장 경계** (OpenAI)
    - 이력 복원에도 20,000자 검사를 한다. 저장 버튼은 길이 초과·빈 내용이면 비활성화하고 이유를 보인다.
    - 저장은 Room 등록이 성공한 뒤에 편집을 끝낸다. 실패하면 초안을 유지하고 오류를 보인다.
    - 거부(baseHash 충돌)가 나면 최신 본문을 기준으로 다시 편집하는 흐름을 둔다. 내 초안과 비교할 수 있어야 한다.
    - 비교는 줄 단위 diff로 한다. 순서와 중복을 반영한다. 집합 비교를 쓰지 않는다.
    - 편집기에 보이는 내부 주석(design.md 참조 등 `<!-- -->`나 개발 메모)은 접어서 숨긴다. (UX 11)
12. **성능** (Claude) 요청 payload JSON은 ViewModel에서 한 번만 풀어 상태로 둔다. 컴포지션 안에서 반복해 디코드하지 않는다.
13. **UX 정리**
    - 선택된 칩 색에 highlight 토큰(#E5F1FE / 다크 #0058B0)을 쓴다. Material 기본 보라가 나오지 않게 `secondaryContainer`를 토큰에 연결한다. `Tag`·`Notice`의 하드코딩 색도 토큰으로 바꾼다.
    - SC-01·SC-13의 상자 안 상자(이중 테두리)를 없애고 요약 줄은 구분선으로 나눈다. 추적 줄의 증감 표시는 세로 가운데 정렬하고, success/error 색을 쓰되 글자는 남긴다.
    - SC-13·14의 메타 정보는 한두 줄로 줄인다(예: "업무 자동화 · ↑ 늘어남 · 관련 글 7건 · 10/18부터"). 관련 글 수는 정수로 보인다.
    - SC-14 7일 추이: 같은 기준선에 막대를 놓고 날짜 라벨을 단다. 0건인 날은 "0"으로 보인다.
    - SC-06: 한 묶음 목록(구분선 + ›)으로 바꾼다. 연결 상태는 "연결 안 됨 · 연결하기"처럼 보인다.
    - 모든 '뒤로' 글자 버튼을 ← 아이콘(48dp, 라벨 "뒤로")으로 바꾸고 상단 바 왼쪽에 둔다. SC-16 순서도 맞춘다.
14. **릴리스 lint 우회 없애기** (OpenAI)
    - `-Pandroid.lint.useK2Uast=false` 없이 기본 설정으로 `assembleRelease`와 `lintVitalRelease`가 통과해야 한다.
    - K2 lint 내부 오류(`No fir element was found for KtParameter`)를 일으키는 코드 구조를 찾아 바꾼다. 안 되면 AGP 패치 버전을 올린다.
    - 우회가 꼭 필요하면 이유와 제거 조건을 `gradle.properties` 주석으로 남기고 보고한다.
