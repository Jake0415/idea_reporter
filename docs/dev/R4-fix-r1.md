# R4 수정 지시 1회차

근거: R4 1회차 리뷰 세 개(OpenAI 코드, Claude 코드, UX). 규칙은 [R4-finish.md](R4-finish.md) §0과 같다.
- 커밋하지 않는다. docs는 고치지 않는다.
- 실제 호출을 하지 않는다.
- daily.yml의 cron을 되살리지 않는다.
- emulator-5554에서만 테스트하고, 서명이 충돌하면 에뮬레이터에서만 앱을 지운다.
- 비밀값과 주소를 기록하지 않는다.
- Gradle을 돌릴 때는 JAVA_HOME을 직접 지정한다.

## 높음
1. **비용 기록은 되돌리지 않는다(예산 우회 방지)**
   - 아래 항목은 가져오기로 덮어쓰거나 지우지 않는다.
     - 비용 원장(`cost-ledger/*`, 분석 원장)
     - `.blocked` 표식, 예약(reservation)
     - Batch 체크포인트, `runs/scheduled/*`
     - 오늘 일일 결과(`out/<오늘>.json`), 메일 상태(`mail/*`)
   - 백업에 든 원장은 현재 원장과 **병합**한다. 같은 키는 큰 값을 취하고, 현재 기록은 절대 줄이지 않는다.
   - 위 항목은 "백업에 없으면 삭제" 대상에서도 뺀다.
   - 테스트: 06:00 백업 → 07:00에 비용 사용 → 백업 가져오기 → 오늘·이번 달 사용액과 차단 표식이 그대로인지 확인.
2. **민감값이 백업에 들어가지 않게**
   - 내보내기는 허용 목록 스키마로 필드를 고른다. 키·토큰·비밀번호·주소 관련 필드명(mail, smtp, address, token, secret, password, key 등)은 값과 상관없이 뺀다.
   - 자유 텍스트는 퍼센트 디코딩 같은 정규화를 한 뒤 메일 주소를 검사한다. 가린 주소 형태(`j***@g***.com`)도 잡는다.
   - 키 문자열 치환은 8자 이상 값에만 한다. 그보다 짧은 값은 해당 필드를 통째로 뺀다.
   - 민감값이 없다고 보장할 수 없는 필드는 내보내지 않는다.
   - 테스트를 넣는다.
3. **가져오기 원자성과 복구**
   - 반영을 시작하기 전에 복구 저널(임시 백업 폴더 경로와 진행 상태)을 디스크에 쓴다.
   - 앱이 시작될 때 실행이나 Room 동기화보다 먼저 미완료 저널을 찾아 임시 백업으로 복원하고, 임시 폴더를 정리한다.
   - 가져오기 작업은 앱 범위(`appScope`)에서 돌려, 화면을 나가거나 회전해도 취소되지 않게 한다. 결과는 화면 상태로 전달한다.
   - 남은 `.backup-*` 폴더를 정리하는 경로를 만든다.
4. **실기기 경로:** 경로를 비교할 때 양쪽 모두 `canonicalFile`을 쓴다(`/data/user/0`와 `/data/data` 링크). 기기 테스트에 실제 가져오기 왕복(restore)을 추가한다.

## 중간
5. **설정 검증:** 미리보기 전에 `config/*.local.json`을 실제 설정 로더(ConfigLoader/PipelineConfig)와 같은 방식으로 검증한다. 실패하면 거부한다.
6. **Room 한도:** 가져오기와 Room 동기화가 같은 파일 크기 한도를 쓴다. 복원한 파일의 동기화가 PARTIAL이면 가져오기 실패로 처리한다(롤백).
7. **알람 재등록 실패:** 재등록이 실패하거나 보류되면 "가져왔지만 예약을 다시 걸지 못했습니다 · 운영 설정에서 저장을 한 번 눌러 주세요"를 보여 준다.
8. **메모리**
   - 가져오기는 크기 제한 스트림으로 임시 파일에 받은 뒤 스트리밍(`decodeFromStream`)으로 읽는다.
   - 미리보기 상태에는 요약(건수·기간)만 둔다. 확인을 누르면 임시 파일을 다시 읽는다.
   - 내보내기도 항목별로 스트리밍해 쓴다.
   - 크기 상한을 넘으면 따로 안내한다: "백업이 20MB를 넘습니다. 오래된 기록을 줄인 뒤 다시 시도하세요".

## UX (strings.xml)
9. **`backup_preview_details`:** `카드 %1$d개 · 추적 %2$d개\n기간 %3$s\n\n지금 이 폰에 있는 카드·추적·피드백·실행 기록·설정·프롬프트·내 기준이 이 파일 내용으로 바뀝니다(비용 기록은 그대로 둡니다). 되돌릴 수 없으니 필요하면 먼저 [내보내기]로 저장하세요.`
   - 확인 버튼: `backup_import_confirm` = `바꾸기`
10. **`backup_busy`:** `실행 중에는 백업을 내보내거나 가져올 수 없습니다. 실행이 끝나면 다시 눌러 주세요.` 경고 노랑을 쓰지 않는다(`warning = false`).
11. **`backup_invalid`:** `이 파일은 불러올 수 없습니다. 이 앱에서 [내보내기]로 만든 백업 파일(20MB 이하)을 골라 주세요.`
12. **`backup_help`:** `카드·추적·피드백·실행 기록·설정·프롬프트·내 기준을 파일 하나로 저장합니다. AI 키·앱 비밀번호·메일 주소는 들어가지 않으니, 새 폰에서는 가져온 뒤 다시 입력하세요.`
13. **결과 문구**
    - `backup_import_error`: `가져오지 못했습니다. 지금 데이터는 그대로입니다. 잠시 뒤 다시 시도하세요.`
    - `backup_export_error`: `백업 파일을 저장하지 못했습니다. 다른 저장 위치를 골라 다시 시도하세요.`
    - `backup_imported`: `백업을 가져왔습니다. 이 폰에 AI 키나 메일 설정이 없으면 [AI 키]·[메일]에서 다시 입력하세요.`
    - `backup_exported`: `백업 파일을 저장했습니다. 새 폰에서는 이 파일을 [가져오기]로 불러오세요.`
14. **버튼 위계:** [가져오기]는 Secondary(테두리) 버튼으로 둔다. [내보내기]만 채운 버튼이다.
15. **목록 아래 여백:** 맨 아래 안내가 하단 탭에 가리지 않게 여백을 둔다.
16. **파일 이름:** `idea-collector-backup-YYYY-MM-DD.json`
17. **접근성:** 결과 안내에 `liveRegion = Polite`를 단다.
