# P7 S1 수정 지시 — 1회차 (Claude·OpenAI 리뷰 + 실제 출력 확인)

리뷰: Claude "수정 필요"(높음 1·중간 3), OpenAI "수정 필요"(높음 1·중간 4). 실제 출력 `out/trend/2026-11-20.*`(2일치)에서 테마 묶기 실패 확인.
규칙 동일(커밋·docs·프롬프트 수정·키 출력 금지, LLM·네트워크 금지).

## 높음
1. **테마 연쇄 묶임** (ThemeMapper) — 실제 출력: "MiniMax H3 Image 모델"에 주제 31개(음성 분리·얼굴 교체·3D·GGUF 등), "AI 에이전트 봇 우회 테스트"에 GitHub 저장소 거의 전부.
   - (a) 흔한 태그 자동 제외: 이번 입력 전체 주제 중 **5% 이상**(최소 3개 주제)에 나오는 태그는 묶기에 쓰지 않는다(문서 빈도). 고정 제외 목록도 확장: HF 메타(`transformers`, `safetensors`, `gguf`, `diffusers`, `gradio`, `pytorch`, `text-generation`, `endpoints_compatible`, `region:*`, `license:*`, `base_model:*`, `arxiv:*` 등 콜론 포함 태그 전부), 범용(`ai`, `llm`, `mcp`, `agent`, `agents`, `ai-agent(s)`, `open-source`, `python`, `typescript`, `machine-learning`, `deep-learning`, `generative-ai`, `chatgpt`, `claude`, `openai`, `gemini`).
   - (b) 태그만으로 묶을 때는 남은 태그 **2개 이상 공유 + 주제명 단어 Jaccard ≥ 0.2**가 함께 맞아야 한다. 주제명 Jaccard ≥ 0.5는 단독으로 묶는다(기존).
   - (c) 연쇄 방지: union-find 대신 **대표 기준 묶기** — 주제를 결정적 순서로 보며, 기존 테마의 **대표 주제와 직접** 위 조건을 만족할 때만 들어간다. 테마 크기 상한 `maxThemeTopics`(기본 8).
   - (d) `themes.json`에 `version` 필드(이번 2). 버전이 다르거나 없으면 기존 매핑을 버리고 다시 만든다(이미 잘못 저장된 파일 자동 정리). overrides는 버전과 무관하게 유지.
   - 회귀 테스트: 흔한 태그(`mcp`,`agent`,`python`)만 공유하는 무관한 주제 5개가 서로 다른 테마; A–B, B–C만 유사하고 A–C는 유사하지 않으면 A와 C가 같은 테마가 아님; 크기 상한; version 1 파일은 재생성되고 overrides는 유지.
2. **카드 보존 재실행에서 그날 탈락·항목·카드 누락** (TrendInput) — state 파일은 `classified`(·topics)만 신뢰하고, `dropped`·`items`·`cards`가 비어 있으면 **같은 날 본 파일 또는 `out/runs/` 보관본 중 가장 최신 실행**의 값으로 채운다(`startedAt` 달라도). 테스트: startedAt이 다른 state + 본 파일 + runs 보관본 조합.

## 중간
3. **무관 항목 집계** — `profile == "none"` 행은 관측에서 제외, 재등장 원본이 `none`이면 제외. 추적 전용 항목(`trackingOnlyKeys` 등 일반 수집이 아닌 것)도 제외. 테스트.
4. **부분 데이터 주의 증가율 부풀림** — 앞 3주 평균은 **실행 파일이 1개 이상 있는 주만**으로, 주마다 실행 일수가 다르면 **일평균**(주 건수 ÷ 그 주 실행 일수)으로 정규화해 비교한다. 앞 3주 중 데이터 있는 주가 없으면 증가율 null(데이터 부족). "신규"는 데이터 있는 앞 주들에 0건일 때만. `insufficientData` 판정 = 데이터 있는 날 14일 미만 **또는** 앞 3주 중 데이터 있는 주 2개 미만. 시장 급증 판정도 같은 기준. 테스트(15일치 데이터에서 거짓 ◆가 안 나옴).
5. **같은 항목 두 테마 중복** — 한 주 안에서 itemKey는 **한 테마에만** 센다: 이번 분류가 있으면 그 분류의 테마, 없으면 재등장 원본 테마. 테스트.
6. **미매핑 GitHub 재등장도 OSS 순위·분포에 포함** — OSS 목록 입력은 테마 매핑과 무관하게 이번 주 GitHub 신규+재등장 전체(테마 칸은 없으면 "—"). 기존 테스트 기대값 수정.
7. **제목 ◆ 수와 본문 불일치** — 본문 뜨는 테마 표에 **◆ 후보는 이번 주 건수와 무관하게 모두 포함**(◆ 먼저, 그다음 기존 순). 제목 ◆ 수 = 본문 ◆ 표시 수. 테스트.
8. **저장 도중 실패 시 결과 섞임** — json·html·txt·themes를 모두 메모리에서 만든 뒤 임시 파일에 쓰고, 전부 성공하면 차례로 교체(기존 `publishRun`의 묶음 저장 방식 재사용 가능). 렌더링·직렬화 실패 시 아무 파일도 바꾸지 않음. 테스트(렌더러 예외 주입).

## 낮음·표시 (실제 출력에서)
9. **과열 묶음 중복** — 이름 기준·설명 기준 묶음이 같은 저장소 집합을 따로 세서 `ai--manus 34`·`manus--ai 34`가 둘 다 나옴. 이름 또는 설명이 같으면 **한 묶음(union)**으로 합치고, 묶음 이름은 가장 흔한 저장소 이름. 테스트.
10. **스팸 의심 저장소 표시** — OSS 표에서 포크/스타 < 0.005 **이고** 스타 ≥ 500이면 `의심` 표시(순위에는 남김). 하루 스타 증가는 정수로 반올림 표시(JSON은 소수 유지 가능).
11. **텍스트·HTML 표시 정리** — 저장소 설명 80자 자르기(…), 지는 테마 없으면 표 대신 "해당 없음", 데이터 부족일 때 제목은 `— 테마 n · 데이터 부족`(뜨는/◆ 대신), 주 표기는 **ISO 주(월요일 시작) 기준 "M월 N주"**로 정의하고 렌더러 주석에 계산 규칙을 적는다.
12. **테스트 보강** — 시장 과열 경계(2건·3배 이상 → 아님, 3건·3배 미만 → 아님), themes.json 파일을 실제로 쓰고 다음 실행에서 읽어 매핑 유지하는 경로.
