# X1 수정 2회차 (OpenAI 코드 리뷰 + Claude 코드 리뷰 + Claude UX 리뷰 합의)

규칙은 X1-expand.md와 같다. 커밋하지 않는다. 끝나면 완료 기준의 Gradle 작업을 모두 통과시킨다.

## 코드

**1. [높음] 생성 전 조기 종료 조건이 예전보다 엄격해졌다** (IdeaGenerator:53, 두 리뷰가 같이 지적)
- **문제:** 지금 조건은 demand-signal이나 market-signal을 꼭 요구한다. 그래서 "기술 + 같은 일을 하는 오픈소스(tech-signal) 경쟁 제품" 조합이 생성 전에 막힌다.
- **수정:**
  - 조건을 예전처럼 "기술 1건 이상 + 근거 2건 이상"으로 되돌린다. 경쟁 제품으로 쓸 수 있는 tech-signal도 근거로 센다.
  - 확장 씨앗은 이 판단에 관여하지 않게 둔다.
  - 두 항목이 모두 tech-signal인 기존 테스트 입력을 되살린다.
  - 요청 카드(F-41)는 견적 단계에서 같은 조건을 검사해 미리 막는다. 웹 조사 비용을 쓰기 전에 막아야 한다.

**2. [높음] 구버전 생성 Batch 체크포인트에 원본 요청이 없을 때** (MessageBatch:181)
- **문제:** 데이터 브랜치 등 공개 체크포인트로 복구한 경우 원본 요청이나 `generationInput`이 없을 수 있다. 그러면 새 스키마 지문과 맞지 않아, 이미 결제한 결과가 있어도 동기 생성을 다시 호출할 수 있다.
- **수정:**
  - 실제로 그런 경로가 있는지 확인한다.
  - 있으면 원본이 없는 구버전 생성 Batch는 결제된 응답을 그대로 재사용한다. 현재 인용 검증은 적용하되, 새 필드 필수 규칙과 확장 규칙은 끈다.
  - 추가 생성 호출이 0회인지 테스트한다.

**3. [중간] 구버전 Batch 응답을 해석하지 못해 동기로 다시 부른 경우** (IdeaGenerator:158)
- **문제:** 이 경우에도 `requiresExpansionFields`가 false로 남는다.
- **수정:** 실제로 쓰인 응답이 동기 재호출 결과면 새 규칙(필수 필드, 확장 검증)을 적용한다.

**4. [중간] 요청 카드의 기존 중복 차단이 꺼졌다** (CollectorRuntime:409)
- **수정:**
  - 근거 묶음이 완전히 같거나 제목이 같으면 예전처럼 버린다.
  - 경고(caveat)는 "비슷한" 수준에만 쓴다.
  - 같은 후보를 두 번 요청하는 테스트를 추가한다.

**5. [중간] 병합된 근거가 씨앗에서 빠진다** (FullPipeline:265)
- **문제:** 같은 주제로 병합된 후보에서 씨앗 생성기는 대표 항목만 본다. 모델이 병합된 출시 제품을 인용하면 씨앗 밖 근거로 탈락한다.
- **수정:**
  - 씨앗 생성에도 검증된 병합 구성원을 넘긴다.
  - 씨앗의 `itemIds`에 실제 항목 키를 넣는다.
  - 테스트를 추가한다.

**6. [중간] 씨앗 기록이 동기화되지 않는다**
- **수정:**
  - `expansion-seeds.json`을 DataSync 상태 파일 목록(stateOutput 등)에 넣어 Actions 실행 사이에도 유지한다.
  - 새 작업 디렉터리에서 이어받는 경우를 테스트한다.

**7. [중간] 잘못된 씨앗 날짜가 들어오면 게시가 막힌다**
- **수정:**
  - 백업 가져오기에서 씨앗 날짜를 검증하고, 잘못된 행은 거부한다.
  - 기존 로컬 기록의 잘못된 행은 읽거나 정리할 때 건너뛴다. 예외로 게시가 막히지 않게 한다.
  - 테스트를 추가한다.

**8. [낮음] 출력 토큰 상한**
- `ideaCount * 1400 + 128`을 카드당 1700으로 올린다.

**9. [낮음] 공용 criteria 파서가 예전보다 넓어졌다** (CriteriaFields:4)
- **수정:**
  - 들여쓰기 없는 줄 맨 앞의 글머리(`- `)만 맞춘다.
  - 같은 키가 여러 번 나오면 첫 번째 줄만 읽고, 그 줄만 바꾼다.
  - 테스트를 추가한다.

## UX

**A. 상세 화면 순서**
- "AI 제안(추정)" 상자를 근거(이미 나온 제품 Evidence) 바로 뒤로 옮긴다. 과거 기록과 실행 판단보다 앞이다.
- 메일과 같은 순서가 된다: 근거 → AI 제안(추정) → 실행 판단·확인 필요.

**B. 추정 상자의 글자색**
- 추정 상자를 `Surface(color = surfaceVariant, contentColor = onSurface)`로 바꿔 본문은 진하게 보이게 한다.
- 안내 줄(`expansion_speculation_help`)만 흐린 색으로 둔다.

**C. 비활성 방법 스위치**
- 큰 스위치를 끄면 RunOption의 글자 영역을 흐리게 한다(alpha 0.38 또는 비활성 색).
- `light|dark/criteria-expansion-off.png`를 추가로 찍는다.

**D. 스위치 이름**
- `expansion_enabled`는 "넓혀 본 아이디어 받기"로 줄인다.
- 도움말 `expansion_enabled_help`로 "하루 카드 중 1장"을 따로 둔다.

**E. 글자 200% 캡처**
- `font200/criteria-lenses.png`를 추가로 찍는다. 방법 목록과 모두 끔 배너가 보이게 한다.

**F. 방법 이름**
- `expansion_b2b_flip`은 "개인용·기업용 서로 바꾸기"로 바꾼다. 기호를 쓰지 않는다.

**참고:** 캡처 전에 포커스와 눌림 잔상을 지운다(잠시 기다리거나 포커스를 지운다).
