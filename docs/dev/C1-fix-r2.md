# C1 수정 지시 2회차

근거: C1 2회차 리뷰(OpenAI 코드 높음 1·중간 1, Claude 코드 높음 1·중간 1·낮음 1, UX 높음 2·중간 3·낮음 2). 규칙은 [C1-fix-r1.md](C1-fix-r1.md)와 같다.

## 결정(Claude): 비용 예약을 현실적으로 바꾸고, 요청 카드 예산을 매일 예산과 분리한다
현재는 웹 검색 결과를 100만 토큰으로 잡고 생성 여유분을 4배로 잡는다. 그래서 추가 조사가 약 $1.2로 예약돼 기본 상한에서 늘 막힌다. 또 요청 비용이 매일 카드 예산($0.50)을 함께 쓰기 때문에 07시 전에 요청하면 그날 매일 실행 예산이 부족해진다.

1. **예약식**
   - 웹 검색 추가 입력은 사용 횟수당 25,000토큰으로 잡는다(`maxUses × 25_000`, 상수로 둔다). 검색 수수료는 그대로 횟수만큼 더한다.
   - 생성 보충 입력 여유분의 ×4를 없앤다. `supplementInputHeadroom`이 이미 최악값이다.
   - 입력 추정은 UTF-8 바이트 대신 `estimateInputTokens × 1.5`로 한다. 견적과 실행이 같은 직렬화와 같은 바이트·글자 상한을 쓴다. 실행용 ID와 JSON 이스케이프까지 포함한 크기로 계산한다(OpenAI 중간).
   - 목표: 기본 모델에서 추가 조사 켬은 약 $0.30, 끔은 약 $0.25(3개 선택 기준). 테스트로 기본값에서 둘 다 $0.50 아래인지 확인한다.
   - 실제 정산이 예약을 넘으면 분석처럼 기록하고, 다음 요청 견적에 반영한다. 차단 표시는 기존 규칙을 따른다.
2. **요청 카드 예산 분리**
   - 요청 카드 비용은 매일 카드 예산(`dailyCardUsd`)을 쓰지 않는다. 대신 새 일일 상한 `requestDailyUsd`(기본 $1.00)와 월 예산(있으면)에 들어간다.
   - 승인값은 `min(requestCardUsd, requestDailyUsd − 오늘 요청 지출, 월 잔액)`이다.
   - 매일 실행 CostGuard와 `dailyCardBudgetRemaining`·`dailyBudgetExceeded`·시험 실행 잔액은 요청 원장을 더하지 않는다. 월 합계에는 더한다.
   - 1회차의 "재시도 판정에서 제외"는 그대로 둔다.
   - SC-11 예산 구역에 "요청 카드 하루 최대 (달러)"를 추가한다. core `setBudget`과 같은 규칙으로 저장한다.
   - 테스트: 06:30 요청 지출이 07:00 매일 실행 예산을 줄이지 않는지, 월 합계에는 들어가는지, 요청 일일 상한에 막히는지 확인한다.

## 코드
3. **견적 사유:** 견적 결과에 막힌 사유를 담는다(근거 부족 / 요청 최대 초과 / 요청 하루 최대 초과 / 월 예산 초과 / 고른 후보 URL이 민감 정보로 제외됨 / 복구 대기). 확인 창은 사유별 문구를 보여 준다. 버튼만 꺼지고 이유가 안 보이는 경우가 없어야 한다.

## UX
4. **막힌 이유 문구**
   - `request_card_budget` = "예상 비용(약 $%2$.2f)이 이번 요청 최대($%1$.2f)를 넘습니다. 추가 조사를 끄거나 설정 > 예산에서 요청 상한을 올리세요." 추가 조사가 꺼진 상태에서 막혔으면 "추가 조사를 끄거나 "를 뺀다.
   - 요청 하루 최대에 막히면: "오늘 요청 카드 예산(하루 최대 $%1$.2f)을 다 썼습니다. 내일 다시 하거나 설정 > 예산에서 올리세요."
   - 추가 조사를 켜도 근거가 부족하거나 상한을 넘을 때 `request_card_insufficient`의 뒷문장: "추가 조사가 필요하지만 예상 비용이 이번 요청 최대를 넘습니다. 설정 > 예산에서 요청 상한을 올리세요."
   - 용어는 "이번 요청 최대"로 통일한다.
5. **견적 창 순서:** 제목 바로 아래에 `request_card_cost`를 titleMedium으로 두고, 그 아래에 scope 줄을 둔다. scope는 "선택 n개 + 함께 쓸 근거 m개 · 이번 요청 최대 $x · 오늘 요청 예산 남음 $y"다. 근거 목록은 그 아래에 둔다.
6. **SC-01 링크 줄바꿈:** "카드 후보 n"을 다음 줄로 밀어내는 48dp 박스를 없앤다. 세로 터치 영역은 `minimumInteractiveComponentSize()`나 padding으로 늘린다. 단계별 건수 줄은 FlowRow로 만든다.
7. **"카드에 안 쓰임" 알약 제거:** 행에는 쓰인 경우에만 "카드에 쓰임"을 보인다. 필터 칩은 그대로 둔다.
8. **200% 글자:** 정보 줄은 FlowRow로 만들어 항목 단위로 줄을 바꾼다. 출처 이름은 중간에서 끊지 않는다.
9. **선택 3개 하단 바:** 한 줄로 "3개 선택 · 최대 3개"라고 쓴다.
