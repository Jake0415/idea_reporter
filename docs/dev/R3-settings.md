## 1. SC-00 첫 실행 마법사(폰 실행용)
하단 탭 없이 단계형으로 한다. 단계마다 [다음]·[이전]이 있고, 진행 표시는 1/5 형식이다.

1. **AI 키**
   - Anthropic·OpenAI 중 하나 이상 입력한다. 입력란은 가린다(●●●). 붙여넣기를 지원하고, 이 화면에는 `FLAG_SECURE`를 건다.
   - [확인]을 누르면 모델 목록을 1회 호출해 검증한다. 화면에는 끝 4자리만 보인다.
   - GitHub 토큰은 선택이다. 수집 한도를 늘리는 용도라고 설명한다.
2. **메일**
   - 받는 주소, 보내는 Gmail 주소, 앱 비밀번호를 입력한다. 앱 비밀번호 만드는 법은 링크로 안내한다.
   - [테스트 발송](`mailTest`)을 둔다.
   - "메일 받지 않기"로 건너뛸 수 있다.
3. **내 기준:** SC-09와 같은 양식이다. 건너뛰면 기본값을 쓴다.
4. **실행 시각과 권한**
   - 실행 시각을 고른다. 기본은 07:00이다.
   - 아래 권한을 단계마다 켜도록 안내한다.
     - 알림 허용
     - 정각 실행(알람 및 리마인더 권한)
     - 배터리 최적화 예외(삼성 절전 예외 안내 포함)
   - 각 항목은 켜짐/꺼짐 상태와 [켜기] 버튼으로 보여 준다. 꺼져 있어도 진행할 수 있다. 이 경우 "정각 실행이 늦어질 수 있습니다"를 안내한다.
5. **첫 실행**
   - [지금 첫 실행]을 누르면 진행 단계를 보여 주고, 끝나면 오늘 화면으로 간다.
   - 실패하면 사유와 [다시 시도]를 보여 준다.

키 검증에 실패하면 그 단계에서 멈추고 이유를 보여 준다.

## 2. SC-01 오늘 화면 보강
- **상단 상태 줄:** "다음 실행 내일 07:00 · 마지막 실행 오늘 07:03"
- **실행 중:** "수집 중…"처럼 단계를 보여 준다. ↻는 비활성으로 두고 "실행 중"을 표시한다.
- **경고 띠**(warning 토큰)
  - "오늘 실행 안 됨 · 배터리 설정 확인 › / 지금 실행"
  - "정각 실행 꺼짐 · 권한 켜기 ›"
  - "AI 키 확인 필요 ›"
  - 예산 초과
- ↻ 확인 창 문구: "오늘 카드를 새 결과로 바꿉니다". 실행이 끝났으면 메일은 하루 1회 규칙에 따라 보내지 않을 수 있다는 점을 짧게 안내한다.

## 3. SC-11 운영 설정(원래 명세 + 폰 실행)
- **일정**
  - 매일 실행 켜기/끄기, 실행 시각(시간 선택기), Wi-Fi에서만, 충전 중에만
  - 다음 실행 시각을 보여 준다.
  - 정각 실행 권한 상태와 [켜기]
  - 배터리 최적화 예외 상태와 [켜기], 삼성 절전 예외 안내
- **메일:** 받는 주소, 발송 계정, [테스트 발송], 메일 받기 끄기
- **AI 공급자 키**
  - Anthropic·OpenAI 각각의 상태를 보여 준다(연결됨/확인 실패/없음). 끝 4자리와 마지막 확인 시각도 함께 보여 준다.
  - 버튼: [등록·교체], [다시 확인], [삭제]
  - 하나 이상 있어야 실행된다.
- **출처 키:** GitHub. 저장 여부만 보여 주고 교체·삭제를 할 수 있다.
- **모델**
  - 분류와 카드 작성 단계마다 공급자와 모델을 고른다. 모델 목록은 연결된 공급자에서 받아 온다.
  - 대체 공급자 사용 여부를 고를 수 있다.
- **예산:** 일일 카드 예산, 월 예산, 분석 상한. core `setBudget`과 같은 규칙으로 저장한다.
- **고급:** Batch 사용. 기본은 꺼짐이다. 켜면 "카드가 07:30 이후 나올 수 있음"을 안내한다.
- 저장하면 곧바로 core 설정 파일에 쓰고, 알람을 다시 등록한다(R2 함수 사용).

## 4. SC-07 출처 관리, SC-09 내 기준·카드 구성 — 편집 가능하게
- **SC-07**
  - 출처 목록: 이름, 켜짐 여부, 최근 30일 통계(core 출처 통계)
  - 출처 상세에서 고칠 수 있는 값: 검색어, 최소 점수, 최대 건수, 기간, 프로필 배정
  - [기본값으로 되돌리기]
  - 저장 위치: `config/sources.local.json`
  - [연결 테스트]는 실제 호출이므로 확인 창을 띄운 뒤 1회만 한다.
- **SC-09**
  - 내 기준 양식을 저장하면 `criteria` 프롬프트로 반영한다.
  - 카드 구성(하루 카드 수 3~7, 분류별 최대, 태그 상한, 피드백 반영 개수)은 `pipeline.local.json`에 저장한다.

## 5. SC-15·SC-16 프롬프트
- 편집 내용은 `config/prompts`에 바로 저장한다. P16의 버전·비교·되돌리기는 그대로 쓴다.
- **시험 실행:** 최근 실행 자료 5건으로 돌린다. 실행 전 추정 비용을 보여 주고 확인을 받는다. 비용은 일일 예산에 포함한다.

## 6. 사업성 분석 화면(최소)
P17 트렌드 화면 전까지는 SC-10a 또는 설정에 둔다.
- 최근 트렌드 리포트의 ◆ 후보 테마 목록을 보여 준다.
- 사용자가 고르면 추정 비용(`estimateAnalysis`)을 보여 준다.
- 상한 안이면 [분석 실행]을 누른다(R2 서비스). 결과는 분석 결과 화면과 메일로 받는다.

## 7. P16에서 넘어온 정리
- inbox·저장소 연결 관련 화면과 문구를 지운다. 요청 상태 칩은 직접 반영 방식에 맞게 단순화한다. 저장이 실패하면 오류만 보여 준다.
- P16 코드·UX 리뷰에서 남은 항목 가운데 화면에 해당하는 것을 반영한다(`docs/dev/P16-fix-r1.md` 참고).

## 7-1. R2에서 넘어온 상태 표시 (R2 커밋 83a6e30)
R2가 노출만 해 둔 상태를 화면에 보여 준다. 새로 계산하지 말고 R2 함수와 Flow를 쓴다.
- **배터리 최적화 예외 필요**(워커가 유료 실행을 못 한 경우): SC-01 경고 띠 "배터리 예외가 필요합니다 · 켜기 ›" 와 SC-11 일정 항목에 표시한다.
- **메일 결과**(보냄·대기·실패, 다른 날짜 메일 실패 건수): SC-01 상태 줄 옆 또는 실행 기록(SC-12)에 표시한다. 실패면 "메일 설정 확인 ›"로 SC-11 메일로 보낸다.
- **실행 중 저장 대기(`pendingLocalChanges`)**: ★·설정 저장 직후 "실행이 끝나면 반영됩니다" 짧은 안내.
- **반영 실패(`failedLocalChanges`)**: 설정 또는 실행 기록에 "반영하지 못한 변경 n건 · 다시 시도 / 버리기".
- **예약 갱신 대기(`hasPendingUpdate`)**: SC-11에 "실행이 끝나면 새 시각이 적용됩니다".
- **취소됨·누락·유료 실패**: SC-01 "오늘 실행 안 됨" 띠의 사유 문구를 구분한다(취소함 / 실행 실패 / 시간에 못 돎).
- **Batch 결과 미게시 날짜**: 실행 기록에 표시한다.
- 실행 중 SC-11 저장 버튼은 막지 않는다(R2가 갱신을 미룬다). 대신 위 안내를 보여 준다.
