# P9 S3 수정 지시 — 1회차 (Claude 중간 1·낮음 3, OpenAI 높음 1·중간 2·낮음 1)

규칙 동일(커밋·docs 수정·키 출력 금지, 실제 LLM 호출 금지). 프롬프트 `analysis-opportunity.md` 수정은 허용.

## 높음
1. **실제 청구가 상한을 넘을 수 있음** (OpenAI) — 입력 토큰 추정이 `문자 수 ÷ 3`이라 한글 섞인 입력에서 과소 추정 가능, 메시지 형식 토큰 미반영.
   - 예약용 입력 토큰 상한 = `문자 수 ÷ 2 + 1000`(메시지·스키마 여유) × 1.2, 화면 추정도 같은 식(보수적으로 통일). 입력 추정이 **217K(272K의 80%) 이상이면 할증 단가**로 예약.
   - 예약액이 남은 예산(요청 상한, 월 상한 중 작은 값)의 **90% 이하**일 때만 실행(정산 오차 여유).
   - 정산 후 실제 비용이 상한을 넘었으면 결과는 저장하되 issues에 "예산 초과 정산"을 남기고, 그 달의 남은 예산을 0으로 보아 이후 요청을 막는다(원장 합계 기준이면 자연히 막힘 — 확인).
   - 테스트: 추정은 272K 이하인데 응답 `usage` 입력이 272K 초과 → 할증 단가로 정산, 원장에 반영, 다음 요청 차단. 예약이 남은 예산의 90% 초과면 거절.

## 중간
2. **`themeId` 강제** (Claude) — 요청마다 출력 스키마의 `themeId`를 요청 테마 ID의 `enum`으로 만든다(OpenAI strict 구조화 출력). 프롬프트에 "`themeId`에는 입력 `themes[].metrics.id` 값을 그대로 쓴다"와 입력 필드 이름(`themes[].metrics`, `themes[].evidence[].itemId/url/profile`)을 명시. 판정기 방어: `themeId`가 ID가 아니라 테마 이름과 정확히 같으면 ID로 바꿔 처리하고 경고. 테스트(스키마 enum 포함, 이름 반환 응답 처리).
3. **댓글 누락** (OpenAI) — 근거 댓글은 `enrichedComments` → `hnContext.topComments` → `item.comments` 순으로 채운다(최대 3개, 300자). 테스트.
4. **리포트 근거가 다른 분류 기록에 밀림** (OpenAI) — 리포트 evidence에 있는 itemId는 **리포트의 프로필·점수를 우선**하고, 추가 관측은 리포트에 없는 itemId만 보탠다(같은 itemId의 다른 분류 기록은 무시). 테스트(과거 기록 점수가 더 높고 프로필이 다른 경우).

## 낮음
5. **실패한 분석 재사용** (Claude) — 재사용은 `issues`가 비어 있고 기회 분야가 1개 이상 있는 성공 실행만. 실패 실행은 `--force` 없이 다시 실행 가능(추정·확인 흐름 그대로). 테스트.
6. 출력 잘림(`length`) — 지금처럼 실패로 저장하되 issues에 "출력 잘림 — maxOutputTokens 상향 필요" 명시(재시도는 하지 않음, 비용 통제).
