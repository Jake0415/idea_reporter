# R3 수정 지시 4회차

근거: 4회차 리뷰 세 개(OpenAI 코드, Claude 코드, UX). 규칙은 [R3-fix-r3.md](R3-fix-r3.md)와 같다.
- 커밋하지 않는다. docs는 이 파일 말고는 고치지 않는다.
- 실제 LLM·메일·수집 호출을 하지 않는다.
- daily.yml의 cron을 되살리지 않는다.
- 계측 테스트와 캡처는 emulator-5554에서만 한다.
- 비밀값과 주소를 기록하지 않는다.
- Gradle을 돌릴 때는 JAVA_HOME을 직접 지정한다.

## 코드 — 높음
1. **첫 실행 전 자동 과금 차단**
   - 온보딩(`first-run.finished`)이 끝나지 않았으면 예약·예비 워커·지연 워커의 **새** 자동 실행을 시작하지 않는다. 막힌 경우 실패로 기록하지 않고 조용히 건너뛴다.
   - 마법사에서 직접 시작한 실행과 그 실행의 묶음 처리 이어받기는 허용한다.
   - R2에서 올라온 기기는 1회 이관으로 이미 완료 처리되므로 영향이 없다. 테스트로 확인한다.
   - 테스트를 넣는다.

## 코드 — 중간
2. **첫 실행 날짜:** [다시 시도]를 누를 때 저장된 첫 실행 날짜가 오늘이 아니고, 게시되지 않았고, 이어받을 묶음 처리도 없으면 오늘 날짜로 다시 저장하고 실행한다.
3. **첫 실행 묶음 처리 복원**
   - 복원 시 재개할 수 있는 체크포인트가 있는데 활성 이어받기 워커가 없으면, 이어받기를 중복 없이 등록한다(KEEP 정책).
   - 화면에는 묶음 처리 대기와 [완료]를 보여 준다.
4. **예약 보류와 공통 실행 상태**
   - 예약 보류 판단과 해제 시점을 `CollectorRunService.running`이 아니라 공통 실행 상태에 맞춘다.
   - `finishOperation`에서 보류된 예약을 넘긴다. 이렇게 하면 메일 테스트나 시험 실행과 겹친 예약이 30분 밀리지 않는다.
5. **SC-07 출처 연속 저장**
   - 편집 기준은 대기열의 출처 변경까지 합친 값으로 한다.
   - 저장할 때는 실제로 고친 필드만 최신 설정에 합친다. 출처 전체를 덮어쓰지 않는다.
   - 테스트를 넣는다.
6. **견적의 잠금 충돌:** `RunLockedException`이 공통 실행 상태와 상관없는 잠금 때문이면, 2초 뒤에 최대 3번까지 다시 견적한다. 유료 호출은 없다.
7. **서비스 시간 초과 경합**
   - `onTimeout`에서는 scope 전체가 아니라 `runJob`만 취소한다.
   - 또는 CAS 전에 `scope.isActive`를 확인해, 취소된 scope에서는 새 실행을 거부한다.
   - 어느 쪽이든 실행 상태가 영구히 true로 남지 않게 한다.

## UX
8. **마법사 5단계 실패 문구**
   - 문구: "첫 실행에 실패했습니다. 오늘은 다시 실행할 수 없고, 다음 예약 시각(%s)에 자동으로 실행됩니다 · 실패 이유 보기 ›"
   - "실패 이유 보기"는 SC-12로 보낸다. 시각은 실제 설정값으로 넣는다.
9. **흰 글자 버튼 색:** 흰 글자 버튼은 모두 #0077D9(strongAccent)를 쓴다. 분석 금액 버튼을 포함해 앱 전체를 확인한다.
10. **분석 금액 줄:** "예상 약 $0.17 · 최대 $0.33까지만 씁니다"처럼 쓴다(.2f, 0.01 미만은 "$0.01 미만"). "승인 상한"과 "USD"는 쓰지 않는다.
11. **SC-01 실행 중 아이콘:** ↻ 자리의 작은 점 대신 24dp 진행 표시를 두거나, 비활성 ↻ 아이콘을 둔다.
12. **마법사 5단계 완료**
    - 문구: "첫 카드 n장을 만들었습니다 · 메일을 보냈습니다". 메일이 꺼져 있거나 대기 중이면 그에 맞게 바꾼다.
    - 실행이 시작된 뒤에는 [이전]을 숨긴다.
13. **마법사 1단계 키보드**
    - 키 입력란에서 키보드 완료 키(ImeAction.Done)를 누르면 [확인]이 실행되게 한다.
    - 포커스가 가면 [확인]까지 보이도록 bringIntoView를 쓴다.
14. **SC-11 키 확인 실패:** 섹션 맨 위에 경고색 줄을 둔다. 예: "Anthropic 키 확인 실패 · 등록·교체 ›". 그 아래 "등록·교체" 텍스트 버튼은 왼쪽 정렬한다.
15. **삼성 안내:** 삼성 기기(`Build.MANUFACTURER`)에서만 보여 준다.
16. **SC-01 경고 띠:** "외 1건 ›" 앞의 가운뎃점을 뺀다. 띠 본문 끝의 ›는 하나만 남긴다.
17. **SC-09 도움말과 용어**
    - 하루 카드 수 도움말: "매일 메일과 오늘 화면에 오는 카드 수"
    - 피드백 항목은 이름과 도움말 모두 "★·숨김 기록"으로 맞춘다.
18. **SC-11 예산 입력**
    - 예산 입력란은 KeyboardType.Decimal을 쓴다.
    - 월 예산 아래에 "비우면 월 제한 없음"을 붙인다.
    - 공급자 이름은 "Claude(Anthropic)", "OpenAI"로 보여 준다. 대문자 enum을 그대로 쓰지 않는다.
19. **SC-16 시험 결과:** JSON 원문이 아니라 값만 보여 준다. 파싱에 실패하면 원문을 보여 준다.
