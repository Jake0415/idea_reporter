# R4 수정 지시 4회차

근거: R4 4회차 리뷰(OpenAI 높음 1·중간 1, Claude 중간 2). 규칙은 [R4-fix-r3.md](R4-fix-r3.md)와 같다. 이번에도 단순한 쪽으로 정한다.

## 결정(Claude): 날짜별 기록은 "채우기만" 한다
- `out/<날짜>.json`(일일 결과)과 `out/runs/**`(실행 기록·실패 기록)는 **이 폰에 없는 날짜만 백업에서 채운다**.
- 이 폰에 이미 있는 날짜 파일은 덮어쓰지 않고, 백업에 없다고 지우지도 않는다.
- 이렇게 하면 다음 문제가 함께 풀린다.
  - 원장 없는 날짜의 지출 계산이 바뀌지 않는다(OpenAI 높음).
  - Batch 대기 날짜의 결과가 덮어써지지 않는다(Claude 중간 2).
- Batch 대기 날짜(`pendingDates`)는 이 폰에 파일이 없어도 백업의 `out/<D>.json`을 쓰지 않는다. `recorded(D)`가 true가 되면 이어받기가 끊기기 때문이다.
- 추적·피드백·설정·프롬프트·내 기준은 지금처럼 백업 내용으로 바꾼다.
- 미리보기 문구 `backup_preview_details`의 설명 부분을 아래로 바꾼다. 건수·기간 줄은 그대로 둔다.
  `이 폰에 없는 날짜의 카드와 실행 기록을 채우고, 추적·피드백·설정·프롬프트·내 기준은 이 파일 내용으로 바꿉니다. 이미 있는 날짜의 카드, 비용 기록과 예산은 이 폰 것을 그대로 둡니다. 필요하면 먼저 [내보내기]로 저장하세요.`
- 미리보기의 카드 건수는 "새로 채울 카드 n개"로 보여 준다.
- 테스트
  - 기존 날짜는 보존되고 없는 날짜만 추가되는지 확인한다.
  - pending 날짜는 쓰지 않는지 확인한다.
  - 원장 파일이 없는 날짜가 있어도 가져오기 전후 `dailyCost`·월 지출 계산이 줄지 않는지 확인한다.

## 코드
1. **워커 시작 시 LOADING 경합**
   - `Workers.kt`에서 doWork 첫머리의 복구 상태 확인 세 곳(BackupRunWorker, DeferredRunWorker, Batch 이어받기 워커, 리뷰 기준 :410·:587·:610)을 바꾼다.
   - 바꿀 코드: `if (app.recovery.first { it != BackupRecovery.LOADING } != BackupRecovery.READY) return Result.retry()`. LOADING이 끝날 때까지 기다린 뒤 판정한다.
   - 실행권 획득 직후의 재확인은 `.value` 그대로 둔다.
2. **RSS 짧은 인증값**
   - `rssPrivateValues()`도 공통 `hasPrivateRssQuery()` 기준으로 짧은 값까지 모은다.
   - 이 값을 RSS 항목의 제목·요약 정제에 적용한다.
   - 백업 내보내기에서는 저장된 결과의 일반 텍스트에도 적용한다(`[redacted]`).
   - 다만 2자 이하 값은 일반 텍스트를 망가뜨리므로, 일반 텍스트 치환에서는 빼고 링크 치환에만 쓴다.
   - 테스트를 넣는다.
