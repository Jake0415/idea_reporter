# R3 수정 지시 2회차

근거: 2회차 리뷰 세 개(OpenAI 코드, Claude 코드, UX). 기준 문서는 [R3-settings.md](R3-settings.md), [R3-fix-r1.md](R3-fix-r1.md), 결정 A~D이며 1회차와 같다.

## 규칙
- 1회차와 같다.
  - 커밋하지 않는다. docs는 이 파일 말고는 고치지 않는다.
  - 실제 LLM·메일·수집 호출을 하지 않는다.
  - 계측 테스트와 캡처는 `emulator-5554`에서만 한다.
  - 비밀값과 주소를 기록하지 않는다.
- `.github/workflows/daily.yml`은 수동 실행 전용이다. cron을 되살리지 않는다.
- 에뮬레이터 System UI가 ANR 상태이면 `adb -s emulator-5554 reboot` 후 부팅이 끝날 때까지 기다렸다가 다시 시도한다.

## 코드 — 높음
1. **R2에서 올라온 기기의 마법사 처리**
   - 문제: R2에는 `first-run` 기록이 없어서, 업그레이드한 기기가 모두 마법사에 갇힌다. 빠져나오려면 유료 수동 실행을 한 번 더 해야 하고, 실행 시각이 07:00으로 덮어써진다.
   - 아래 중 하나라도 있으면 `first-run.finished=true`로 이관한다(1회만): AI 키 저장, 실행 기록(out/ 아래 일일 기록이나 Room 카드), 예약 설정.
   - 마법사 4단계의 시각 초기값은 `schedule.options().time`에서 가져온다. 7*3600 고정을 없앤다.
   - 5단계에 "나중에 실행"(텍스트 버튼)을 둔다. 누르면 첫 실행 없이 완료하고 오늘 화면으로 간다. 오늘 실행이 이미 기록돼 있으면 5단계를 완료로 보여 준다.
   - 테스트: 업그레이드 이관, 시각 보존, 나중에 실행.
2. **첫 실행 [다시 시도] 이중 과금 방지**
   - 오늘 `paid` 실패가 기록돼 있으면 마법사 [다시 시도]도 R2의 자동 실행과 같은 차단을 받는다. 서비스에서 검사한다.
   - 회수할 묶음 처리가 있으면 새 실행 대신 이어받기로 처리한다.
   - 차단된 경우에는 이유를 보여 주고, 다시 시도 대신 "오늘 화면으로" 버튼을 둔다.
   - 테스트를 넣는다.

## 코드 — 중간
3. **메일 수신 거부**
   - `mail=false`(메일 받지 않기 또는 메일 끄기) 상태에서 게시된 보고서는 발송 대기·재시도 대기열에 넣지 않는다.
   - 일시적인 발송 보류(마감 유예 등)와 구분한다. 수신을 다시 켜도 과거 보고서가 나가지 않게 한다.
   - core 테스트를 넣는다.
4. **공통 실행 상태**
   - 메일 테스트, 프롬프트 시험 실행, 일일·분석 실행이 하나의 앱 공통 실행 상태(원자적 CAS)를 확보하고 해제한다.
   - 버튼 비활성, 서비스, 워커가 같은 상태를 본다.
   - 워커가 이 상태 때문에 막히면 R2의 락 충돌 경로처럼 처리한다. 즉 예약을 다시 걸고, 실패로 기록하지 않는다.
5. **SC-09 카드 구성 저장 기준**
   - 비교 기준은 대기열 patch까지 합친 최신 설정이다. 저장이 접수되면 기준을 갱신한다(revision 키).
   - 회귀 시나리오 테스트를 넣는다: 4→5 저장 후 다시 4로 저장.
6. **분석 재견적**
   - core가 예약액이나 상한 버전을 거부하면, 서비스 결과를 화면 상태로 전달한다. 저장된 견적을 지우고 다시 산출하게 한다.
   - 실패 알림 문구를 둘로 나눈다.
     - 상한·버전 거부: "견적을 다시 받아 주세요"
     - 그 밖의 실패: "분석 실패 · 사유"
   - 분석 견적 계산은 ViewModel 범위에서 해서 회전할 때 다시 계산하지 않게 한다.
7. **첫 실행의 묶음 처리 대기 복원**
   - 완료 플래그는 사용자가 대기 안내에서 [완료]를 누를 때 기록한다.
   - 회전하거나 프로세스가 종료된 뒤에도 `hasPendingBatch`나 continuation 예약이 있으면 같은 대기 안내를 보여 준다. 실패나 [다시 시도]로 보여 주지 않는다.
8. **프롬프트 시험 실행 예산**
   - 견적이 남은 일일 예산보다 크면 승인 버튼을 끄고 이유를 보여 준다.
   - core가 실행 직전에 막으면 그 사유("예산 부족")를 화면에 그대로 보여 준다.
9. **다른 날짜 메일 실패 건수**
   - 실행이 끝날 때마다 실제 남은 실패 건수로 덮어쓴다. 만료 처리 뒤에도 덮어쓰고, 비어 있으면 0으로 둔다.

## 코드 — 낮음
10. **SC-07 출처 저장**
    - 저장 버튼에서 `validateRouting`과 `sourceId` 존재 여부를 먼저 검사한다. 대기열에 넣기 전에 오류를 보여 준다.
    - 연결 확인 창은 승인 시점의 불변 설정 스냅샷으로 실행한다.
11. **`resume` 실행의 키 사용:** 확인 실패 키는 묶음 처리 회수 경로(`batchRecoverySecrets`)에만 쓴다. 새 분류·작성 호출에는 쓰지 않는다.
12. **★ 안내 표시**
    - "처음 ★ 사용" 여부를 지속 상태로 저장해, 한 번 쓰면 다시 나오지 않게 한다.
    - SC-01 위쪽 테두리 카드의 추적 안내는 없앤다(중복). 목록 아래 한 줄만 남긴다.
13. **카드 구성 라벨:** "카드당 태그 최대 개수"를 "같은 태그의 후보 최대 개수"로 바꾼다. 동작은 유지하고, SC-09와 마법사 3단계 모두 바꾼다.

## UX
14. **키보드 가림:** 마법사 바깥 Column, SC-11, SC-07 상세, SC-09, SC-16 스크롤 영역에 `Modifier.imePadding()`을 넣는다. 하단 고정 바도 키보드 위로 올라와야 한다.
15. **"실행이 끝나면 반영됩니다"**
    - 실행 중일 때만 보여 주고, 문구는 "저장한 변경은 지금 실행이 끝나면 반영됩니다"로 바꾼다.
    - 반영 실패 띠가 있으면 숨긴다. 실행 중이 아니면 바로 저장되므로 띄우지 않는다.
16. **마법사 5단계**
    - 추정이 0이거나 없으면 금액 부분을 뺀다.
    - 하단 바 오른쪽 버튼을 단계 상태에 맞게 바꾼다.
      - 실행 전: [지금 첫 실행]
      - 실행 중: 비활성 "실행 중"
      - 완료나 묶음 처리 대기: [완료]
      - 실패: [다시 시도]. 2번 차단 시에는 "오늘 화면으로"
    - 본문에 있는 같은 버튼은 지운다.
17. **[다음]이 꺼진 이유:** 바로 위에 회색 한 줄을 둔다.
    - 1단계: "키를 하나 이상 [확인]하면 다음으로 갈 수 있습니다"
    - 2단계: "[테스트 발송]에 성공하거나 ‘메일 받지 않기’를 고르세요"
18. **SC-01 띠 정리**
    - 경고 띠: `… · 외 3건 ›`를 띠 안 오른쪽 끝에 둔다.
    - 진행 띠: 보이는 텍스트로 `실행 중 · 2/5 분류 중`을 쓰고, [취소]를 띠 안 오른쪽에 둔다.
    - 진행 표시는 확정 진행(step/5)으로 그린다.
    - SC-11의 [다시 시도]·[버리기]도 띠 안에 가로로 둔다.
19. **SC-01 메일 실패 표시**
    - 상태 줄 전체를 링크로 만들지 않는다. 시각 부분은 회색 텍스트로 두고, "· 메일 실패 ›"만 경고색 링크(탭 영역 48dp)로 둔다.
    - 들여쓰기를 다른 줄과 맞춘다.
20. **SC-11 구역 이름:** "실행 시각과 권한"을 "권한"으로 바꾼다. 마법사 4단계는 지금 이름을 유지한다.
21. **`no_today` 문구:** "오늘 결과 없음 · 다음 실행 %s"로 바꾸고 실제 다음 실행 시각을 넣는다. 매일 실행이 꺼져 있으면 "오늘 결과 없음 · 매일 실행 꺼짐"으로 쓴다.
22. **마법사 1단계**
    - GitHub 토큰 상태는 입력이나 확인을 한 뒤에만 보여 준다.
    - "키 받는 곳 ↗"은 입력란 아래 오른쪽의 작은 텍스트 링크(탭 영역 48dp)로 바꾼다.
    - 형식 힌트가 보이는지 확인한다.
23. **삼성 안내:** "설정 › 배터리 › 백그라운드 사용 제한 › 절전 예외 앱에 이 앱 추가"처럼 경로를 적는다. 마법사 4단계와 SC-11 모두 고친다.
24. **마법사 3단계**
    - 대상 고객 칩에 선택 표시를 넣는다. "제한 없음"이면 셋 다 선택 상태로 보인다.
    - 메모·제외·수익화 칸은 `minLines=2`로 둔다.
    - "건너뛰기"를 "기본값으로 건너뛰기"로 바꾼다.
25. **분석 금액 표시:** `.2f`로 "예상 약 $0.02 · 분석 실행"이라고 쓴다. 0.01 미만은 "$0.01 미만"으로 쓴다.
26. **SC-01 정각 경고:** "정각 실행이 꺼져 있어 늦게 시작할 수 있습니다 · 켜기 ›"
27. **옛 문구 정리:** strings에서 쓰이지 않는 `running`(Actions…)와 `secrets`(GitHub Secrets…)를 지운다. 쓰이면 폰 실행에 맞게 고친다.
