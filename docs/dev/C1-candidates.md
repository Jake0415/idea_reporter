## 1단계 F-40 카드 후보 보기 (LLM 0원)
**자료:** 날짜별 결과 파일 `out/<날짜>.json`
- `classified`(Signal: item + ClassifiedItem의 profile·score·reason·summary·topicLabel·tags)
- `dropped`(BELOW_PROFILE_THRESHOLD / SAME_TOPIC / OVER_QUOTA)
- `cards`의 인용(SignalRef)

**구분**
- **카드 후보:** 선택 단계를 통과한 항목. `report.stages`의 select 건수와 맞아야 한다. 판정 함수는 core에 두고 테스트한다.
  - 카드에 인용된 후보에는 "카드에 쓰임"을 표시한다.
- **기준 미달:** 분류는 됐지만 임계값 미달·같은 주제·상한 초과로 빠진 항목. 이유를 함께 보여 준다.

**core:** `collector.runtime`에 `candidates(date): CandidateView`를 둔다.
- 후보 목록: 점수 내림차순. 항목마다 key, 제목, 출처, URL, 분류 기준, 점수, 요약, 이유, 주제 이름, 태그, 카드에 쓰임 여부, 쓰인 카드 id
- 기준 미달 목록
- 단계별 건수

**화면(SC-05 "오늘 후보", 기존 SC-05 자리를 이 용도로 먼저 연다)**
- 진입
  - SC-01 상태 줄의 "단계별 건수"에서 "카드 후보 n"을 누르면 그날 후보로 간다.
  - 보관함(SC-03)의 날짜 머리에도 "후보 보기 ›"를 둔다.
- 머리: 날짜와 "카드 후보 18 · 카드에 쓰임 7"
- 필터 칩: 전체 / 쓸 수 있는 기술 / 사람들의 요청·불편 / 이미 나온 제품 / 카드 안 됨
- 행
  - 위 줄: 분류 기준 칩과 점수(예: 7.5)
  - 가운데: 한국어 한 줄 요약(2줄까지)
  - 아래: 출처와 주제 이름(작은 글씨)
  - 오른쪽: "카드에 쓰임" 배지
  - 행을 누르면 펼쳐져 이유 한 줄, [원문 열기], [이 카드 보기](쓰였으면)가 보인다.
- 맨 아래 "기준 미달 n건 ›"은 접어 둔다. 펼치면 점수순으로 보여 주고, 탈락 이유를 쉬운 말로 적는다(예: "기준 점수 미달", "같은 주제로 합쳐짐", "하루 상한 초과").
- 빈 상태: "이 날은 후보 기록이 없습니다"
- 다크 모드, 글자 200%, 48dp 터치 영역을 지킨다.

**메일(선택)**
- 설정 SC-11 메일 구역에 "메일에 오늘 후보 목록 넣기"(기본 꺼짐)를 둔다.
- 켜면 메일 카드 아래에 "오늘 후보(카드 안 된 것)" 구역을 둔다. 내용은 최대 15건의 분류 기준·점수·요약 한 줄과 원문 링크다.
- `MailTheme`과 기존 토큰을 쓰고, 인라인 CSS로 만든다. 앱 링크는 지금 규칙을 따른다.

## 2단계 F-41 골라서 카드 만들기 (요청형, 유료)
**선택**
- SC-05에서 행을 길게 누르거나 체크하면 선택 모드가 된다. 한 번에 1~3개까지 고를 수 있다.
- 하단에 고정 바를 둔다: "n개 선택 · [카드 만들기]"

**근거 보충(코드, LLM 0원)**
- 카드 규칙(쓸 수 있는 기술 1개 이상 + 요청·불편 또는 이미 나온 제품 1개 이상)을 채우기 위해, 같은 날 분류 항목과 과거 기록 검색(HistorySearch)에서 같은 주제·태그의 근거를 최대 4개까지 자동으로 붙인다.
- 붙인 근거는 견적 화면에 "함께 쓸 근거" 목록으로 보여 준다.
- 그래도 규칙을 못 채우면 실행 전에 알린다: "근거가 부족합니다. [추가 조사]로 관련 글을 더 찾을 수 있습니다."

**견적 → 확인 → 실행**
- core에 `estimateRequestedCards(date, keys, research: Boolean)`과 `runRequestedCards(date, keys, research, approvedMaxUsd)`를 둔다.
- 기존 IdeaGenerator, 인용 검증, 카드 중복 제거, 비용 기록을 그대로 쓴다. 작성 모델은 설정의 카드 작성 단계 모델이다.
- **추가 조사(선택 체크):**
  - 그 항목에 대해 기존 보충 검색(공급자 웹 검색, max_uses 3)과 댓글 수집을 돌리고, 결과를 근거에 더한다.
  - 견적에 포함하고, 견적 화면에 "웹 검색 최대 3회 포함"을 보여 준다.
- **비용**
  - 일일 예산에 포함한다. 요청 1건 상한(`requestCardUsd`, 기본 $0.50)을 둔다. 저장은 core `setBudget`과 같은 규칙이고, SC-11 예산 구역에 칸을 추가한다.
  - 실행 직전에 상한을 다시 확인한다(사업성 분석과 같은 방식).
- **실행**
  - CollectorRunService(공통 실행 상태)로 돌린다. 진행 알림을 띄우고 [취소]를 둔다.
  - 매일 실행 중이거나 복구 대기 중이면 거절하고 이유를 보여 준다.
- **저장**
  - 결과 카드는 `out/requested/<날짜>-<id>.json`에 저장하고 Room에 반영한다.
  - 카드에는 "요청" 배지를 붙인다(`badges`). 보관함과 그날 오늘 화면 카드 목록에 들어간다.
  - ★ 추적과 피드백은 매일 카드와 같다.
  - 매일 결과 파일(`out/<날짜>.json`)은 건드리지 않는다. 메일 중복 규칙에 영향을 주지 않기 위해서다.
- **메일(선택):** 견적 화면에 "결과를 메일로도 받기"(기본 꺼짐)를 둔다. 켜면 그 카드만 담은 메일을 보낸다. 수신 설정은 발송 직전에 다시 확인한다.
- **실패:** 실패하면 사유를 보여 주고, 비용이 0인 실패만 [다시 시도]를 허용한다. 유료 호출이 시작된 뒤의 실패는 자동으로 다시 호출하지 않는다.
- **Batch는 쓰지 않는다.** 요청형은 즉시 실행한다.
- **백업(R4):** `out/requested/**`는 날짜별 기록과 같은 "없는 것만 채우기" 규칙으로 백업과 가져오기에 포함한다.
