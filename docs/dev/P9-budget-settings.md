# P9 — 사용자 금액 상한 설정과 상한별 동작 (S3 추가 요구)

기준: `docs/business-scout-plan.md` §7-1(v4, 사용자 요청: "금액 상한을 사용자가 설정해서 운용, 상한에 따라 동작"). 이전 지시 `P9-S3-analysis.md`, `P9-fix-r1.md`의 규칙 유지.
규칙: 커밋·docs 수정·키 출력 금지, 실제 LLM 호출 금지(가짜 공급자).

## 할 일
1. **설정 파일** `collector.budget.BudgetSettings` — PC 저장 위치 `out/settings/budget.json`(없으면 기본값). 항목:
   `dailyCardUsd`(0.50), `analysisRequestUsd`(1.00), `analysisMonthlyUsd`(5.00), `backfillRunUsd`(0.50), `monthlyTotalUsd`(null=없음), `warnAtPercent`(80), `overBudget`(`ASK`|`AUTO_FIT`|`STOP`, 기본 ASK).
   - 검증: 금액은 0 이상·소수 2자리, 이상한 값은 오류 메시지와 함께 기본값 유지(파일을 고치지 않음). 알 수 없는 키 무시.
   - 지금 쓰는 곳 연결: 일일 파이프라인 `dailyBudgetUsd`, 분석 요청·월 상한, 과거 채우기 기본 예산이 이 설정을 읽는다(실행 옵션 `--budget`은 그 실행에만 쓰는 일회성 값으로 우선하되, 분석에서는 월 남은 예산을 넘을 수 없음).
   - `Main --budget-status`: 각 상한, 이번 달 사용액(일일 카드 원장 합계, 분석 원장 합계, 전체), 남은 예산, 사용률, 월 초기화일(다음 달 1일). `Main --set-budget key=value [key=value…]`: 검증 후 원자 저장, 바뀐 값 출력.
2. **분석 요청 흐름** (AnalysisCommand) — 예약액(P9-fix-r1의 보수적 식) vs 남은 예산 = min(요청 상한 또는 일회성 값, 분석 월 상한 − 분석 월 사용액, 전체 월 상한 − 전체 월 사용액):
   - A. 예약액 ≤ 남은 예산 × 0.9 → 지금처럼(추정 출력, `--yes`면 실행).
   - B. 넘으면 **맞춤안** 계산: 단계 ① 근거 줄이기(테마당 15→10→6) ② 추론 강도 HIGH→MEDIUM ③ 반대 검토 끄기(S4용 자리만, 지금은 해당 없음 표시) ④ 테마 수 줄이기(점수·증가율 높은 테마부터 남김). 각 맞춤안의 예약액을 출력.
     - `ASK`: 맞춤안 목록을 출력하고 끝. 사용자는 `--fit <n>`(번호)로 골라 다시 실행(`--yes`와 함께).
     - `AUTO_FIT`: ①→②→④ 순으로 상한(×0.9)에 맞는 첫 구성을 고르고 그 내용과 예약액 출력, `--yes`면 실행.
     - `STOP`: C처럼 끝.
   - C. 최소 구성(근거 6·MEDIUM·테마 1)도 넘으면 실행하지 않고 남은 예산·월 초기화일·`--set-budget` 사용법 안내.
   - D. 정산 후 실제 > 예약이면 결과 저장 + issues "예산 초과 정산 $x" + 콘솔 경고. 사용액은 원장 합계 그대로라 남은 예산이 줄고, 0 이하면 다음 요청은 C.
   - E. 실행 후 월 사용률 ≥ `warnAtPercent`이면 콘솔·결과 리포트·`--analysis-list`에 "이번 달 $a / $b (p%)" 경고.
   - F. 상한을 이미 쓴 금액보다 낮게 바꾸면 남은 예산 0 → C.
   - 실행에 쓴 구성(근거 수, 추론 강도, 테마, 맞춤 단계)을 `AnalysisRun`에 `fit` 필드로 저장하고 결과 리포트·간단 보기에 "맞춤 실행: 근거 10건·추론 medium" 표시. 같은 테마라도 구성이 다르면 재사용하지 않는다(재사용 키에 구성 포함).
3. **전체 월 상한** — 정해져 있으면 일일 파이프라인·과거 채우기·분석 모두 실행 전 "전체 월 사용액 + 이번 예약 ≤ 전체 월 상한"을 확인하고, 넘으면 유료 단계를 시작하지 않는다(일일 파이프라인은 수집·정제·코드 단계만 하고 분류·작성 생략, 실행 기록에 사유). 정하지 않으면 지금 동작 그대로.

## 테스트
- 설정 파일 없음·정상·잘못된 값(기본값 유지)·알 수 없는 키, `--set-budget` 검증·원자 저장, `--budget-status` 합계(두 원장).
- A/B(ASK 목록, `--fit` 선택, AUTO_FIT 자동 선택)/C/D/E/F 각각. 맞춤안 예약액이 단계마다 줄어듦.
- 일회성 `--budget`이 월 남은 예산을 넘지 못함.
- 전체 월 상한: 넘으면 일일 파이프라인 분류·작성 생략(사유 기록), 분석·과거 채우기 거절. 없으면 기존 동작 회귀 없음.
- `fit` 저장·표시, 구성 다르면 재사용 안 함.
