## 1단계 F-42 반복 막기 (LLM 비용 추가 없음)
**지금의 문제**
- 카드 중복은 같은 날 안에서만 코드로 막는다(IdeaGenerator의 DUPLICATE 판정).
- 최근 카드는 제목만 `recentCards`로 프롬프트에 넘긴다. 모델이 무시해도 걸러지지 않는다.

**카드 필드 추가(IdeaCard, 모두 기본값 있음)**
- `targetCustomer: String = ""`: 대상 고객. 짧은 한국어 명사구(예: 1인 회계사무소)
- `coreTech: String = ""`: 핵심 기술. 짧은 명사구
- `pain: String = ""`: 핵심 불편 한 문장
- 구조화된 출력 스키마와 ideas.md 설명에 추가한다. 새 카드에서는 세 칸 모두 필수다(빈 값이면 MISSING_FIELD).

**조합 키와 판정(core, 순수 함수 + 테스트)**
- 최근 카드: 지난 `recentCardDays`일의 매일 카드와 요청 카드(`out/requested`)를 대상으로 한다. 기본값은 7에서 14로 바꾼다.
- 정규화: 소문자, 공백·기호 제거, 한글/영문 토큰. 불용어 몇 개만 둔다.
- 반복 판정. 아래 중 하나라도 맞으면 반복이다.
  - 인용한 기술 신호의 주제 키(topicKey)가 하나 이상 같고, `targetCustomer`가 같거나 `pain` 토큰 겹침(Jaccard)이 0.5 이상
  - 제목 토큰 겹침이 0.6 이상
  - 예전 카드처럼 새 필드가 빈 경우에는 제목과 기술 주제 키만 비교한다
- 반복이면 버린다.
  - 새 탈락 이유 `REPEAT`를 추가하고, 상세에 "최근 카드와 같음: <제목> (<날짜>)"를 남긴다.
  - 카드 탈락 기록이 있는 곳(report/issues 등 기존 방식)에 똑같이 남긴다.
- 프롬프트에 주는 `recentCards`를 제목만이 아니라 `제목 · 대상 고객 · 핵심 기술 · 불편` 한 줄로 바꾼다. ideas.md 4번 규칙도 그에 맞게 고친다.
- 반복으로 버려서 카드 수가 줄어도, 다시 호출해서 채우지 않는다(비용이 늘지 않게).

## 2단계 F-43 매일 확장 카드 (하루 1장)
**설정(pipeline 설정, 고친 칸만 병합)**
```json
"expansion": {
  "enabled": true,
  "cardsPerDay": 1,
  "seedCount": 3,
  "seedHistoryDays": 30,
  "lenses": { "other-customer": true, "korea": true, "b2b-flip": true,
              "unbundle": true, "invert": true, "second-order": true },
  "myFields": []
}
```
- `ideaCount` 5는 그대로 둔다. 그중 `cardsPerDay`장을 확장 몫으로 쓴다. 확장 카드가 없으면 매일 카드로 채울 수 있다.

**렌즈 6개(이름은 화면 문구, 설명은 프롬프트 리소스)**
| id | 이름 | 뜻 |
|---|---|---|
| other-customer | 다른 고객으로 옮기기 | 같은 기술·해결 방식을 원래와 다른 직업군·사용자층에 적용 |
| korea | 한국 시장으로 옮기기 | 해외 제품·요청을 한국어·한국 제도·한국 서비스 환경에 맞게 |
| b2b-flip | B2C↔B2B 바꾸기 | 개인용을 팀·기업용으로, 또는 그 반대로 |
| unbundle | 기능 하나만 떼어 내기 | 큰 제품의 기능 하나를 1인이 만들 작은 서비스로 |
| invert | 반대로 하기 | 문제나 가정을 뒤집기(자동화 → 사람 검수, 생성 → 검증 등) |
| second-order | AI가 만든 새 불편 | AI 확산 때문에 새로 생긴 불편을 푸는 서비스 |

- 렌즈 정의는 리소스 파일(예: `lenses.default.json`)에 두고 코드가 읽는다.
- 렌즈 설명 문구는 ideas.md나 별도 프롬프트 리소스에 둔다. 사용자가 프롬프트를 고칠 수 있는 규칙을 따른다.

**씨앗 만들기(코드, LLM 0원)**
- 오늘 선택된 신호에서 조합 후보를 만든다: 기술 신호 1개 × (요청·불편 또는 이미 나온 제품 1개) × 대상 고객 1개 × 렌즈 1개.
- 대상 고객 후보는 이 순서로 고른다.
  1. 3단계의 `myFields`(내 분야)
  2. criteria의 대상 고객
  3. 리소스의 기본 고객 목록(직업군 10여 개)
- 렌즈는 켜진 것 중에서 고른다.
  - 기본은 최근에 덜 쓴 순서(돌아가며)
  - 렌즈별 피드백으로 가중치를 준다: ★ +1, 관심 없음 −1. 아래한도를 둬서 렌즈가 완전히 사라지지는 않게 한다.
- 지난 `seedHistoryDays`일에 쓴 조합 키(기술 주제 + 대상 고객 + 렌즈)는 제외한다.
  - 씨앗 기록은 `out/expansion-seeds.json`에 두고, 백업 허용 목록에 넣는다.
- `seedCount`(3)개를 만들어 사용자 메시지에 `expansionSeeds`로 넣는다. 각 씨앗에는 씨앗 id, 렌즈 id·이름·설명, 대상 고객, 신호 itemId 목록이 들어간다.
- 켜진 렌즈가 없거나 `enabled: false`면 씨앗을 넣지 않는다. 그러면 확장 카드도 없다.

**카드 필드 추가**
- `kind: String = "daily"`: "daily" 또는 "expanded"
- `lens: String? = null`: 렌즈 id
- `seedId: String? = null`
- `speculation: List<String> = emptyList()`: 근거가 아니라 AI가 추정해서 넓힌 부분. 화면에는 "AI 제안(추정)"으로 보인다.

**프롬프트(ideas.md에 확장 절 추가)**
- `expansionSeeds` 중 되는 것 하나로 확장 카드를 최대 `cardsPerDay`장 쓴다. 안 되면 쓰지 않는다.
- 렌즈의 관점으로 넓히되, 근거 블록에는 씨앗에 있는 실제 신호만 인용한다.
- 근거로 확인되지 않는 확장 내용(새 대상 고객의 불편 추정 등)은 `speculation`에 쓴다. `whyToday`에는 출발한 신호와 렌즈를 밝힌다.

**검증(코드가 강제)**
- 확장 카드
  - 씨앗의 신호 중 기술 신호 1개 이상을 인용한다.
  - 요청·불편이나 이미 나온 제품이 없으면 `caveats`에 "직접 수요 신호 없음 — AI 추정"이 있어야 한다. 없으면 코드가 붙인다.
  - `lens`는 켜진 렌즈 id여야 한다. `seedId`는 오늘 씨앗이어야 한다. `speculation`은 1개 이상이어야 한다.
  - 하루 `cardsPerDay`장을 넘으면 넘친 것은 버린다(새 탈락 이유 `EXPANSION_CAP`).
- 1단계 반복 막기를 확장 카드에도 똑같이 적용한다.
- 매일 카드(kind=daily)의 기존 규칙은 바뀌지 않는다.
- 쓰인 씨앗만 씨앗 기록에 남긴다.

**표시**
- 앱 카드(SC-01·SC-02 상세·SC-03 보관함)
  - "AI 확장 · <렌즈 이름>" 칩을 붙인다. 중립 회색이고, 좋은 신호용 파랑 배지와 구분한다.
  - 상세에는 "AI 제안(추정)" 구역에 `speculation` 목록을 보여 준다.
- 메일
  - 목차에서 확장 카드 옆에 "AI 확장 · 렌즈 이름"을 표시한다.
  - 본문은 매일 카드 뒤에 "넓혀 본 아이디어" 구역으로 따로 둔다.
  - `MailTheme` 토큰과 인라인 CSS를 쓰고, 텍스트 본문에도 넣는다.
- 피드백(★·관심 없음)은 매일 카드와 같다. 렌즈 가중치 계산에 쓴다.

## 3단계 F-44 내 분야 씨앗 (LLM 0원)
