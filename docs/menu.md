# 메뉴·기능 설계 — AI 아이디어 수집기

> 데이터 흐름·타입은 [design.md](design.md). 이 문서는 사용자가 보는 기능·메뉴·화면·메일의 기준이다.
> 화면 번호(SC-xx)와 기능 번호(F-xx)는 코드·커밋에서 그대로 쓴다.

## 1. Horizon 데모 분석 (2026-11-19 브리핑)

[Horizon 데모](https://thysrael.github.io/Horizon/) 2026-11-19 중국어 브리핑을 내장 브라우저로 확인했다. (REA는 이 세션에 불러와지지 않아 사용하지 못함.)

| 관찰 | 실제 모습 | 우리 결정 |
|---|---|---|
| 상단 깔때기 | "43건 중 11건을 골랐다" 한 줄 | **차용.** "수집 412 → 후보 18 → 카드 5" (SC-01, 메일) |
| 목차 | 프로필별 묶음, 제목 + 점수 배지 | **차용.** 카드 목록에 분류·점수·배지 |
| 제목 | 원문 제목이 아니라 사실을 요약한 문장 | **차용.** 카드 제목은 "누구의 무엇을 푸는가"가 드러나게 |
| 첫 블록 | 제목 바로 아래 요약 문단(블록 제목 없음) | **차용.** 카드 상세 첫 줄 = 한 줄 설명 |
| 출처 줄 | 출처 · 작성자 · 시각 · "커뮤니티 토론" 링크 | **차용.** 근거 항목마다 출처·시각·원문 링크 |
| 배경 블록 | "10월 29일 브리핑에서 보도했던…"처럼 **과거 브리핑을 날짜로 인용** | **차용.** "과거 언급" 블록(과거 기록 검색) |
| 영향 블록 | "누구에게 무슨 영향" 실무 관점 | **변형.** "실행 판단" 블록(난이도·차별화·위험·검증) |
| 커뮤니티 블록 | 댓글 작성자를 이름으로 인용, 찬반 의견을 함께 | **차용.** 수요 신호 블록에 댓글 인용(찬반 포함) |
| 불확실성 표시 | "커뮤니티 주장, 공식 자료로 확인 안 됨", "업체 주장" 명시 | **차용.** 카드에 "확인 필요" 표시(`caveats`) |
| 태그 | 항목 끝에 태그 3~5개 | **차용.** 보관함 검색·필터에 사용 |
| 묶음 | 기술 뉴스·기술 블로그·금융 뉴스가 한 페이지에 섞임 | **우리는 AI 아이디어만.** 프로필은 근거 구분용이고 카드는 하나의 목록 |
| 한계 | 기사 1건 = 항목 1개, "그래서 나는 무엇을 만들까"는 없음. 피드백·보관함 필터 없음 | **우리 고유 기능:** 신호 종합 카드, ★·관심 없음, 반복 주제 |

## 3. 메뉴 구조

```
SC-00 첫 실행 설정 (최초 1회: API 키 → 메일 → 내 기준 → 첫 실행)

하단 탭
├── ① 오늘
│   ├── SC-01 오늘의 카드
│   └── SC-02 카드 상세
├── ② 보관함
│   ├── SC-03 지난 카드
│   └── SC-04 반복 주제            (L)
├── ③ 수집함
│   └── SC-05 오늘 수집 항목       (L, MVP에서는 탭 숨김)
└── ④ 설정
    ├── 수집
    │   ├── SC-07 출처 관리 (+ SC-07a 출처 상세)
    │   └── SC-08 신호 프로필      (L)
    ├── 아이디어
    │   └── SC-09 내 기준·카드 구성
    ├── 운영
    │   ├── SC-10 실행 기록 (+ SC-10a 실행 상세)
    │   └── SC-11 일정·메일·API 키·모델·백업
    └── 정보 (버전, 오픈소스 고지)

진입 경로
- 실행 완료 알림 → SC-01
- 실행 실패 알림 → SC-10a
- 메일의 카드 링크 → 앱 링크 `ideacollector://card/{cardId}` → SC-02
```

MVP의 하단 탭은 **오늘·보관함·설정** 3개. 수집함은 화면만 나중이고, 탈락 이유 기록은 1단계부터 core에 넣는다.

## 4. 화면 명세

### SC-00 첫 실행 설정
- **목적:** 처음 한 번 필요한 값만 받고 첫 실행까지 안내.
- **단계:** ① Anthropic API 키(필수) + GitHub 토큰(선택) → ② 받는 메일 주소, 발송 계정(Gmail 앱 비밀번호) + [테스트 발송] → ③ 내 기준 4문항(SC-09와 같은 양식, 건너뛰면 기본값) → ④ [지금 첫 실행].
- **상태:** 키 검증 실패 시 해당 단계에서 멈추고 이유 표시.
- **데이터:** SecretProvider, Mailer, `criteria`.

### SC-01 오늘의 카드
- **목적:** 오늘 받을 것을 한눈에.
- **표시:**
  - 상단 깔때기: "수집 412 → 후보 18 → 카드 5", 마지막 실행 시각, 오늘 비용. 실패 출처가 있으면 "Reddit 수집 실패" 띠(누르면 SC-10a).
  - 카드 목록(최대 `ideaCount`): 제목, 한 줄 설명, 분류, 배지(급상승·여러 곳에서 화제·3일 연속), ★ 버튼.
- **동작:** 카드 누르기 → SC-02, ★ 토글, [지금 실행](실행 중이면 진행 단계 표시), 아래로 당겨 새로고침(저장된 결과 다시 읽기).
- **상태:** 아직 오늘 실행 전 → 어제 카드 + "다음 실행 예정 07:00"; 실행 중 → 단계 표시(수집 중/분류 중/작성 중); 예산 초과로 일부만 생성 → 안내 띠.
- **데이터:** IdeaStore(오늘 카드), RunReport(깔때기·비용·실패 출처), FeedbackStore.

### SC-02 카드 상세
- **목적:** 아이디어를 판단하는 데 필요한 근거를 한 화면에.
- **블록 구성:** §5 참고.
- **동작:** ★, 관심 없음(이유: 이미 있음 / 너무 큼 / 내 분야 아님 / 근거 약함 / 기타 입력), 근거 원문 열기(브라우저), (L) 메모, 공유, 더 파고들기.
- **데이터:** IdeaCard, SignalRef → Item, FeedbackStore, HistorySearch.

### SC-03 지난 카드
- **표시:** 날짜별 묶음 목록(날짜 머리글에 그날 깔때기 요약), 카드 줄은 SC-01과 같은 모양.
- **필터:** ★만, 분류, 태그, 글자 검색(제목·설명·태그 전문 검색), 관심 없음 숨기기(기본 켬).
- **데이터:** IdeaStore, FeedbackStore, HistorySearch(FTS).

### SC-04 반복 주제 (L)
- **표시:** 최근 30일 동안 여러 번 나온 주제(`topicKey`) 목록: 주제명, 등장 횟수, 첫·마지막 날짜, 관련 카드 수, 흐름(작은 막대).
- **동작:** 주제 누르기 → 관련 항목·카드 목록.
- **데이터:** ItemStore(topicKey 이력), IdeaStore.

### SC-05 오늘 수집 항목 (L)
- **표시:** 출처별 탭, 항목마다 제목·출처 점수·통과 여부·탈락 이유(`DropReason`)·분류 점수와 이유.
- **동작:** 탈락 항목에 "다음엔 포함" 표시 → 출처 임계값 조정 참고용 기록. 원문 열기.
- **데이터:** ItemStore(오늘 항목 + DropReason + ClassifiedItem).

### SC-07 출처 관리
- **표시:** 출처 목록: 이름, 켜짐 여부, 기본 프로필, 최근 30일 통계(하루 평균 수집, 통과율, 평균 점수), 마지막 실패 시각.
- **SC-07a 출처 상세:** 검색어(여러 개), 출처별 최소 점수, 최대 건수, 기간, 프로필 배정(명시/후보), [연결 테스트](실제 호출 1회, 건수와 첫 3건 제목 표시), [기본값으로 되돌리기].
- **(L)** RSS 피드 추가: 이름, URL, 프로필, 최대 건수.
- **데이터:** SourceConfig(Room에 덮어쓰기), SourceStats.

### SC-08 신호 프로필 (L)
- **표시:** 기술 신호·수요 신호·경쟁 제품 3개: 임계값(0~10), 후보 상한, 평가표 요약.
- **동작:** 임계값·상한 수정, 평가표(`analysis.md`) 보기, 고급: 평가표 직접 수정(되돌리기 제공).
- **데이터:** ProfileConfig.

### SC-09 내 기준·카드 구성
- **내 기준:** 개발 범위(1인/소수, 기간), 대상 고객(개발자·B2B·소비자 등 복수 선택 + 메모), 관심 분야, 제외 분야, 수익화 방식. 저장 시 `criteria` 텍스트로 변환해 아이디어 작성 프롬프트에 넣음.
- **카드 구성:** 하루 카드 수(3~7), 분류별 최대 개수, 최근 피드백 반영 개수.
- **데이터:** `criteria`, PipelineConfig.

### SC-10 실행 기록
- **표시:** 날짜별 실행: 결과(성공/일부/실패), 깔때기, 비용, 소요 시간. 상단에 이번 달 비용 합계와 예산 대비.
- **SC-10a 실행 상세:** 단계별 입력/출력 건수와 소요 시간, 출처별 수집 결과와 실패 이유, LLM 호출별 토큰·비용, 인용 검증에서 제거된 근거 수.
- **데이터:** RunReport.

### SC-11 일정·메일·API 키·모델·백업
- **일정:** 실행 시각, Wi-Fi에서만, 충전 중에만, 배터리 최적화 예외 안내(제조사별 설정 화면 이동).
- **메일:** 받는 주소, 발송 계정, [테스트 발송], 메일 받기 끄기.
- **API 키:** Anthropic(필수), GitHub, Reddit, Product Hunt — 저장 여부만 표시(값은 다시 보여주지 않음), 교체·삭제.
- **(L) 모델·예산:** 분류 모델, 작성 모델, 일일 예산, 보충 검색 켜기와 횟수.
- **(L) 백업:** 설정·카드·피드백 JSON 내보내기/가져오기 (키는 제외).

## 5. 카드 상세 블록 구성

Horizon의 "첫 블록 + 선택 블록" 방식을 따른다. 내용이 없는 선택 블록은 숨긴다.

| 순서 | 블록 | 필수 | 내용 | IdeaCard 필드 |
|---|---|---|---|---|
| 0 | 머리 | 필수 | 제목, 한 줄 설명(블록 제목 없이), 분류, 배지, 태그 | title, oneLiner, category, badges |
| 1 | 오늘 고른 이유 | 필수 | 왜 오늘 이 카드인가 한두 문장 | whyToday |
| 2 | 문제 | 필수 | 누구의 어떤 불편 | problem |
| 3 | 기술 신호 | 필수 | 가능하게 한 기술: 제목·출처·점수·라이선스, 원문 링크 | techSignals |
| 4 | 수요 신호 | 선택 | 불편·요청 근거, **댓글 인용(작성자·찬반)** | demandSignals |
| 5 | 경쟁 제품 | 선택 | 이미 나온 것과 빈틈(불만 댓글) | competitors |
| 6 | 과거 언급 | 선택 | "11월 13일 카드/항목에서…" 날짜 인용 최대 2개 | history |
| 7 | 실행 판단 | 필수 | 난이도(1인 기간), 차별화, 가장 큰 위험 1개, 2주 검증 방법 | effort, differentiation, biggestRisk, validationPlan |
| 8 | 확인 필요 | 선택 | 근거가 한 출처뿐, 업체 주장, 커뮤니티 주장 등 | caveats |
| 9 | 근거 링크 | 필수 | 이번 실행에서 수집된 항목 URL만(인용 검증 통과분) | 모든 SignalRef |

규칙: 기술 신호 1개 이상 + (수요 신호 또는 경쟁 제품) 1개 이상이 없는 카드는 만들지 않는다.

## 6. 메일 리포트

```
제목: [AI 아이디어] 11월 19일 — 카드 5개 (수집 412 → 후보 18)

1. 머리      날짜, 깔때기 한 줄, 실패 출처 있으면 한 줄 경고
2. 목차      카드 5개: 번호 · 제목 · 분류 · 배지
3. 카드      카드마다: 제목 / 한 줄 설명 / 오늘 고른 이유 /
             핵심 근거 2개(링크) / 가장 큰 위험 / [앱에서 보기] 링크
4. 반복 주제  (L) 이번 주 계속 나오는 주제 3개
5. 꼬리      오늘 비용 · 이번 달 합계 · 실행 시간
```

- 메일은 **요약본**이고, 판단은 앱(SC-02)에서 한다. 피드백 버튼은 메일에 넣지 않는다(서버가 없으므로).
- HTML + 일반 텍스트 둘 다 만든다.

## 7. 화면 → core 데이터 요구

| 필요 | 화면 | core 반영 |
|---|---|---|
| 실행 깔때기·단계별 건수·비용·실패 출처 | SC-01, SC-10, 메일 | `RunReport`에 단계별 건수, 출처별 결과, LLM 호출별 토큰·비용 |
| 실행 중 진행 단계 | SC-01 | `Pipeline`이 단계 변경을 알리는 콜백(진행 상태) |
| 카드 식별자·날짜 | SC-02, 메일 링크 | `IdeaCard`에 `id`, `runDate` |
| 확인 필요 표시 | SC-02 | `IdeaCard.caveats` |
| 탈락 이유 | SC-05, SC-07 통계 | `DropReason` 항목별 저장 (1단계부터) |
| 출처 통계 | SC-07 | `SourceStats` 계산 (`StatsStore`) |
| 반복 주제 | SC-04 | `topicKey` 이력 저장 (`ItemStore`) |
| 피드백 | SC-01~03 | `Feedback` 저장, 최근 N개를 작성 프롬프트에 포함 |
| 설정 덮어쓰기 | SC-07~11 | 기본값(리소스) + 사용자 값(앱 저장소) 병합 (`ConfigLoader`) |
