# 제품 프롬프트 — AI 아이디어 수집기

> 이 제품을 다른 도구(디자인·프로토타입 생성 등)에 설명할 때 쓰는 프롬프트. 기준 문서는 [design.md](design.md), [menu.md](menu.md)이며, 결정이 바뀌면 이 문서도 함께 고친다.

1. **앱 유형**: 1인 개발자를 위한 개인용 **AI 서비스 아이디어 수집기** 안드로이드 앱을 만든다. 매일 정해진 시간에 Hacker News, GitHub, Hugging Face, Reddit, Product Hunt에서 AI 관련 소식을 자동으로 모으고 정제한다. 그다음 "새로 가능해진 기술"과 "사람들이 원하는 것", "이미 나온 경쟁 제품"을 엮어서, 사용자가 혼자 만들 수 있는 **서비스 아이디어 카드 5개**를 근거 링크와 함께 앱과 메일로 전달한다. 기사를 요약하는 브리핑이 아니라 "그래서 무엇을 만들 수 있는가"를 제안하는 도구다. 별도 웹 서버 없이 폰에서 동작한다.

2. **핵심 기능 상세**:
   - **첫 설정:** 첫 이용 시 사용자는 Anthropic API 키(필수)와 GitHub 토큰(선택), 결과를 받을 메일 주소와 발송 계정을 입력하고 테스트 발송으로 확인한다. 이어서 "내 기준"을 입력한다. 내 기준은 개발 범위(1인 기준 기간), 대상 고객, 관심 분야, 제외 분야, 수익화 방식이다.
   - **매일 자동 처리:** 수집은 하루 300~500건이다. 먼저 코드로 기간, 출처별 인기도, 제외 키워드, 스팸 묶음을 거르고 중복과 이미 본 글을 뺀다. 남은 항목은 저렴한 AI 모델이 "기술 신호 / 수요 신호 / 경쟁 제품"으로 분류하고 0~10점과 태그를 매긴다. 점수 기준과 분야별 상한으로 15~20건만 남긴 뒤 본문 일부, 상위 댓글, 과거 기록을 보강한다. 마지막으로 고성능 AI 모델이 카드 5개를 작성한다.
   - **카드 작성 규칙:** 카드 하나는 기술 신호 1개 이상과 수요 신호 또는 경쟁 제품 1개 이상을 근거로 해야 한다. 근거 링크는 그날 실제로 수집한 글만 허용한다.
   - **카드 내용:** 사실을 요약한 제목, 한 줄 설명, 오늘 고른 이유, 해결할 문제를 담는다. 근거로는 기술 신호(라이선스 포함), 수요 신호(댓글 작성자와 찬반 인용), 경쟁 제품과 그 빈틈, 과거 언급(날짜 인용, 최대 2개)을 담는다. 실행 판단으로는 1인 개발 기간, 차별점, 가장 큰 위험 1개, 2주 안의 검증 방법을 담는다. 그 밖에 확인 필요 사항(단일 출처, 업체 주장, 커뮤니티 주장), 분류와 태그, 배지(급상승·여러 곳에서 화제·연속 등장)를 넣는다.
   - **피드백:** 각 카드에 ★ 관심, "관심 없음"을 표시할 수 있다. 관심 없음에는 이미 있음, 너무 큼, 내 분야 아님, 근거 약함, 기타 중 이유를 고른다. 이 피드백은 다음 날 카드 작성에 반영된다.
   - **보관함:** 지난 카드를 날짜별로 다시 보고, ★만 보기, 분류·태그 필터, 글자 검색을 할 수 있다.
   - **출처 관리:** 출처마다 켜기/끄기, 검색어, 최소 점수, 최대 건수를 바꾸고 연결 테스트를 할 수 있다. 출처마다 최근 30일의 하루 평균 수집량, 통과율, 평균 점수를 보여준다.
   - **실행 기록:** 실행마다 "수집 412 → 후보 18 → 카드 5" 같은 단계별 건수, 실패한 출처와 이유, AI 호출별 비용, 이번 달 비용 합계를 보여준다. 하루 비용 상한을 넘으면 그때까지 만든 결과만 보낸다.

3. **레이아웃 구조**:
   - 모바일 세로 화면 기준으로 하단 탭 3개(오늘 · 보관함 · 설정)를 둔다.
   - **오늘 탭:** 맨 위에 날짜, 마지막 실행 시각, 깔때기 한 줄("수집 412 → 후보 18 → 카드 5"), 오늘 비용을 보여준다. 실패한 출처가 있으면 그 아래에 경고 띠를 둔다. 중앙에는 카드 5개를 세로 목록으로 놓는다. 각 카드 줄에는 제목, 한 줄 설명, 분류, 배지, ★ 버튼을 둔다.
   - **카드 상세:** 카드를 누르면 상세 화면으로 이동한다. 블록 순서는 머리(제목·한 줄 설명·분류·배지·태그) → 오늘 고른 이유 → 문제 → 기술 신호 → 수요 신호 → 경쟁 제품 → 과거 언급 → 실행 판단 → 확인 필요 → 근거 링크다. 블록 제목은 고정하고, 내용이 없는 선택 블록은 숨긴다. 근거 링크 목록은 기본으로 접어 둔다.
   - **보관함 탭:** 날짜 머리글 아래에 카드를 묶어 보여주고, 상단에 검색창과 필터 칩을 둔다.
   - **설정 탭:** 출처 관리, 내 기준·카드 구성, 실행 기록, 일정·메일·API 키를 목록으로 둔다.

4. **화면 구성**: MVP는 총 6개 화면으로 구성한다.
   - **① 첫 실행 설정:** API 키 → 메일 → 내 기준 → 첫 실행의 4단계로 진행한다.
   - **② 오늘의 카드:** 깔때기 요약과 카드 5개, 지금 실행 버튼이 있다.
   - **③ 카드 상세:** 근거와 실행 판단을 읽고, ★·관심 없음을 표시하고, 원문을 연다.
   - **④ 보관함:** 지난 카드를 검색하고 필터링한다.
   - **⑤ 실행 기록:** 날짜별 결과와 비용을 보고, 들어가면 단계별 건수, 출처별 결과, AI 호출별 토큰과 비용을 확인한다.
   - **⑥ 설정:** 출처 관리, 내 기준·카드 구성(하루 카드 수, 분야별 최대 개수), 실행 일정(시각, Wi-Fi·충전 조건), 메일, API 키를 관리한다.
   - **진입 경로:** 실행 완료 알림은 ②, 실행 실패 알림은 ⑤의 상세로 연결한다. 메일 안의 카드 링크는 앱 링크(`ideacollector://card/{id}`)로 ③을 바로 연다.
   - **나중에 추가할 화면:** 반복 주제, 수집함(통과·탈락 이유), 신호 프로필 편집, 카드 추가 질문, 백업.

5. **디자인 분위기**: 매일 아침 몇 분 안에 읽고 판단하는 **집중형 개인 브리핑** 분위기로 만든다. 장식보다 읽기 쉬운 글자 크기와 줄 간격, 명확한 정보 위계를 우선한다. 점수와 분류는 작은 색 배지로 구분하고, 근거 블록은 출처·시각·원문 링크가 한눈에 보이게 한다. 라이트·다크 모드를 모두 지원한다. "업체 주장", "확인 필요" 같은 불확실성 표시는 눈에 띄되 과하지 않게 한다.

6. **인터랙션 디테일**:
   - ★와 관심 없음은 누르는 즉시 상태가 바뀌고, 짧은 확인 메시지와 되돌리기를 보여준다. 관심 없음을 누르면 이유 선택 칩이 아래에서 올라온다.
   - "지금 실행"을 누르면 진행 단계(수집 중 → 거르는 중 → 분류 중 → 작성 중)를 상단에 보여준다.
   - 아래로 당기면 저장된 최신 결과를 다시 불러온다.
   - 오늘 실행 전이면 어제 카드와 "다음 실행 예정 07:00"을 보여준다. 비용 상한으로 일부만 만들어진 경우에는 안내 띠를 보여준다.
   - 보관함의 필터와 검색은 입력하는 즉시 목록이 갱신된다.
   - 출처 연결 테스트는 실제로 한 번 호출해서, 받아 온 건수와 첫 3건의 제목을 보여준다.
   - **메일:** 매일 요약본을 보낸다. 제목에는 날짜, 카드 수, 깔때기를 넣는다. 본문에는 목차와, 카드마다 한 줄 설명, 오늘 고른 이유, 핵심 근거 2개, 가장 큰 위험, 앱에서 보기 링크를 넣는다. 꼬리에는 비용과 실행 시간을 넣는다. HTML과 일반 텍스트를 함께 보내고, 배지는 인라인 스타일로 그린다.

7. **상태 관리**:
   - **기기 안 데이터베이스에 영구 저장하는 것:** 내 기준, 출처 설정(기본값에 사용자 수정값을 덮어씀), 카드 구성, 실행 일정, 메일 설정, 날짜별 카드와 근거, 카드별 피드백(★·관심 없음·이유·시각)을 저장한다. 수집 항목과 탈락 이유, 주제 키(반복 주제용), 이미 본 글 기록, 실행 기록(단계별 건수·출처별 결과·비용), 출처별 통계도 저장한다.
   - **검색:** 과거 항목과 카드는 전문 검색으로 찾을 수 있게 한다. 이 검색은 보관함과 카드의 "과거 언급"에 쓴다.
   - **비밀값:** API 키와 메일 비밀번호는 데이터베이스가 아니라 기기 보안 저장소에만 둔다. 화면에서는 값을 다시 보여주지 않는다.
   - **재실행 안전:** 같은 날 다시 실행해도 카드와 메일이 중복되지 않게 날짜별 실행 키를 둔다.
   - **개인화:** 최근 피드백 일부를 다음 날 카드 작성의 선호 예시로 넣는다.

8. **기술 스택**:
   - **구성:** Kotlin으로 구현한다. 수집·정제·AI 호출·리포트 로직은 안드로이드 의존성이 없는 순수 Kotlin(JVM) `core` 모듈에 두고, 안드로이드 기능은 `app` 모듈에만 둔다. 실행 시각을 반드시 보장해야 할 때는 같은 `core`를 JVM 실행 파일로 만들어 GitHub Actions에서 돌릴 수 있게 한다.
   - **core:** OkHttp, kotlinx.serialization, 코루틴, Anthropic Java SDK를 쓴다.
   - **app:** Jetpack Compose, WorkManager(하루 주기 실행), Room(SQLite, FTS 전문 검색), Android Keystore, Jakarta Mail(SMTP)을 쓴다.
   - **AI 모델:** 1차 분류는 `claude-haiku-5-5`, 카드 작성은 `claude-opus-5-5`를 쓰고, 일일 비용 상한을 둔다.
   - **출처 수집:** 공식 API를 우선하고 HTML 파싱은 피한다. 인스타그램은 쓰지 않는다.
   - **목표 비용:** 월 3~8달러.
